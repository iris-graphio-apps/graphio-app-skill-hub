# 한국어 문서 작성 규칙

한국어 산출물을 만들 때 적용한다. 초안을 쓸 때 지키고, 다 쓴 뒤 마지막에 한 번 더 훑는다.

원칙은 하나다. **영어로 생각한 문장을 한국어 단어로 갈아끼우지 말고, 한국어로 다시 쓴다.**

이 규칙이 가장 필요한 자리는 **영문 자료를 읽고 한국어로 쓸 때**다. 원문의 구조가
그대로 딸려 나와 번역투가 배기 때문에, 첫 문장을 쓰기 전에 규칙을 잡아 두어야 한다.

---

## 동작은 둘뿐이다

이 스킬이 도는 길은 두 가지다. 셋째 모드를 새로 만들지 않는다. 예외를 하나 늘릴 때마다
어느 쪽으로 도는지 사용자가 알 수 없게 되고, 부르지도 않은 파일을 고치는 사고가 난다.

| 언제 | 무엇을 한다 |
|---|---|
| **한국어 문서를 새로 만들 때** — 예외 없이 자동으로 켜진다 | 지금 쓰는 문서에 아래 규칙을 적용한다 |
| **`/korean-writing <파일…>`** — 파일이 있어야 동작한다 | 옵션으로 받은 파일을 규칙에 맞게 고친다 |

**작성**은 문서의 종류도, 출발 자료도 가리지 않는다. 사용자에게 보여줄 한국어 문서를
새로 만들어 내는 일이면 모두 해당한다. 영문 자료를 옮길 때 번역투가 가장 심하지만,
한국어 메모나 표를 문장으로 펴는 순간에도 똑같이 군더더기가 붙는다.

**교정**은 고칠 파일이 있어야 돈다. 파일 없이는 동작하지 않는다.
"이 문서 어색한데 다듬어줘"처럼 말로만 부탁받았다면, 스킬이 켜졌더라도 규칙을 적용하지
말고 아래 안내로 빠진다. 고칠 대상을 사용자가 정해서 부르는 것이 이 스킬의 약속이다.

**둘 중 어느 쪽도 아니면 아무것도 하지 않고 조용히 빠진다.** 한국어를 다루기만 하는
일 — 인코딩 깨짐, 한글 폰트, 형태소 분석기, 번역 API 연동, 데이터셋 라벨링, i18n 키
맞추기 — 은 한국어 문서를 만드는 일이 아니다. 스킬 이름 때문에 켜지는 자리라서, 켜졌다는
이유만으로 문장을 손보면 사용자가 부탁하지 않은 일을 하게 된다. 한 줄 알림도 남기지 않는다.

켜지면 어느 쪽인지 한 줄로 밝힌다. **파일을 읽거나 고치기 전, 첫 발화로 낸다.**
일을 다 마친 뒤에 밝히면 늦다. 사용자가 아직 되돌릴 수 있는 시점에 보여야 뜻이 있다.

```
korean-writing · 작성 — 지금 쓰는 글에 규칙을 적용합니다
korean-writing · 교정 — work/report.md
```

### 고칠 파일을 옵션으로 받지 못했을 때

교정은 **파일을 옵션으로 받았을 때만** 한다. 두 경우가 여기에 걸린다.

- `/korean-writing`만 입력했다 — 고칠 파일을 아직 못 받았다.
- 자동으로 켜졌는데, 새 글을 쓰는 일이 아니라 이미 있는 파일을 손보는 일이었다.

둘 다 짐작해서 아무 파일이나 열지 말고, 아래를 그대로 보여준 뒤 **멈춘다.** 부르지도 않은
파일을 고쳐 놓는 것이 되돌리기 가장 어려운 사고다. 무엇을 붙여야 하는지 알면 한 번에 끝난다.

```
korean-writing · 고칠 파일을 알려주세요

고칠 파일을 옵션으로 붙여서 다시 불러 주세요.

    /korean-writing docs/보고서.md
    /korean-writing docs/보고서.md docs/공지.md      ← 여러 개도 됩니다

(교정은 여기서 멈춥니다 — 파일을 손대지 않습니다)

새로 쓰는 글이라면 부르지 않아도 됩니다.
보고서·요약·공지·가이드를 만들어 달라고 하시면 그때 알아서 켜집니다.
```

### 파일을 고칠 때의 순서

1. 파일을 읽는다.
2. `python3 scripts/check_korean.py <파일>`을 돌려 기계로 잡히는 것부터 모은다.
3. 아래 규칙에 비춰 하나씩 판단한다. 스크립트가 짚은 곳이라도 그 분야에서 굳어진
   말이면 두고, 판단이 갈리면 고치지 말고 대안을 제시한다.
4. 고친 파일과 함께 **무엇을 왜 고쳤는지** 짧게 정리해 보여준다. 규칙 번호가 아니라
   사람이 읽을 말로 적는다.

파일을 여러 개 받으면 하나씩 처리하고, 마지막에 문서 사이에 걸친 용어 혼용을 한 번 더 본다.
`툴`/`도구`처럼 갈린 낱말은 파일 하나만 봐서는 드러나지 않는다.

## 1. 외국어에서 온 말을 어떤 꼴로 적을 것인가

가장 자주 틀리고, 문서의 인상을 가장 크게 좌우하는 자리다.
외국어에서 온 말은 세 가지 꼴로 적을 수 있다.

| 꼴 | 예 |
|---|---|
| 한국어 뜻 | 이관, 승인, 범위, 운영 매뉴얼 |
| 원어 철자 | Slack, Kubernetes, MCP |
| 한글 음차 | 핸드오프, 컨펌, 스코프, 슬랙 |

**한글 음차는 거의 언제나 가장 나쁜 선택이다.** 원어를 아는 사람은 그 철자를 찾지
못하고, 모르는 사람은 뜻을 짐작하지 못한다. 양쪽 독자를 다 잃는다.

음차를 만나면 이 순서로 판단한다.

1. **회사·제품·서비스·사람 이름인가** → 원어 철자로 적는다. 한국어로 옮기지도 않는다.
   슬랙 → `Slack`, 깃허브 → `GitHub`, 쿠버네티스 → `Kubernetes`, 앤트로픽 → `Anthropic`
2. **원어를 알아야 검색되는 기술 용어인가** → 원어 철자로 적고, 처음 나올 때 뜻을 괄호에 붙인다.
   `MCP(Model Context Protocol)`, `pass^k`, `eval`, `harness(에이전트를 업무로 만드는 부속품 일체)`
3. **그 밖에 한국어로 뜻이 서는 말인가** → 한국어로 푼다.

원어에서 옮길 때도, 이미 음차된 것을 고칠 때도 같은 표를 쓴다.
**뜻이 서지 않는 직역은 음차만큼 나쁘다** — 가운데 칸이 그것까지 함께 막는다.

| 원어 | 음차·직역 (쓰지 말 것) | 한국어 |
|---|---|---|
| confirm / approve | 컨펌 / 어프루브 | 승인 |
| assign | 어사인 | 배정 |
| align | 얼라인 | 조율 |
| handoff | 핸드오프 | 이관 |
| discovery | 디스커버리 | 파악 단계 |
| framing | 프레이밍 | 범위 확정 |
| scope | 스코프 | 범위 |
| triage | 트리아지 | 원인 판정 |
| thin slice | 씬 슬라이스 / **얇은 동작 버전** | 끝까지 한 번 돌아가는 최소 버전 |
| human calibration | **사람 보정 기준** | 사람이 직접 확인해 기준을 맞추는 절차 |
| runbook | 런북 | 운영 매뉴얼 |
| use case | 유즈케이스 | 후보 업무 |
| inventory | 인벤토리 | 목록 |
| setup / archiving | 셋업 / 아카이빙 | 설치·설정 / 보관 |

팀에서 이미 그 음차를 입으로 쓰고 있다면 **처음 한 번만** 괄호에 넣어 준다 —
`파악 단계(디스커버리)`. 그다음부터는 한국어로만 쓴다.

한글 문장에 영어 철자를 그대로 박아 넣은 것도 같은 판단을 받는다.
`no-go 조건`은 3번에 해당하므로 **하지 않을 것의 기준**으로 푼다.

**그대로 두어야 할 것** — 이미 한국어에 자리 잡아 음차라는 느낌이 없는 말은 건드리지 않는다.
데이터, 시스템, 서버, 파일, 프로젝트, 페이지, 서비스, 버튼, 브랜치, 커밋, 배포, 테스트.

가르는 법: **원어 철자로 바꿔 적어 보라.** "data가 부족하다"는 어색하니 데이터는 둔다.
"Slack으로 알려주세요"는 자연스러우니 슬랙은 고친다.

## 2. 영어 관용구를 직역하지 않는다

영어에서만 통하는 비유는 한국어에서 뜻이 사라지거나 다른 뜻이 된다. 원문이 무엇을
말하려는지 파악한 뒤 한국어 표현으로 다시 쓴다.

**이 규칙은 본문을 위한 것이다.** 제목과 라벨은 8번을 따른다 — 앞뒤가 받쳐 주지 않는
자리라 같은 방식으로 다시 쓰면 뜻이 오히려 날아간다.

| 직역 (쓰지 말 것) | 원문 | 고친 표현 |
|---|---|---|
| 사람이 **익사**하고 있다 | the humans are drowning | 사람이 **감당을 못 하고 있다** |
| **신탁(神託)**이 아니라 큐 | not an oracle but a queue | **답을 내려주는 기계**가 아니라 **확인할 것을 쌓아두는 대기줄** |
| **배당**이 옮겨가지 않는다 | does not shift the dividend | **그 이득이 우리 쪽으로** 넘어오지 않는다 |
| 로드맵을 미리 **정찰**한다 | scout ahead | 다음에 만들 것을 **미리 찾아낸다** |
| 조항을 **사람으로 만든다** | turns a clause into a person | 계약서 문구에 **이름과 얼굴을 붙인다** |
| **의미론**에 **운동학**을 짝짓는다 | semantics paired with kinetics | **뜻**만으로는 부족하고 **움직임**이 붙어야 한다 |

특히 주의할 것:
- **한자어가 다른 뜻으로 먼저 읽히는 경우** — "신탁"은 금융 용어로, "배당"은 주식 배당으로 먼저 읽힌다.
- **학술 용어로 오해되는 경우** — "운동학"은 물리학 용어처럼 보여 뜻을 가린다.

## 3. 한 개념은 끝까지 한 단어로 부른다

같은 것을 문단마다 다르게 부르면 읽는 사람이 다른 개념으로 오해한다.
문서를 다 쓴 뒤 **동의어 쌍의 빈도를 세어 많은 쪽으로 통일**한다.

| 혼용 | 빈도 | 통일 |
|---|---|---|
| 툴 / 도구 | 2 : 30 | **도구** |
| 평가셋 / 평가 세트 | 2 : 2 | **평가 세트** |
| handoff / 이관 | 1 : 1 | **이관** |

## 4. 문장은 한 번에 읽히게 자른다

영어는 뒤에 계속 붙여도 구조가 보인다. 한국어는 꾸미는 말이 앞에 쌓이고 서술어가
맨 끝에 오기 때문에, 문장이 길어지면 독자가 끝에 닿기 전에 앞을 잊는다.
영어로 생각하며 쓸 때 가장 티가 나는 자리다.

- 한 문장에 하나만 말한다. 둘을 말해야 하면 문장을 둘로 나눈다.
- **100자를 넘으면 자를 곳을 찾는다.** 넘겨도 되지만 이유가 있어야 한다.
- 주어와 서술어가 멀어지면 자른다.
- "~하였으며", "~인데", "~이나"로 이어 붙이는 대신 마침표를 찍는다.
- 괄호와 줄표로 다는 곁가지는 한 문장에 하나까지.

✗ 본 파일럿은 기존에 상담사가 수동으로 수행하던 티켓 분류 업무를 LLM 기반 시스템을
통해 자동화하는 것을 목표로 하였으며, 이를 통해 상담사의 업무 부담 경감 및 응답 시간의
단축이라는 두 가지 효과성을 동시에 확보하고자 하는 시도였다고 할 수 있습니다. (143자)

○ 상담사가 손으로 하던 티켓 분류를 자동으로 처리하는 것이 목표였다. 상담사의 부담을
덜고 응답 시간도 함께 줄이려 했다. (58자)

짧게 끊는 것이 목적이 아니다. **한 번 읽어 뜻이 들어오는 것**이 목적이다.
리듬이 죽을 만큼 토막 내면 그것도 읽기 나쁘다.

## 5. 번역투 군더더기를 걷어낸다

영어의 전치사구와 명사구를 그대로 옮기면 한국어에 없던 군더더기가 붙는다.
뜻은 하나도 늘지 않고 문장만 길고 딱딱해진다.

| 군더더기 | 고침 |
|---|---|
| ~을 통해 / ~를 통하여 | 조사로 — ~로, ~에서 |
| ~에 대한 / ~에 대하여 | 조사로 — ~의, ~을 |
| ~에 있어서 | ~에서, ~할 때 |
| ~되어지다 | 이중 피동 — ~되다 |
| ~에 기인한 것으로 | ~ 때문이다 |
| ~하는 것을 목표로 하였다 | ~하려 했다 |
| ~라고 할 수 있다 | 빼고 단정한다 |
| ~에 해당한다 | ~이다 |
| 본 문서는 / 본 파일럿은 | 이 문서는 / 이 사업은 |

**접미사 ~적·~성·~화** — 빼도 뜻이 그대로면 뺀다. 그것이 판정 기준이다.
- 두 가지 **효과성**을 확보 → 두 가지 **효과**를 얻다
- **정량적** 결과 → **숫자로 본** 결과
- **일반적으로** 관찰되는 → **흔히** 나타나는

**명사화** — 영어 명사구를 그대로 옮기면 딱딱해진다. 동사로 푼다.
- ✗ "이 **급함**은 어디서 나온 건가"를 묻습니다 → ○ "이게 **왜 급한 건지**"부터 묻습니다

**주어를 감추는 피동** — 누가 했는지 밝힌다. 보고서에서 이 습관은 책임 소재를 흐린다.
- ✗ 라벨링 작업이 **수행되었음** → ○ 상담사 12명이 라벨을 **달았다**
- ✗ 개선이 필요한 영역으로 **식별되었다** → ○ 여기를 고쳐야 한다고 **보았다**
- ✗ ~로 **판단된다** / **사료된다** → ○ ~로 **본다**
- ✗ "돈이 안 됐다"가 **들키기** 시작한 국면 → ○ 그 사실이 **드러나기** 시작한 국면

## 6. 문체와 어미를 하나로 맞춘다

한 문서에서 문체가 흔들리면 읽는 사람은 글쓴이가 여럿이라고 느낀다.
내용이 옳아도 신뢰가 깎인다.

**문서 첫 문단에서 정하고 끝까지 간다.**
- 보고서·기록물 → 한다체 (`~했다`, `~이다`)
- 안내·가이드·공지 → 합니다체 (`~합니다`, `~하세요`)
- 회의록·메모 → 개조식 (`~함`, `~임`)

섞이는 자리는 대개 마지막 문단과 결론이다. 다 쓴 뒤 거기부터 본다.
- ✗ (한다체 문서에서) …시도였다고 할 수 **있습니다**.
- ✗ (한다체 문서에서) …전사 확대를 검토할 **예정임**.

**목록 항목의 어미도 맞춘다.** 한 목록 안에서 꼴이 다르면 나란한 것으로 읽히지 않는다.
- ✗ 계정 발급 / 노트북은 자동으로 **설치됨** / 코드베이스를 **읽는다**
- ○ 계정 발급 / 노트북 자동 설치 / 코드베이스 읽기

**구어체와 문어투를 섞지 않는다.**
- 속어 — ✗ 몇 주를 **갈아 넣어** → ○ 몇 주를 **매달려**
- 과한 문어투 — ✗ **사료된다** → ○ **본다** / ✗ 회의를 **표합니다** → ○ 우려를 **내비칩니다**

## 7. 숫자·단위·날짜는 한 가지 꼴로

표기가 흔들리면 같은 문서 안에서 숫자를 견주기 어렵고, 표나 그림으로 옮길 때 다시
손봐야 한다. 무엇이 옳은가보다 **한 문서 안에서 하나로 통일**하는 것이 중요하다.

- **백분율** — `%`·퍼센트·프로를 섞지 않는다. 문서라면 대개 `%`.
  ✗ 87퍼센트 … 85% … 61프로 → ○ 87% … 85% … 61%
- **숫자와 단위는 붙인다** — ✗ `85 %`, `1.1 분` → ○ `85%`, `1.1분`
- **소수점 자릿수를 맞춘다** — 87%와 61.0%를 나란히 두지 않는다.
- **날짜** — `2026년 7월 1일`이든 `2026-07-01`이든 한 꼴로.
  `2026. 7. 1`과 `2026년 4월`을 한 문서에 섞지 않는다.
- **범위** — `4월부터 6월까지`와 `4~6월` 중 하나로.
- **어림수를 겹치지 않는다** — ✗ `약 500건 정도`, `약 2주정도` → ○ `약 500건`, `2주쯤`
- **네 자리부터 쉼표** — `1,200건`

## 8. 제목과 라벨은 그것만 읽어도 뜻이 통해야 한다

목차와 표 머리글은 본문과 떨어져 읽힌다. 앞뒤 문맥이 없는 자리라 말이 겹치거나
모자라면 바로 걸린다.

**같은 말을 두 번 하지 않는다.**
- ✗ `FDE의 연장통 — 다섯 가지 도구` → ○ `FDE의 다섯 가지 도구`
- ✗ `도구 2 · 도구 설계` → ○ `02 · 도구 설계`

**목차와 본문 제목을 맞춘다.** 목차에 "일의 미래"라 적고 본문에 "이 일은 어디로 가나"라고
쓰면 다른 절로 보인다.

**라벨은 홀로 서게 쓴다.**
- ✗ `읽는 법` → ○ `이 숫자를 읽는 두 가지 방법`
- ✗ 표 머리글 `누구` → ○ `역할`

**원문에 없던 비유를 제목에 새로 만들지 않는다.** 번역하거나 정리할 때 제목을 인상 깊게
만들고 싶어지는데, 제목은 목차에서 본문과 떨어져 읽히는 자리다. 비유를 넣으면 읽는 사람은
무엇에 대한 이야기인지부터 짐작해야 한다. **원문 제목이 밋밋하면 밋밋하게 옮긴다.**

| 원문 | 과하게 옮김 | 고침 |
|---|---|---|
| The handoff problem | 이관에서 **무너진다** | 이관에서 생기는 문제 |
| Head sampling is cheap but blind | 앞에서 자르면 싸지만 **눈이 먼다** | 앞에서 걸러내면 싸지만 놓치는 것이 생긴다 |
| Where rollouts trip up: routing | 적용에서 제일 많이 **걸려 넘어지는** 지점 | 적용할 때 가장 자주 막히는 곳 |

특히 조심할 것은 **의인화**다. 사람이 아닌 것이 무너지고, 눈이 멀고, 넘어지면 읽는 사람이
한 번 멈춘다. 그리고 **주어를 빼지 않는다** — "이관에서 무너진다"는 무엇이 무너지는지
말하지 않아서 걸린다.

가르는 법: **제목만 뽑아 목차처럼 늘어놓고 읽어 보라.** 본문 없이 무슨 이야기인지
그려지지 않으면 고친다.

## 마지막 점검

초안을 다 쓰면 부속 스크립트를 돌린다. 기계가 잡을 수 있는 것(음차, 용어 혼용,
문체 혼용, 긴 문장, 번역투, 숫자 표기, 제목 중복)을 한 번에 훑어 준다.
마크다운과 HTML을 모두 읽고, 코드 블록과 인라인 코드는 건너뛴다.

```bash
python3 scripts/check_korean.py 문서.md          # 경로는 이 스킬 폴더 기준
python3 scripts/check_korean.py 문서.md --pair 툴 도구 --pair 배포 릴리즈
```

`--pair`에는 그 문서에서 섞어 쓴 낱말 쌍을 넣는다. 문서마다 다르므로 직접 지정한다.

나오는 항목은 **확인할 곳**이지 틀린 곳이 아니다. 스크립트는 그 분야에서 굳어진 말과
어색한 음차를 가리지 못한다. 규칙에 비춰 하나씩 판단하고, 판단이 갈리면 고치지 않는다.

## 고치지 말아야 할 것

규칙이 늘어날수록 과하게 고칠 위험도 함께 커진다. 아래는 손대지 않는다.

- **한국 업무 현장에서 실제로 쓰는 말** — 현업, 상주, 공수, 산출물, 배포, 온콜, 스프린트.
  억지로 풀면 오히려 낯설어진다.
- **이미 한국어가 된 외래어** — 데이터, 시스템, 서버, 프로젝트, 커밋, 브랜치.
  1번 규칙은 이런 말을 겨냥한 것이 아니다.
- **뜻이 정확한 접미사** — 자동화, 정량적, 가용성처럼 그 말이 곧 그 뜻인 경우.
- **날 선 표현** — 세게 쓴 것이 의도라면 무르게 만들지 않는다. 판단이 갈리면 고치지 말고
  **대안을 제시하고 물어본다.** (예: "자동화당하는 쪽" — 조어지만 비대칭을 정확히 담아 유지)
- **고유명사** — 회사·제품·사람 이름은 번역하지 않는다.
- **원문에 없는 내용** — 다듬는 일이지 새로 쓰는 일이 아니다. 문장을 고치다 사실을 바꾸지 않는다.
- **리듬을 죽이는 토막 내기** — 4번은 길이를 줄이라는 규칙이 아니라 한 번에 읽히게 하라는 규칙이다.
