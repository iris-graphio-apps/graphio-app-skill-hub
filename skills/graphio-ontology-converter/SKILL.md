# graphio-ontology-converter

온톨로지 정의를 적은 문서를 **Graphio 에 반입할 수 있는 정의 파일**로 옮긴다. 산출물은 파일 두 개다 — 4블록 graphio JSON 하나, 무엇이 어디로 갔고 무엇이 남았는지 적은 한국어 리포트 하나.

**옮기는 일만 한다.** 문서에 있는 것을 규격에 맞는 파일로 바꾸고, 옮길 수 없는 자리를 알린다. 옮기는 일은 스크립트가 하므로 해석이 끼어들지 않는다. 같은 문서를 몇 번 넣어도 같은 파일이 나온다.

| 하지 않는 것 | 왜 |
|---|---|
| 문서에 없는 개념·속성·관계를 만들지 않는다 | 받는 사람은 파일 안의 모든 것을 문서에 있던 내용으로 읽는다 |
| 문서에 있는 것을 빼지 않는다 | 스킬이 빼 버린 것은 아무도 다시 찾지 않는다 |
| 문서가 잇지 않은 개념을 잇지 않는다 | 어느 관계에도 걸리지 않은 개념은 정상이다 |
| 그래프가 어떻게 보일지 보지 않는다 | 온톨로지 설계는 문서 작성자의 몫이다 |
| 문서를 고치지 않는다 | 대신 채우면 작성자는 자기가 적은 것으로 읽고 넘어간다 |

---

## 0) 맡는 곳과 맡지 않는 곳

| 범위 | 내용 |
|---|---|
| 맡는다 | 서식 확인 → 스크립트로 옮기기 → 규격 검증 → 리포트. 서식이 아닌 문서는 서식을 건네거나, 문서에 적힌 것만 서식 초안으로 옮긴다 |
| 맡지 않는다 | 문서 해석으로 개념 뽑아내기 · 문서 고치기 · 대상 환경에 Meta Type 이 있는지 확인 · 그래프 설계 · 운영 환경 반입·적용(별도 Export 스킬) · graphio 앱·노드 개발(`graphio-app-dev`·`graphio-subagent-dev`) |

## 1) 작업 순서

### ① 문서가 서식인지 본다

`## Object Type` 절이 있으면 서식이다. 없으면 3)으로 간다.

### ② 스크립트로 옮긴다

```bash
python3 scripts/build_graphio_json.py 정의.md -o 정의-ontology.json
```

스크립트가 서식을 읽어 graphio JSON 을 쓴다. **파일을 열어 읽을 일은 없다** — 필요한 것은 실행 결과에 다 나온다.

문서 오류가 있으면 **JSON 을 쓰지 않는다.** 반쯤 옮긴 파일을 남기면 그것이 완성품으로 오해된다.

### ③ 문서 오류가 있으면 고칠 자리를 알린다

스크립트가 알린 것을 사용자에게 그대로 전한다 — 몇 줄이 문제이고 무엇을 적어야 하는지. **스킬이 문서를 고치지 않는다.** 고쳐진 문서를 받으면 ②로 돌아간다.

### ④ 규격을 확인한다

```bash
python3 scripts/validate_graphio_json.py 정의-ontology.json
```

서식은 지켰지만 규격을 어기는 자리가 남을 수 있다. 흔한 셋 —

| 규격 위반 | 코드 | 문서에서 무엇을 고치나 |
|---|---|---|
| 대표 표시 속성이 0개거나 2개 이상 | `GOS61006` `GOS61007` | 개념마다 `Title` 칸에 `O` 를 정확히 하나 |
| 자기 참조 관계 (source 와 target 이 같은 개념) | `GOS61106` | 그 관계를 지우고 상위 식별자를 속성으로만 적는다 |
| 조인 속성 이름이 상대 개념에 없다 | `GOS61109` `GOS61111` | 이름을 맞추거나 그 속성을 상대 개념에 적는다 |

오류가 나오면 그것도 문서를 고칠 일이다. 스킬이 파일을 손으로 고쳐 맞추지 않는다 — 그러면 문서와 파일이 갈린다.

### ⑤ 리포트를 쓴다

두 스크립트가 알린 것을 아래 2.2 의 뼈대로 옮겨 적는다.

---

## 2) 산출물

파일 두 개를 정의 문서와 같은 폴더에 만든다. 사용자가 위치를 지정하면 그것을 따른다.

| 파일 | 이름 | 쓰는 곳 |
|---|---|---|
| 온톨로지 정의 | `<문서이름>-ontology.json` | Export 스킬이 그대로 읽어 반입한다 |
| 리포트 | `<문서이름>-ontology-report.md` | 문서 작성자가 읽고 남은 일을 처리한다 |

### 2.1 graphio JSON

스크립트가 쓴다. 손으로 만들지 않는다. 최상위는 네 키뿐이고, 문서에 해당 절이 없으면 빈 배열이 들어간다.

```json
{ "objectTypes": [], "linkTypes": [], "metaTypes": [], "objectMapping": [] }
```

필드별 제약과 전체 예시는 [`references/graphio-json-spec.md`](references/graphio-json-spec.md) 에 있다.

### 2.2 리포트

파일이 답하지 못하는 것에 답한다 — 문서의 무엇이 어디로 갔나, 스크립트가 채운 것은 무엇인가, 문서에서 고칠 것은 무엇인가, 반입 전에 사람이 할 일은 무엇인가. 해당 없는 절은 "없음"으로 남긴다. 절을 지우면 읽는 사람이 빠뜨린 것으로 읽는다.

```markdown
# (온톨로지 이름) 온톨로지 정의 리포트

| 항목 | 내용 |
|---|---|
| 정의 문서 | (경로) |
| 산출 파일 | (경로) |
| 작성일 | YYYY-MM-DD |
| 옮긴 결과 | Object Type n개 · Link Type n개 · Meta Type n개 · Object Mapping n개 |
| 검증 결과 | 오류 0건 · 경고 n건 · 보류 n건 |

## 1. 옮긴 개념
| Object Type | 대표 표시 속성 | 식별 속성 | 속성 수 | 문서 위치 |
|---|---|---|---|---|

## 2. 옮긴 관계
| 관계 이름 | source | target | 방향 | 문서 위치 |
|---|---|---|---|---|

## 3. 스크립트가 채운 규격 필수값
| 항목 | 채운 값 | 왜 채웠나 |
|---|---|---|

## 4. 문서에서 고칠 자리
| 문서 위치 | 무엇이 어긋났나 | 무엇을 적어야 하나 |
|---|---|---|

## 5. 서식 밖에 적힌 내용
| 문서 위치 | 내용 | 왜 파일에 담기지 않았나 |
|---|---|---|

## 6. 반입 전에 할 일
- [ ] (검증기의 보류 항목을 여기로 옮겨 적는다)
```

3·4·5절이 이 리포트의 값을 만든다.

| 절 | 답하는 질문 | 어디서 오나 |
|---|---|---|
| 3. 채운 규격 필수값 | 파일에 있는데 문서에 없는 것은 무엇인가 | `build_graphio_json.py` 의 "규격 필수값을 채운 곳" |
| 4. 문서에서 고칠 자리 | 문서의 무엇이 어긋났나 | `build_graphio_json.py` 의 "문서 오류" + `validate_graphio_json.py` 의 오류 |
| 5. 서식 밖에 적힌 내용 | 문서에 있었는데 파일에 없는 것은 무엇인가 | 계산 값, 복합키, 조회 요구처럼 규격이 담지 못하는 것 ([`references/document-format.md`](references/document-format.md) 9절) |

3절이 `colorCode` 말고 길어지면 그것 자체가 신호다. 문서에 없는 것을 만들고 있다는 뜻이다.

---

## 3) 서식이 아닌 문서를 받았을 때

`## Object Type` 절이 없으면 서식이 아니다. **문서를 해석해 개념을 뽑아내지 않는다.** 산문에서 개념을 찾아내는 일에는 판단이 끼어들고, 그렇게 만든 온톨로지는 문서 작성자가 확인할 수 없다.

| 사용자가 원하는 것 | 어떻게 하나 |
|---|---|
| 이 문서로 온톨로지를 만들어 달라 | 서식([`assets/온톨로지-정의-서식.md`](assets/온톨로지-정의-서식.md))을 건네고, 이 서식으로 적어 주면 옮긴다고 알린다 |
| 이 문서를 서식으로 옮겨 달라 | **문서에 적혀 있는 것만** 서식 칸에 옮긴다. 문서가 말하지 않은 칸은 **빈 칸으로 남긴다.** 그 초안을 작성자가 채워 확정한 뒤 ②로 간다 |

두 번째에서 빈 칸을 남기는 것이 핵심이다. 데이터 타입이나 대표 표시 속성을 짐작해 채우면 작성자는 자기가 적은 것으로 읽고 넘어간다.

---

## 4) 스크립트가 채우는 값은 하나뿐이다

**`colorCode`** — 화면 표시 색이다. 온톨로지의 뜻에 관여하지 않지만 없으면 `GOS61004` 로 적용이 막힌다.

문서에 `- 색:` 이 있으면 그 값을 쓰고, 없으면 스크립트가 **문서에 나온 순서대로 서로 겹치지 않게** 준다. 앞 12개는 색상환을 고르게 나눈 값이고 13번째부터는 황금각으로 색상을 돌려 만들어, 개념이 몇 개가 되어도 같은 색이 두 번 나오지 않는다. 색에는 뜻이 없다.

그 밖에 스크립트가 정하는 것은 없다. `orderNo` 는 표의 행 순서를 읽는 것이고, `isPublic`·`description` 은 선택 항목이라 없으면 키를 넣지 않는다.
