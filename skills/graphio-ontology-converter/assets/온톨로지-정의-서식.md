## 채우는 법

이 절은 읽는 사람을 위한 것이고 파일을 옮길 때 읽히지 않는다.

| 칸 | 규칙 |
|---|---|
| 색 | 위 서식에 없는 줄이다. 정하고 싶으면 `### 개념 이름` 밑에 `- 색: #RRGGBB` 를 더한다. 더하지 않으면 다른 개념과 겹치지 않는 색이 자동으로 들어간다. 색에는 뜻이 없다 |
| 공개 | 위 서식에 없는 줄이다. 공개하려면 `### 개념 이름` 밑에 `- 공개: 예` 를 더한다. 더하지 않으면 비공개다 |
| 개념 이름 | 영문이나 한글로 시작하고, 영문·숫자·한글·밑줄만, 50자까지. 공백·하이픈·점·괄호를 쓸 수 없다 |
| 속성 이름 | 형식 제약이 없다. 개념 하나 안에서 겹치지만 않으면 된다 |
| 데이터 타입 | `INTEGER` `TEXT` `DATETIME` `FLOAT8` `BOOLEAN` `VECTOR` `UNKNOWN` 중 하나 |
| PK | 개체를 유일하게 가리키는 속성에 `O`. 개념마다 **1개까지**. 없어도 된다 |
| Title | 화면에서 개체를 대표해 보일 속성에 `O`. 개념마다 **정확히 1개** |
| `O` 와 `X` | 해당하는 줄에 `O`, 아닌 줄은 비우거나 `X`. **`X` 는 "아니다"로 읽는다.** 숫자 `0` 은 영문 `O` 와 가릴 수 없어 오류로 짚는다 |
| 방향 | `→` 또는 `단방향`(source→target) · `←` 또는 `역방향`(target→source) · `↔` 또는 `양방향`. 규격 이름 `UNIDIRECTIONAL`·`REVERSE_DIRECTIONAL`·`BIDIRECTIONAL` 을 그대로 적어도 된다 |
| source 속성 · target 속성 | 두 값이 같으면 연결된다. 양쪽 모두 그 개념에 있는 속성 이름이어야 한다 |
| 종류 | `CUSTOM`(테이블·CSV) · `PARSING`(문서 파싱) · `DOC_TYPE`(문서 타입 파생) |
| 설명 | 비워도 된다. 개념·관계·속성은 5000자, Meta Type 컬럼은 1000자까지 |

**알아 둘 것 넷**

1. **관계는 양쪽 조인 속성이 있어야 성립한다.** 관계 이름만 적으면 만들어지지 않는다. `주문.고객번호 = 고객.고객번호` 처럼 양쪽에서 비교할 속성을 적어야 한다.
2. **자기 참조 관계는 쓸 수 없다.** source 와 target 이 같은 개념일 수 없다. 조직→상위조직 같은 계층은 상위 식별자를 **속성으로만** 적는다.
3. **N:N 관계는 가운데 개념이 필요하다.** 학생과 과목이 서로 여러 건으로 얽히면 `수강` 같은 개념을 하나 더 적고 관계를 두 개 적는다.
4. **Meta Type 은 Graphio 에 이미 있는 것을 이름으로 가리키는 참조다.** 이 파일로 만들어지지 않는다. 이름이 대상 환경과 다르면 반입할 때 `GOS61014` 로 걸린다.
