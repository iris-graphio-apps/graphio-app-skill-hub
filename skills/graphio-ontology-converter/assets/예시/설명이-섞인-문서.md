# 설비점검 온톨로지 정의

## 배경

설비운영팀 요청으로 2026년 3분기에 정리했다. 목표는 설비별 고장 이력을 그래프로 보고
부품 교체 주기를 잡는 것이다.

이 절은 서식의 네 절이 아니므로 스크립트가 읽지 않는다. 배경·근거·미확정 항목을
문서에 함께 두어도 결과가 달라지지 않는다.

## 답하려는 질문

- 어느 설비가 같은 부품으로 반복 고장 나는가
- 점검 담당자별 처리 건수와 평균 소요 시간은 어떻게 되는가
- 부품 교체 뒤 고장 간격이 실제로 늘어나는가

세 번째 질문은 지금 구조로 답이 나오는지 확인이 필요하다. 점검이력에 교체 여부가
있으니 이력을 시각 순으로 늘어놓으면 될 것으로 본다.

## 확정하지 못한 것

| 항목 | 상태 |
|---|---|
| 담당자 개인정보를 온톨로지에 담을 범위 | 법무 확인 중. 지금은 사번과 이름만 두었다 |
| 월평균 고장률 | 계산값이라 속성으로 적지 않았다. 화면에서 계산한다 |
| 설비 위치 좌표 | 원천에 컬럼이 없다. 설비관리시스템 개편 뒤 다시 본다 |
| 데이터 원천 | 아직 정하지 않아 Meta Type 절을 두지 않았다 |

## 검토 기록

- 설비와 부품을 관계 하나로 잇지 않고 `설비부품` 을 둔 이유는 소요수량을 담아야 하기
  때문이다. 관계는 속성을 가질 수 없다.
- 부서 계층을 관계로 만들려다 자기 참조가 막혀 `상위부서코드` 속성으로 남겼다.
  부서 트리가 필요하면 화면에서 이 속성을 따라가며 그린다.
- `점검이력.교체부품번호` 는 비어 있는 행이 많다. 교체하지 않은 점검이 대부분이라
  `점검이력_부품` 관계는 일부 이력에만 걸린다. 의도한 것이다.
