# (이름) 온톨로지 수정 요청

| 항목 | 내용 |
|---|---|
| 작성일 | YYYY-MM-DD |
| 차수 | n차 |
| 스킬 판본 | (판본) |
| 대상 판정 | (구조 판정 경로) |
| 정의 문서 초안 | (다음 차수 정의 문서 경로) / 해당 없음 |

## 1. 개요

### 1.1 목적

- 온톨로지 설계 스킬이 구조 판정의 지적을 읽고 고친 결과와 남은 일을 기록함. 판정 뒤 사람 요청과 CQ 변경을 모아 다음 설계 수정 차수에 넘김. 이하 '스킬'은 이 설계를 수행한 도구를 가리킴
- 지적을 스킬이 고친 항목, 사람이 정해야 고칠 수 있는 항목, 입력 문서를 바꿔야 풀리는 항목으로 나눠 기재함
- 스킬이 고치는 대상은 다음 차수 설계 리포트(설계 변경)와 정의 문서(부분 수정)임. CQ 문서·원천 구조 문서·참고 문서·가이드는 입력 문서라 스킬이 고치지 않음
- 지적의 문제 설명·발생 경로·참고 자료는 대상 판정 3절에 있음

### 1.2 갈래 기준

| 갈래 | 뜻 | 처리 |
|---|---|---|
| 스킬 수정 | 정의 문서만 고치면 풀리고 고칠 내용을 입력 문서로 정할 수 있는 지적 | 스킬이 정의 문서 초안을 고침(5절) |
| 결정 필요 | 정의 문서를 고치면 풀리나 어느 쪽으로 고칠지 입력 문서만으로 정할 수 없는 지적 | 답을 받은 뒤 스킬이 고침(3절) |
| 입력 변경 필요 | 정의 문서만으로는 풀리지 않고 입력 문서를 바꿔야 풀리는 지적 | 사람이 입력 문서를 바꾼 뒤 다시 부름(4절) |

| 성격 | 뜻 |
|---|---|
| 설계 변경 | 요소를 더하거나 지우거나 설계 칸 값(개념·속성·관계의 더함·뺌·이름, 관계 방향·조인 속성, 원천 선택, 구조 꼴)을 바꾸는 항목. 다음 차수 설계 리포트를 먼저 고치고 다시 연 설계안 확인(⑥)에서 확인받음 |
| 정비 | 설계 칸은 그대로 두고 정의 문서를 설계 리포트·가이드에 맞추는 항목 |
| 입력 변경 | 입력 문서를 바꿔야 풀리는 항목 |

- 항목은 판정 지적·사람 요청·CQ 변경 세 종류임
- 수정 범위는 기본이 Error 지적이고, Warning까지 요청받은 경우에만 Warning 지적을 포함함(2절 '수정 범위')
- 개념·관계를 더하거나 빼는 항목은 다시 연 설계안 확인(⑥) 위층에서 확인받은 것만 반영함. 확인받지 못한 항목은 3절에 있음

### 1.3 답 기재 방법

- 3절 '답' 칸에 선택지 번호나 짧은 글을 기재함. 스킬은 3절에서 '답' 칸만 읽음. 멈춤 질문 파일의 답 봉투(`--answers`)로도 답할 수 있고, 3절 '답' 칸은 파일로 답하는 다른 길임
- Warning 행까지 고치려면 답 봉투의 범위 칸을 'Warning 포함'으로 줌
- 사람 요청 행은 사람이 직접 더할 수 있음. 근거 칸에 까닭을 기재함
- 스킬이 답 칸을 채워 둔 행은 정의 문서를 바꾸지 않기로 한 결정임(의도한 것, 더하지 않음, 그대로 둠). 다음 수정에서 다시 묻지 않음
- 답을 기재한 뒤 `--fix`로 다시 부르면 스킬이 답대로 고침. '답' 칸이 빈 항목은 다시 물음
- 스킬은 규칙과 위치로 답을 지적에 맞댐. 판정 지적 번호는 판정마다 새로 매겨지므로 대상 판정에서 지적을 찾아볼 때만 씀
- 다시 부를 때 이미 풀린 지적의 답은 쓰지 않음

## 2. 수정 결과 요약

| 항목 | 결과 |
|---|---|
| 수정 범위 | Error / Error·Warning |
| 스킬 수정 | n건 / 해당 없음 |
| 결정 필요 | n건 / n건(답 있음 n건) / 해당 없음 |
| 입력 변경 필요 | n건 / 해당 없음 |
| 사람 요청 | n건 / 해당 없음 |
| CQ 변경 | n건 / 해당 없음 |
| 판정 지적 대기 | n건 / 해당 없음 |

## 3. 결정 필요 사항

- 정의 문서를 고치면 풀리나 고칠 방향을 사람이 정해야 하는 지적임
- 선택지 가운데 하나를 '답' 칸에 기재함. 모르면 비워 둠
- 스킬이 답을 채워 둔 행은 정의 문서를 바꾸지 않기로 한 결정이라 다시 기재하지 않아도 됨

| No. | 판정 지적 번호 | 규칙 | 위치 | 정할 것 | 선택지 | 선택지별 영향 | 답 |
|---|---|---|---|---|---|---|---|

## 4. 입력 변경 필요 사항

- 정의 문서만으로는 풀리지 않아 입력 문서를 바꿔야 하는 지적임. 스킬은 입력 문서를 고치지 않음
- CQ 문서를 바꾸면 `--fix`로 다시 부름. 바뀐 CQ는 'CQ 변경' 행으로 받아 다음 설계 수정 차수에 반영함. 재생성은 설계 전체를 다시 수행하는 호출임
- 원천 구조 문서·참고 문서·가이드를 바꾸면 설계 판단이 달라지므로 재생성이 필요함. 재생성은 새 산출물 폴더로 수행함

| No. | 판정 지적 번호 | 규칙 | 위치 | 바꿀 입력 | 바꿀 내용 | 바꾼 뒤 부르는 법 |
|---|---|---|---|---|---|---|

## 5. 스킬 수정 사항

- 스킬이 정의 문서 초안에서 고친 항목임. 같은 목록이 정의 문서 초안 끝 '스킬 수정 기록' 절에 있음
- 위치는 요소 이름으로 기재하고, 이름이 없는 줄은 대상 판정이 가리킨 정의 문서의 줄 번호로 기재함

| No. | 판정 지적 번호 | 규칙 | 위치 | 고친 내용 |
|---|---|---|---|---|

## 6. 사람 요청과 CQ 변경

- 설계를 바꾸는 외부 수정이 든 초안으로 부르면 스킬은 고치지 않고 멈추며, 바뀐 자리를 사람 요청 행 초안으로 기재함. 대상 키·바꿀 내용은 차이에서 채우고 성격은 '설계 변경', 상태는 '해석 필요', 근거는 빈 칸으로 둠
- 이름 바뀜은 짝짓지 않고 뺌·더함 두 행으로 기재함
- 근거 칸을 채우고 반영하지 않을 행을 지운 뒤 `--fix`로 다시 부름. 외부 수정본은 `-N+1차-외부수정` 이름 파일로 보존되어 있음

| No. | 출처 | 기준 | 대상 키 | 바꿀 내용 | 성격 | 갈래 | 답 | 상태 | 근거 | 반영 |
|---|---|---|---|---|---|---|---|---|---|---|

## 7. 후속 조치

- 3절 '답' 칸 기재 후 `--fix`로 수정 재수행 필요 / 3절 '답' 칸 기재 후 `--fix`에 "Warning도 고쳐"를 붙여 수정 재수행 필요
- 4절 입력 문서 변경 후 '바꾼 뒤 부르는 법' 칸대로 재수행 필요
- 고친 결과는 (다음 차수 구조 판정 경로) 6절(앞 판정 대조)에서 확인 필요
- Warning 가운데 스킬 수정 대상 n건은 Warning까지 수정 요청 시 처리함
