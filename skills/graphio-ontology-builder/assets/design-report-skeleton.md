## 1. 개요

### 1.1 목적

- 온톨로지 설계 과정의 판단과 근거를 기록함
- 정의 문서에는 설계 결과만 있으므로, 설계 사유와 제외 사유, 미확인 사항, 답 요소별 원천 근거와 원천 근거가 없어 만들지 않은 요소를 이 문서에 기재함
- CQ 응답 가능 여부는 판정하지 않음. 판정은 검증 리포트에 있음

### 1.2 산출물 구성

- 온톨로지 설계 스킬이 차수마다 문서 4종을 생성함. 이하 '스킬'은 이 설계를 수행한 도구를 가리킴
- 차수: 같은 온톨로지를 검증한 차례. 스킬이 설계 전체를 수행한 결과가 1차이고, 판정 뒤 정의 문서를 고쳐 검증만 다시 수행할 때마다 2차, 3차로 늘어남. 정의 문서는 스킬이 판정 지적을 보고 고치거나 사람이 고침. 2차부터 파일 이름 끝에 '-n차'를 붙임
- 외부 수정: 앞 차수 뒤에 사람이 스킬 밖에서 정의 문서를 고친 것. 스킬이 설계안 확인 뒤 바꾼 것(설계안 확인 후 변경)과 구분하여 2절에 기재함
- 스킬 수정: 앞 차수 구조 판정의 지적을 보고 스킬이 정의 문서를 고친 것. 설계안 확인 후 변경, 외부 수정과 구분하여 2절에 기재함

| 문서 | 내용 |
|---|---|
| 정의 문서 | 온톨로지를 정해진 서식(Graphio 규격)으로 기재한 문서. `graphio-ontology-converter`가 Graphio 정의 파일로 변환함 |
| 설계 리포트 | 이 문서. 설계 판단과 근거 |
| 검증 리포트 | 설계 완료 후 정의 문서를 검사한 결과. CQ 응답 여부, 서식 변환 여부 |
| 구조 판정 | 검사 결과에 등급(Error·Warning·Info)을 부여하여 구조 확정 가능 여부를 판정한 문서 |

- 정의 문서 작성 전 설계안을 사용자에게 제시하여 개념·관계를 확인받는 절차를 둠. 이번 수행의 확인 결과는 2절 '설계안 확인'에 있음

### 1.3 문서 구성

| 구분 | 절 | 내용 |
|---|---|---|
| 설계 입력 | 3 · 4 | 입력 문서별 역할, CQ별 사용 값과 응답 경로, 답 요소별 원천 근거(4.2), CQ별 구조 꼴 적용(4.3) |
| 설계 결과 근거 | 4.4 · 5 · 6 · 7 | 구조 꼴 선택 근거(4.4절), 개념·관계·데이터 구조의 설계 근거 |
| 정의 문서 미반영 사항 | 8 · 9 · 10 · 11 | 확인 필요 사항, 제외 항목, 서식 미반영 항목, 입력 문서 간 불일치 |
| 결정 기록 | 12 | 원천 확인·설계안 확인의 항목별 선택과 정한 쪽(사람·기본값·사람 수정) |

- '외부 수정(근거 미기재)'은 사람이 더하거나 이름을 바꾼 요소라 스킬이 설정 근거·명명 근거를 기재하지 않은 칸임. '외부 수정(근거 CQ 없음)'은 그 요소를 쓰는 CQ가 없는 칸임
- 'CQ 변경(근거 CQ 없음)'은 CQ 문서에서 빠진 CQ만 근거 CQ였던 요소의 칸임. 요소는 정의 문서에 남아 있음
- 정의 문서 미반영 사항은 결함 목록이 아님. 정의 문서에 없는 항목이 누락인지 의도적 제외인지 구분하기 위한 기록이며, 모든 CQ에 응답 가능한 설계에서도 작성됨

### 1.4 설계 기준

- 개념(Object Type): 업무에서 다루는 대상의 묶음(예: 사원, 부서, 휴가신청)
- 관계(Link Type): 두 개념의 연결. 양쪽 개념의 조인 속성 값이 같을 때 연결됨
- 메타타입(Meta Type): 데이터가 실제로 들어 있는 구조(테이블, 문서 저장소). 개념은 메타타입과 연결되어야 데이터를 표시함
- 중간 개념: 두 개념 사이에 두는 개념. 아래 4가지 조건 중 하나에 해당하고 이를 요구하는 CQ가 있을 때만 둠

| 조건 | 예 |
|---|---|
| 연결 자체에 값이 딸림 | 학생-과목 연결에 수강 학기·성적이 딸림 → '수강' |
| 양쪽 어디에도 연결값이 없음 | 학생에 동아리번호가 없고 동아리에 학생번호가 없으며, 두 번호를 함께 담은 테이블이 원천에 있음 → '학생동아리' |
| 여러 개념이 같은 값을 가지나 그 값이 개념이 아님 | 구매주문·판매주문·세금계산서가 모두 거래처코드를 가짐 → '거래처' |
| 한 칸에 여러 값이 뭉쳐 있음 | '참석자' 칸에 사원번호 3건이 쉼표로 들어 있음 → '교육참석사원' |

- 메타타입 종류: `CUSTOM`(원천 테이블, 또는 사람이 채택한 매핑 테이블), `DOC_TYPE`(원천 문서에서 항목을 뽑아 만드는 문서 타입)
- 매핑 테이블: 고객 시스템의 기존 테이블 값이나 원천 문서가 밝힌 비정형 저장소 경로·파일명 규칙만으로 행을 만들어 두 구조를 잇거나 결합 값·한 칸 목록을 펴는 테이블. 새 업무 데이터를 담지 않음
- 원천 근거: 요소의 데이터가 오는 곳을 원천 문서의 글자로 짚을 수 있는 것. 개념은 테이블·문서 종류, 속성은 컬럼·문서 항목, 관계는 연결 키

## 3. 입력 문서 역할 판정

- 참고 문서는 종류가 정해져 있지 않아 문서별로 사용할 역할을 판정함
- CQ 문서는 사용자가 지정하므로 판정하지 않음. 가이드 2종은 설계 규칙 문서로 역할이 정해져 있음

| 역할 | 사용 내용 |

| 정형 원천 | 테이블과 컬럼. 데이터 위치와 연결 컬럼 |
| 비정형 원천 | 문서 종류와 내부 구조 |
| 업무 범위 | 범위 안과 밖 |
| 스타일 가이드 | 개념·속성·관계의 이름, 설명·별칭·질문예시·경고문 작성 규칙. 설명은 임베딩되어 검색에 사용됨 |

## 4. CQ-구조 연결표와 원천 대조표

### 4.1 CQ-구조 연결표

- CQ별 사용 값, 값을 담은 속성, 응답 경로를 기재함. 이 리포트와 검증 리포트의 CQ 번호 내용은 이 표에서 확인함
- 등급은 CQ 문서가 매긴 말을 그대로 적으며, 등급이 없으면 '-'
- 응답 경로의 '→'는 관계 방향, '←'는 반대 방향으로 거쳐 감을 뜻하며 괄호 안은 관계 이름임. 홉 수는 거치는 관계 수(한 개념 안에서 끝나면 0홉)
- 응답 경로가 '경로 없음'인 CQ의 판정은 검증 리포트 5절에 있음

| No. | CQ | 출처 | 등급 | 사용 값 | 사용 속성 | 응답 경로 | 홉 수 |
|---|---|---|---|---|---|---|---|

### 4.2 원천 대조표

- 답 요소마다 원천 근거와 처리를 기재함. 판정 있음이 아닌 요소는 만들지 않았거나 사람이 고른 방법(조인·매핑 테이블)으로 만듦
- 원천에만 있는 테이블 n건은 9.1절에 있음

| No. | 답 요소 | 요소 종류 | 사용 CQ | 판정 | 근거 위치 | 처리 | 결정 No. |
|---|---|---|---|---|---|---|---|

### 4.3 구조 꼴 적용표

- CQ마다 어떤 구조 꼴로 답하는지와 꼴 요소 가운데 채운 것·뺀 것을 기재함. 한 CQ를 나눠 서로 다른 꼴로 답하면 조각마다 한 줄임
- 구조 꼴: 질문이 묻는 모양에 맞춰 개념과 관계를 엮는 정해진 꼴(예: 참여 사건, 역할 관계). 6절 구조 꼴 칸은 이 표의 고른 꼴과 같음
- 뺀 꼴 요소는 원천 근거가 없어 만들지 않은 요소이며 4.2절 No.로 가리킴

| No. | CQ | CQ 꼴 표지 | 고른 꼴 | 맞춤 경우 | 채운 꼴 요소 | 뺀 꼴 요소 | 내려간 꼴 | 대안 꼴 | 결정 No. |
|---|---|---|---|---|---|---|---|---|---|

### 4.4 구조 꼴 선택 근거

- 구조 꼴마다(또는 같은 판단으로 묶인 CQ 조각마다) 고른 꼴, CQ 꼴 표지, 4.2절 원천 판정, 정한 단계, 버린 대안과 까닭, 줄인 꼴이면 뺀 요소를 글머리 묶음으로 기재함

## 5. 개념 설계

### 5.1 개념 목록

- 개념별 설정 근거를 기재함
- 대표 표시 속성: 화면에서 개념을 가리킬 때 보이는 값(서식의 Title Key). 개념마다 1건
- 식별 속성: 개체를 서로 구분하는 값
- 근거 CQ가 빈 개념은 만들지 않아야 할 개념임

| No. | 개념 | 대표 표시 속성 | 식별 속성 | 속성 수 | 근거 CQ | 개념 설정 근거 | 원천 |
|---|---|---|---|---|---|---|---|

### 5.2 명명 근거

- 같은 대상을 입력 문서마다 다르게 부르므로, 선택한 이름과 선택 근거를 기재함
- 같은 입력으로 재설계 시 같은 이름이 나오도록 선택 규칙을 남김

| No. | 개념 | 입력 문서 표현 | 명명 근거 |
|---|---|---|---|

### 5.3 CQ 외 추가 속성

- CQ가 요구한 속성만 두는 것이 원칙임. 관계 연결에 쓰는 조인 속성 등 규격상 필요한 속성만 예외로 둠
- 이 표에 없는 속성이 4절의 어느 CQ와도 연결되지 않으면 만들지 않아야 할 속성임

| No. | 개념·속성 | 추가 사유 | 요구 근거 |
|---|---|---|---|

## 6. 관계 설계

- 관계별 원천 연결값 유무와 근거를 기재함
- 원천에 연결 키가 있거나 사람이 채택한 매핑 테이블·조인으로 잇는 관계만 만듦. 만들지 않은 경로는 4.2절과 검증 리포트 5.2절에 있음

| No. | 관계 | 출발 → 도착 | 조인 속성 | 근거 CQ | 연결 근거 | 구조 꼴 |
|---|---|---|---|---|---|---|

## 7. 매핑 테이블 제안과 문서 타입

- 대상 환경에 아직 없어 먼저 만들어야 하는 구조임. 사람이 채택한 매핑 테이블과 원천 문서를 근거로 선언한 문서 타입 둘뿐임
- 새 데이터가 필요한 테이블·컬럼은 제안하지 않음
- 채택하지 않은 매핑 테이블 후보도 행을 남김. 채택하면 살아나는 CQ를 근거 CQ 칸에서 확인함

### 7.1 매핑 테이블 제안

| No. | 이름 | 꼴 | 재료 | 생성 방법 | 근거 CQ | 쓰는 요소 | 데이터 확인 사항 | 결정 | 만드는 곳 | 조치 주체 |
|---|---|---|---|---|---|---|---|---|---|---|

### 7.2 문서 타입

## 8. 확인 필요 사항

- 입력 문서로 알 수 없어 확인이 필요한 항목임. 정의 문서의 '확인 필요' 표기와 1:1로 대응하지 않음
- 대부분 실제 데이터를 확인해야 알 수 있는 값임(코드 저장값, 값 형식 등)
- 확인 후 정의 문서의 해당 항목을 수정함
- 2절 '설계안 확인'은 설계안에 대한 사용자 확인 결과이고, 이 절은 아직 확인되지 않은 값임

## 9. 제외 항목

### 9.1 일반 항목

- 입력 문서에 있으나 의도적으로 온톨로지에 넣지 않은 항목임
- 제외 사유 유형: CQ 미사용, 저장값이 아닌 계산값, 공식 기록이 아닌 표현, 이번 범위에서 제외된 CQ. CQ가 요구했는데 원천 근거가 없어 만들지 않은 요소는 4.2절에 있음
- CQ가 추가되면 이 절에서 복원 대상을 확인함

### 9.2 미적용 중간 개념

- 중간 개념은 질의 단계를 늘리므로 1.4의 4가지 조건에 해당하고 이를 요구하는 CQ가 있을 때만 둠
