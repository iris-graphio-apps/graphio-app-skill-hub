# 구조 판정 서식

검증 리포트는 **무엇을 검사했는지** 적는다. 이 문서는 그 결과에 등급을 매겨
**구조를 확정해도 되는지** 한 줄로 만든다.

두 문서를 가른 까닭이 있다. 검사 결과만 있으면 읽는 사람은 「지적 15건」 을 보고도
그것이 고쳐야 할 항목인지 규칙을 지킨 항목인지 모른다. 실제로 지적된 것 대부분은
고칠 것이 아니라 다음 단계의 일거리다. 등급을 매기지 않으면 그 둘이 똑같이 보인다.

**⑨ 단계가 이 문서를 마지막에 쓴다.** 검증 리포트를 다 쓴 뒤에 쓴다 — 이 문서는
검증 리포트를 읽어 만들기 때문이다.

**문서의 꼴과 문체는 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 를 따른다.** 판정
스크립트가 그 규칙대로 문서를 내므로, 손으로 고칠 때도 그 규칙을 벗어나지 않는다.

**규칙과 등급은 [`검사-규칙.md`](검사-규칙.md)에 있다.** 이 문서는 그 규칙으로 판정 문서를 만드는 법을 적는다.

---

## 판정은 한 가지로 정해진다

| 판정 | 조건 |
|---|---|
| 확정 가능 | Error가 0건이다 |
| 확정 불가 | Error가 1건이라도 있다 |

**Warning은 판정을 막지 않는다.** 인지하라는 뜻이고, 언제 처리할지는 인수 측이
정한다. Warning이 스물이어도 Error가 없으면 확정한다.

**등급은 Error·Warning·Info 셋뿐이다.** 넷째 등급을 만들지 않는다. 등급이 늘면 「이건 꼭 해야 하나」 라는
물음이 되돌아온다. 고칠 것이 아닌 항목은 Info라 3절에 올리지 않고 4절에 건수만 적는다.

---

## 등급은 규칙마다 정해져 있다

**Error·Warning·Info는 [`검사-규칙.md`](검사-규칙.md) 2절의 등급 칸이 정한다.** 검증 리포트의 지적마다 붙은 규칙 번호로 등급을 찾는다. 판정 스크립트도 그 표를 읽어 등급을 붙인다. 이 문서에는 규칙과 등급을 따로 적지 않는다.

**목록 밖의 것은 Error가 아니다.** 등급이 Error인 규칙에 걸린 지적만 Error다. 다른 항목이 심각해 보여도 판정 문서에서 등급을 올리지 않는다. 정말 늘려야 하면 [`검사-규칙.md`](검사-규칙.md) 5절대로 규칙을 더하고 까닭을 남긴다.

**필수 CQ를 무엇으로 볼지는 CQ 문서가 정한다.** [`입력-문서-읽기.md`](입력-문서-읽기.md) 2장
「필수 질문」 의 차례로 필수 등급을 정해 그 말을 `--required-grade` 로 알려 준다. 차례 ③(등급이
없거나 높낮이를 가릴 수 없다)이면 옵션을 주지 않아 모든 CQ를 필수로 본다.

**Info 규칙의 지적은 고칠 항목이 아니라 다음 단계의 일거리다.** 판정 문서 4절(조치 대상 외 항목)에
규칙마다 건수만 적고 무엇을 언제 채우는지는 검증 리포트 7절(후속 조치)에 둔다. 두 문서에 목록을
겹쳐 적지 않는다.

DOC-09·SPC-03으로 잡히지 않는 대상 환경 작업(설계 리포트 7.1절의 생성 방법 등), MAP-02~04로 세지 않는 원천 조치, 원천 확보·수집 시험, 사람이 정해야
풀리는 것도 같은 성격이다. 건수를 스크립트가 세지 못하므로 4절에 줄로 올리지 않고,
1.2 판정 기준에 「검증 리포트 7절 사항은 판정에 영향 없음」 으로 한 번 밝힌다.

**「고칠 것이 아니다」 를 문서에 적어 둔다.** 적지 않으면 읽는 사람은 건수를 보고
할 일로 센다. 이 스킬이 처음 부딪힌 문제가 그것이었다.

## 만드는 법

검증 리포트를 다 쓴 뒤 판정 스크립트를 수행한다. 판정 스크립트는 [`검사-규칙.md`](검사-규칙.md)와 검증 리포트, 정의 문서를 읽는다. 스크립트 검사 결과는 적힌 대로 믿지 않는다. 수집 스크립트를 다시 수행해 검증 리포트의 수집 조건, 4.1 No.1·No.2 행과 자동 채움 주석, 4.2절 스크립트 행과 맞대 본다. 그래서 수집할 때 준 옵션을 같이 준다. 스킬이 적은 위치(4.2절 스킬 행, 5절 부분 응답·응답 불가 행)는 정의 문서에서 다시 찾아 빠진 줄 번호를 채운다.

```bash
python3 scripts/judge_structure.py \
  <온톨로지-정의.md> <온톨로지-검증-리포트.md> \
  --converter <converter 스킬 폴더> \
  --required-grade 필수 \
  --manual-checked \
  -o <이름>-온톨로지-구조-판정.md
# converter 스킬이 없어 --spec-skipped 로 수집했으면 --converter 대신 --spec-skipped
# 수집할 때 --source·--warn-mark 를 줬으면 같게 준다
```

명령은 스킬 폴더에서 수행하는 꼴로 적었다. 수행하는 폴더에 따라 스크립트와 converter 경로, 파일 경로를 주는 법은 SKILL.md 2.5에 있다.

| 옵션 | 의미 |
|---|---|
| `--required-grade` | 등급 칸에서 필수로 볼 말. CQ 문서가 쓴 말 그대로 쓴다. 여러 번 줄 수 있다. **주지 않으면 모든 CQ를 필수로 본다** |
| `--converter` | converter 스킬 폴더. 수집 스크립트를 다시 수행해 검증 리포트와 맞대 볼 때 쓴다 |
| `--spec-skipped` | converter 스킬이 없어 서식 변환 검사를 수행하지 못했다. `--converter`와 둘 가운데 하나만 준다 |
| `--source` | 원천 구조 문서. 여러 파일을 받는다. 수집할 때 준 것과 같은 파일을 준다. 검증 리포트 문서 정보 표에 원천 구조 문서가 적혀 있으면 반드시 준다 |
| `--manual-checked` | 설계 리포트 11절을 확인해 입력 문서 간 불일치(INP-01) 행을 검증 리포트 4.2절에 모두 적었다 |
| `--warn-mark` | 가이드가 정한 경고 기호가 `⚠` 가 아닐 때. 수집할 때 준 것과 같게 준다 |
| `--name` | 판정 문서 제목에 쓸 이름. 주지 않으면 정의 문서 파일 이름에서 딴다 |
| `-o`(`--out`) | 쓸 곳. 주지 않으면 화면에 낸다 |

**앞 판의 옵션 다섯은 없어졌다.** 옵션으로 넘기던 것을 이제 검증 리포트에서 읽는다.

- `--spec-errors`·`--spec-warnings`·`--spec-deferred`: 검증 리포트 4.2절의 규격 검사 행(SPC-01~03)이 대신한다
- `--convert-failed`: 검증 리포트 4.1 No.2 결과(변환 실패)가 대신한다
- `--add-major`: 검증 리포트 4.2절의 스킬 행이 대신한다

**converter 스킬이 없으면 판정 범위가 좁아진다.** `--spec-skipped`로 판정하면 서식 변환 검사가 5절(미수행 검사)에 남는다. 반입되는지 모르는 채로 판정한 것이다.

종료 코드는 0 확정 가능, 1 확정 불가, 2 판정하지 않음이다.

### 판정하지 않고 멈추는 경우

입력을 읽지 못하면 스크립트는 판정 문서를 쓰지 않고 종료 코드 2로 멈춘다. 읽지 못한 채
판정하면 Error가 가려진 문서가 「확정 가능」 으로 나가기 때문이다. 메시지대로 검증 리포트나
옵션을 고친 뒤 다시 수행한다. 고칠 곳이 스킬 스크립트·규칙 목록 문서·converter 쪽이면 셋째 줄에 '판정 문서는 쓰지 않았다.'만 나온다. 이때는 고치지 않고 사용자에게 알린다.

메시지는 표준 오류로 나온다. '판정하지 않음:' 줄에 까닭을, '고칠 곳:' 줄에 고칠 곳을 적는다. 아래 표는 두 줄의 글자를 판정 스크립트에서 그대로 옮긴 것이다. 바뀌는 값은 `<…>`로 적었다. 표는 규칙 목록, 옵션, 입력 파일, 수집 조건, 2절, 4.1절, 4.2절, 위치, 5절, 6절로 나눠 둔다.

| 메시지('판정하지 않음:' 뒤) | 고칠 곳('고칠 곳:' 뒤) |
|---|---|
| `규칙 목록 문서를 읽지 못했거나 확인에 걸림: <까닭>` | `스킬 스크립트·규칙 목록 문서·converter 쪽 문제라 입력이나 옵션으로 풀리지 않음. 스크립트를 고치지 말고 사용자에게 알림` |

| `검증 리포트 문서 정보 표의 원천 구조 문서 행에 문서가 적혀 있으나 --source 가 없음` | `옵션` |

| `정의 문서가 없음: <경로>` | `정의 문서 경로` |
| `정의 문서를 읽지 못함: <경로> (<문제>)` | `정의 문서` |
| `검증 리포트를 읽지 못함: <경로> (<까닭>)` | `검증 리포트 경로` |
| `판정 문서를 쓸 폴더가 없음: <폴더>` / `판정 문서를 쓰지 못함: <경로> (<까닭>)` | `-o 경로` |
| `검증 리포트 4.2절 표 아래 첫 주석에 수집 조건 줄이 없음` / `검증 리포트 4.2절 수집 조건 줄의 꼴이 수집 스크립트가 낸 꼴과 다름` | `수집 스크립트 출력을 4.2절에 다시 붙임` |
| `수집 조건이 판정할 때의 조건과 다름. <원인>` | `다시 수집하거나 옵션을 수집 때와 맞춤` |

### 스킬이 적는 지적

스크립트는 스스로 셀 수 있는 것만 센다. 가이드 위반(GDE-01·02), 어느 CQ도 쓰지 않는 개념·속성(CQS-05), 입력 문서 간 불일치(INP-01)는 스킬이 검사해 검증 리포트 4.2절에 스킬 행으로 적는다. 판정 스크립트는 그 행의 규칙 번호로 등급을 붙인다. 쓰는 법은 [`검증-리포트-서식.md`](검증-리포트-서식.md) 4.2절에 있다. **판정 문서를 손으로 고쳐 줄을 더하지 않는다** — 손으로 더하면 2절의 건수와 No. 가 어긋난다.

**`--manual-checked` 는 설계 리포트 11절을 확인해 INP-01 행을 모두 적었다는 뜻이다.** 적을 불일치가 없어도 확인했으면 준다. 가이드 준수 검사와 CQ-구조 정합성 검사를 했는지는 검증 리포트 4.1 No.3·No.4 결과가 보여 준다. 주지 않으면 5절(미수행 검사)에 입력 문서 간 불일치 확인이 남는다. 4.2절에 있는 INP-01 행은 그래도 등급을 매겨 올린다.

**CQ 등급 미확정(CQS-06)은 스크립트가 올린다.** 검증 리포트 2절 「필수 CQ 기준」 에 '(스킬 판단)' 이
붙었거나 '전체 CQ' 로 시작하면 — 입력-문서-읽기.md 2장 차례 ②·③ 으로 정한 경우다 — Warning으로
적는다. 4.2절에 적으면 판정 스크립트가 멈춘다.

## 1. 개요

### 1.1 목적

- 검증 리포트의 검사 결과에 등급을 부여하여 온톨로지 구조의 확정 가능 여부를 판정함
- 조치가 필요한 항목과 조치 대상 외 항목을 구분함

### 1.2 판정 기준

- Error 0건이면 확정 가능, 1건 이상이면 확정 불가로 판정함
- Warning은 확정을 막지 않음. 처리 시점은 인수 측이 결정함
- 등급은 규칙마다 정해져 있음(1.3 참조)

| 등급 | 정의 | 판정 영향 |
|---|---|---|
| Error | 필수 CQ에 응답하지 못하거나 틀린 답을 내는 항목, 또는 Graphio 반입을 막는 항목 | 1건 이상이면 확정 불가 |
| Warning | 구조와 필수 CQ 응답에는 문제가 없으나 인수 측이 인지해야 하는 항목 | 영향 없음 |
| Info | 규칙에 따라 비워 두었거나 대상 환경에서 이어서 할 항목 | 영향 없음 |

- Info 항목은 3절에 올리지 않고 4절에 건수만 기재함
- 검증 리포트 7절(후속 조치)의 사항은 판정에 영향 없음
- 5절에 미수행 검사가 있으면 판정은 수행한 검사 범위 내에서만 유효함

### 지적 사항을 적는 법

3.1·3.2절은 요약표 하나와 상세표 여럿으로 적는다. 요약표는 지적 한 건에 한 행이고 상세표는 묶음마다 하나다. 칸의 뜻은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장에 있다.

- 규칙·외부 코드·문제 설명·조치 방안·조치 주체가 같은 지적을 한 묶음으로 둔다
- 요약표는 규칙 번호 차례로 둔다. 같은 규칙 안에서는 묶음 차례, 묶음 안에서는 출처 표의 No. 차례다. 묶음 차례는 묶음의 첫 행이 출처 표에 나오는 차례다. 출처 표는 검증 리포트 4.2절, 5절, 6절, 2절 차례로 본다. 그래서 한 묶음의 행은 요약표에서 늘 이어진다
- 상세표의 지적 번호는 Error-n·Warning-n이고 n은 요약표 No.다. 묶었으면 'Warning-1~2'처럼 적는다
- 상세표는 제목 없이 지적 번호 행으로 구분한다. 제목은 `###`까지만 쓴다. 두 칸짜리 표라 No. 칸을 두지 않는다([`리포트-작성-규칙.md`](리포트-작성-규칙.md) 1·2장)
- 상세표의 위치는 한 건이면 그 위치, 묶었으면 '요약표 No.1~2' 꼴이다
- 발생 경로는 묶은 지적의 경로가 같고 두 문장 이내면 칸에 그대로 적는다. 같은데 두 문장을 넘으면 칸에 '표 아래 ※ 주석에 적음'을 적고 표 아래 '※ No.1~2 발생 경로:' 주석에 옮긴다. 서로 다르면 칸에 '건별로 표 아래 ※ 주석에 적음'을 적고 표 아래 '※ No.n 발생 경로:' 주석을 건마다 한 줄씩 둔다
- 참고 자료는 묶은 지적의 참고 자료를 겹치지 않게 모으고 끝에 검증 리포트 기록 위치를 붙인다
- 1.3에는 3·4절에 나온 규칙을 규칙 번호 차례로 [`검사-규칙.md`](검사-규칙.md) 2·3절에서 옮긴다
- 1.3 첫머리에는 '스킬'과 탐지 방식의 '스킬 검사'가 무엇인지 한 줄 적는다. '스킬'의 뜻은 검증 리포트 1.2절과 같다. 판정 문서만 받은 사람도 탐지 방식 칸을 읽을 수 있어야 하기 때문이다
- 4절은 Info 규칙마다 한 행이고 규칙 번호 차례로 둔다. 참조 위치는 검증 리포트 기록 위치 뒤에 [`검사-규칙.md`](검사-규칙.md) 3절의 기본 참고 자료를 붙인다
