# 구조 판정 서식

검증 리포트는 **무엇을 검사했는지** 적는다. 이 문서는 그 결과에 등급을 매겨
**구조를 확정해도 되는지** 한 줄로 만든다.

두 문서를 가른 까닭이 있다. 검사 결과만 있으면 읽는 사람은 「지적 15건」 을 보고도
그것이 고쳐야 할 항목인지 규칙을 지킨 항목인지 모른다. 실제로 지적된 것 대부분은
고칠 것이 아니라 다음 단계의 일거리다. 등급을 매기지 않으면 그 둘이 똑같이 보인다.

**⑨ 단계가 이 문서를 마지막에 쓴다.** 검증 리포트를 다 쓴 뒤에 쓴다 — 이 문서는
검증 리포트를 읽어 만들기 때문이다.

**문서의 꼴과 문체는 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 를 따른다.** 판정
스크립트가 그 규칙대로 문서를 내므로, 손으로 고칠 때도 그 규칙을 벗어나지 않는다.

---

## 판정은 한 가지로 정해진다

| 판정 | 조건 |
|---|---|
| 확정 가능 | 치명이 0건이다 |
| 확정 불가 | 치명이 1건이라도 있다 |

**중대는 판정을 막지 않는다.** 인지하라는 뜻이고, 언제 처리할지는 인수 측이
정한다. 중대가 스물이어도 치명이 없으면 확정한다.

**등급은 둘뿐이다.** 셋째 등급을 만들지 않는다. 등급이 늘면 「이건 꼭 해야 하나」 라는
물음이 되돌아온다. 고칠 것이 아닌 항목은 등급을 붙이지 않고 4절에 건수만 적는다.

---

## 치명 — 닫힌 목록

**여기 없는 것은 치명이 아니다.** 아래 일곱 가지가 전부다. 다른 항목이 심각해 보여도
목록을 늘리지 않고, 정말 늘려야 하면 이 표에 한 줄을 더해 까닭을 남긴다.

구분 칸의 말은 판정 문서 3.1절 구분 칸에 그대로 쓴다. 집계 주체가 「옵션 입력」 이면
자매 스킬의 결과를 판정 스크립트 옵션으로 넘긴 것이고, 「스킬」 이면 스킬이 짚어
`--add-major` 로 넘긴 것이다.

| 구분 | 출처 | 치명 사유 | 집계 주체 |
|---|---|---|---|
| 필수 CQ 응답 불가 | 검증 리포트 5절(CQ별 판정) | 필수 CQ에 응답 불가 | 스크립트 |
| 필수 CQ 부분 응답 | 검증 리포트 5절(CQ별 판정) | CQ 조건 미충족으로 답 불충분 | 스크립트 |
| 대체 매핑 | 검증 리포트 6절(매핑 컬럼 대조 결과) | 질의 결과가 틀림 | 스크립트 |
| 규격 오류 | 검증 리포트 4절(서식 변환 검사) | 반입 불가 | 옵션 입력 |
| 변환 실패 | 검증 리포트 4절(서식 변환 검사) | 반입 불가 | 옵션 입력 |
| 정의 문서 오류 | 검증 리포트 4절(정의 문서 검사) | 서식 손상으로 내용 누락 | 스크립트 |
| 대표 표시 속성 오류 | 검증 리포트 4절(정의 문서 검사) · 3절(산출 규모) | 반입 불가 | 스크립트 |

**대표 표시 속성 오류는 정의 문서 오류와 따로 센다.** 정의 문서 검사기가 개념마다 한 건씩 짚고, 판정 스크립트는 그 건을 「대표 표시 속성 오류」 로 옮긴다. 산출 규모 표의 건수로 한 번 더 세지 않는다.

**필수 CQ를 무엇으로 볼지는 CQ 문서가 정한다.** [`입력-문서-읽기.md`](입력-문서-읽기.md) 2장
「필수 질문」 의 차례로 필수 등급을 정해 그 말을 `--required-grade` 로 알려 준다. 차례 ③(등급이
없거나 높낮이를 가릴 수 없다)이면 옵션을 주지 않아 모든 CQ를 필수로 본다.

**`확인 필요` 가 남은 것은 치명이 아니다.** 모르는 값을 지어내지 않고 비운 것은 규칙을
지킨 것이다. 그 항목을 채우는 일은 검증 리포트 7절(후속 조치)에 있다.

## 중대 — 닫힌 목록

구분 칸의 말은 판정 문서 3.2절 구분 칸에 그대로 쓴다.

| 구분 | 출처 | 중대 사유 | 집계 주체 |
|---|---|---|---|
| CQ 응답 불가 · CQ 부분 응답 | 검증 리포트 5절(CQ별 판정) | 응답하지 못하는 CQ 잔존. 필수 CQ가 아니므로 확정을 막지 않음 | 스크립트 |
| 정의 문서 경고 | 검증 리포트 4절(정의 문서 검사) | 내용 누락 가능성 | 스크립트 |
| 규격 경고 | 검증 리포트 4절(서식 변환 검사) | 규격은 통과했으나 의도 확인 필요 | 옵션 입력 |
| 미사용 개념·속성 | 검증 리포트 4절(CQ-구조 정합성 검사) | CQ가 요구하지 않은 구조. 확정 시 그대로 잔존 | 스킬 |
| 스타일 가이드 위반 · 서식 가이드 위반 | 검증 리포트 4절(가이드 준수 검사) | 가이드 규칙 위반 | 스킬 |
| CQ 등급 미확정 | 검증 리포트 2절(필수 CQ 기준) | 필수 CQ 범위 불확정으로 판정 근거 불안정 | 스크립트 |
| 입력 문서 간 불일치 | 설계 리포트 11절(입력 문서 간 불일치) | 어느 쪽이 맞는지 미확정 | 스킬 |

**「가이드 위반」 에서 `확인 필요` 를 뺀다.** 생성 후 검사의
「`확인 필요` 가 남아 있는 항목이 있는가」 는 규칙을 지킨 항목이라 여기가 아니라 4절로
간다. 이 항 하나 때문에 「지적 1건」 이 되어 고쳐야 할 것처럼 읽히는 일이 잦다.

## 등급이 붙지 않는 것

아래는 고칠 항목이 아니라 **다음 단계의 일거리**다. 판정 문서 4절(조치 대상 외 항목)에
건수만 적고, 무엇을 언제 채우는지는 검증 리포트 7절(후속 조치)에 둔다. 두 문서에 목록을
겹쳐 적지 않는다.

항목 칸의 말은 판정 문서 4절 항목 칸에 그대로 쓴다.

| 항목 | 참조 위치 |
|---|---|
| 의미 불일치 미매핑 · 원천 부재 미매핑 · 원천 확인 필요 미매핑 | 검증 리포트 6절(매핑 컬럼 대조 결과) · 설계 리포트 7.2절(기존 메타타입 추가 컬럼) |
| '확인 필요' 표기 | 검증 리포트 3절(산출 규모) · 설계 리포트 8절(확인 필요 사항) |
| 정의 문서 검사 확인 사항 | 검증 리포트 4절(정의 문서 검사) |
| 규격 검사 보류 | 검증 리포트 4절(서식 변환 검사) · 검증 리포트 7.1절(대상 환경 조치) |

대상 환경에 만들 데이터 구조, 원천에 더할 컬럼, 원천 확보·수집 시험, 사람이 정해야
풀리는 것도 같은 성격이다. 건수를 스크립트가 세지 못하므로 4절에 줄로 올리지 않고,
1.2 판정 기준에 「검증 리포트 7절 사항은 판정에 영향 없음」 으로 한 번 밝힌다.

**「'확인 필요' 표기」 는 정의 문서에 적힌 `확인 필요` 의 횟수다.** 한 항목에 여러 번 적히기도 하므로 설계 리포트 8절의 줄 수와 다를 수 있다.

**「고칠 것이 아니다」 를 문서에 적어 둔다.** 적지 않으면 읽는 사람은 건수를 보고
할 일로 센다. 이 스킬이 처음 부딪힌 문제가 그것이었다.

## 만드는 법

검증 리포트를 다 쓴 뒤 스크립트를 수행한다. 규격 검사 결과는 자매 스킬이 내므로
숫자로 넘긴다 — 검증 리포트 4절(서식 변환 검사)에 적은 값을 그대로 쓴다.

```bash
python3 scripts/judge_structure.py \
  <온톨로지-정의.md> <온톨로지-검증-리포트.md> \
  --required-grade 필수 \
  --spec-errors 0 --spec-warnings 0 --spec-deferred 1 \
  --manual-checked \
  --add-major "스타일 가이드 위반|속성 이름 12건이 원천 컬럼명과 같음(검사 항목 C-01 지적, 규칙 R-01 위반)|속성 이름을 업무 용어로 변경|설계 담당|검증 리포트 4절(가이드 준수 검사)|대상 속성: ORD_NO, CNTR_AMT, …" \
  -o <이름>-온톨로지-구조-판정.md
```

| 옵션 | 의미 |
|---|---|
| `--required-grade` | 등급 칸에서 필수로 볼 말. CQ 문서가 쓴 말 그대로 쓴다. 여러 번 줄 수 있다. **주지 않으면 모든 CQ를 필수로 본다** |
| `--spec-errors` · `--spec-warnings` · `--spec-deferred` | Graphio 규격 검사 결과 건수 |
| `--spec-skipped` | 규격 검사를 수행하지 못했다. 자매 스킬이 없을 때 쓴다 |
| `--convert-failed` | 정의 문서가 Graphio 정의 파일로 옮겨지지 않았다 |
| `--manual-checked` | 스킬이 짚는 세 항목(아래)을 모두 짚었다 |
| `--add-major` | 스킬이 짚어 찾은 중대 사항 한 건. `구분\|지적 내용\|조치 방안\|조치 주체\|근거[\|주석]` 꼴. 여러 번 줄 수 있다. 구분은 아래 「스킬이 짚는 세 항목」 표의 말만 받는다 |
| `--warn-mark` | 가이드가 정한 경고 기호가 `⚠` 가 아닐 때 |
| `-o` | 쓸 곳. 주지 않으면 화면에 낸다 |

**`--spec-errors` 를 주지 않으면 규격 검사를 수행하지 못한 것으로 본다.** 그러면
5절(미수행 검사)에 줄이 남고 판정 범위가 좁아진다. 0건이면 `--spec-errors 0` 이라고 적는다.

### 판정하지 않고 멈추는 경우

입력을 읽지 못하면 스크립트는 판정 문서를 쓰지 않고 종료 코드 2로 멈춘다. 읽지 못한 채
판정하면 치명이 가려진 문서가 「확정 가능」 으로 나가기 때문이다. 메시지대로 검증 리포트나
옵션을 고친 뒤 다시 수행한다.

| 중단 조건 | 수정 위치 |
|---|---|
| 검증 리포트 5절이 없거나, 표·'판정' 열·행이 없다 | 검증 리포트 5절(CQ별 판정) |
| 5절·6절 판정값이 닫힌 목록 밖의 말이다 | 검증 리포트 5·6절. 말은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 4장 |
| `--required-grade` 의 말이 5절 등급 칸에 없거나 등급 열이 없다 | 옵션 또는 5절 등급 칸 |
| 검증 리포트 2절 「필수 CQ 기준」 에 적은 등급과 `--required-grade` 가 다르다 | 둘 중 틀린 쪽 |
| 검증 리포트 6절이 없거나, 표는 있는데 '판정' 열이 없다 | 검증 리포트 6절. 매핑 단계를 건너뛰었으면 표 없이 「매핑 단계 미수행. 원천 구조 문서 미제공」 을 적는다 — 이때는 멈추지 않고 5절(미수행 검사)에 남긴다 |
| 정의 문서를 읽지 못했다 | 정의 문서의 Object Type 절 |
| `--add-major` 의 칸 수나 구분이 틀렸다 | 옵션 |

### 스킬이 짚는 세 항목

스크립트는 스스로 셀 수 있는 것만 센다. 사람이 문서를 펴야 아는 세 항목은 스킬이 짚어
**옵션으로 넘긴다.** 산출물을 손으로 고쳐 줄을 더하지 않는다 — 손으로 더하면 2절의
건수와 No. 가 어긋난다.

| 구분 | 확인 내용 | 확인 위치 |
|---|---|---|
| 미사용 개념·속성 | 어느 CQ도 쓰지 않는 개념·속성 | 검증 리포트 4절(CQ-구조 정합성 검사) · 설계 리포트 5.1절 |
| 스타일 가이드 위반 · 서식 가이드 위반 | 가이드 검사 항목 가운데 지적된 것. `확인 필요` 가 남았는지 묻는 항은 뺀다 | 검증 리포트 4절(가이드 준수 검사) |
| 입력 문서 간 불일치 | 판정할 쪽이 정해지지 않은 채 남은 불일치 | 설계 리포트 11절 |

- 해당하는 것이 있으면 — 한 건마다 `--add-major` 를 준다. 구분 칸에는 위 표의 말을 쓴다
- 셋을 모두 짚었으면 — 해당하는 것이 없어도 `--manual-checked` 를 준다

**CQ 등급 미확정은 스크립트가 올린다.** 검증 리포트 2절 「필수 CQ 기준」 에 '(스킬 판단)' 이
붙었거나 '전체 CQ' 로 시작하면 — 입력-문서-읽기.md 2장 차례 ②·③ 으로 정한 경우다 — 중대로
적는다. 스킬이 같은 구분으로 `--add-major` 를 넘겼으면 겹쳐 올리지 않는다.

**`--manual-checked` 를 주지 않으면 세 항목이 5절(미수행 검사)에 남는다.** 세 항목은
모두 중대라 판정을 바꾸지는 않는다. 짚지 않은 채 넘어갔다는 것이 문서에 드러나게 하기
위해서다.

**`--add-major` 의 칸 쓰는 법.** 지적 내용에는 무엇이 몇 건인지와 영향 판단을 두 문장
이내로, 조치 방안에는 조치만 적는다. 대상 목록이 길면 여섯째 칸(주석)으로 넘긴다 — 표 아래 `※`
줄로 나간다. 조치 주체가 정해지지 않았으면 `지정 필요` 로 적는다. 칸 안에 `|` 를 쓰지
않는다. 문체는 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 3장을, 규칙 번호를 적는 법은
같은 문서 5장을 따른다 — 가이드의 검사 항목(C-xx)이 규칙(R-xx)을 점검하는 짝이면 둘을
함께 적는다.

## 뼈대

스크립트가 이 꼴로 낸다. 손으로 쓸 때도 절과 칸을 바꾸지 않는다 — 다음 실행과
맞대 보는 문서라 꼴이 달라지면 무엇이 나아졌는지 알 수 없다. `<!-- -->` 주석은
스킬에게 하는 지시라 산출물에 옮기지 않는다.

```markdown
# (이름) 온톨로지 구조 판정

| 항목 | 내용 |
|---|---|
| 판정일 | YYYY-MM-DD |
| 대상 문서 | (정의 문서 경로) |
| 검증 리포트 | (검증 리포트 경로) |
| 설계 리포트 | (검증 리포트 문서 정보 표에서 옮김) |
| CQ 문서 | (검증 리포트 문서 정보 표에서 옮김) |
| 스타일 가이드 | (검증 리포트 문서 정보 표에서 옮김) |
| 서식 가이드 | (검증 리포트 문서 정보 표에서 옮김) |

## 1. 개요

### 1.1 목적

- 검증 리포트의 검사 결과에 등급을 부여하여 온톨로지 구조의 확정 가능 여부를 판정함
- 조치가 필요한 항목과 조치 대상 외 항목을 구분함

### 1.2 판정 기준

- 치명 사항 0건이면 확정 가능, 1건 이상이면 확정 불가로 판정함
- 중대 사항은 확정을 막지 않음. 처리 시점은 인수 측이 결정함

| 등급 | 정의 | 판정 영향 |
|---|---|---|
| 치명 | 필수 CQ에 응답하지 못하거나 틀린 답을 내는 항목, 또는 Graphio 반입을 막는 항목 | 1건 이상이면 확정 불가 |
| 중대 | 구조와 필수 CQ 응답에는 문제가 없으나 인수 측이 인지해야 하는 항목 | 영향 없음 |

- 규칙에 따라 비워 둔 항목은 등급을 부여하지 않고 4절에 건수만 기재함
- 검증 리포트 7절(후속 조치)의 사항은 판정에 영향 없음
- 5절에 미수행 검사가 있으면 판정은 수행한 검사 범위 내에서만 유효함

## 2. 판정 결과

| 항목 | 결과 |
|---|---|
| 판정 | **확정 가능** / **확정 불가** |
| 치명 사항 | n건 |
| 중대 사항 | n건 |
| 미수행 검사 | n건 / 해당 없음 |
| 필수 CQ 응답 | n건 중 n건 응답 가능(전체 CQ n건) |
| 필수 CQ 기준 | (검증 리포트 2절 '필수 CQ 기준'을 그대로 옮김) |

- 미수행 검사 n건이 있어 판정은 수행한 검사 범위 내에서만 유효함(5절 참조)

<!-- 위 한 줄은 미수행 검사가 있을 때만 -->

## 3. 지적 사항

### 3.1 치명 사항

| No. | 구분 | 지적 내용 | 조치 방안 | 조치 주체 | 근거 |
|---|---|---|---|---|---|

<!-- 0건이면 표 없이 "해당 없음" 한 줄 -->

### 3.2 중대 사항

| No. | 구분 | 지적 내용 | 조치 방안 | 조치 주체 | 근거 |
|---|---|---|---|---|---|

※ No.n (주석)

## 4. 조치 대상 외 항목

- 규칙에 따라 비워 두었거나 다음 단계로 넘긴 항목임
- 건수를 줄이기 위해 값을 임의로 채우지 않음
- 조치 일정과 방법은 검증 리포트 7절(후속 조치)에 있음

| No. | 항목 | 건수 | 참조 위치 |
|---|---|---|---|

## 5. 미수행 검사

- 미수행 검사 항목은 판정에 반영되지 않았으므로 해당 범위의 지적 사항이 있을 수 있음

| No. | 검사 항목 | 미수행 사유 |
|---|---|---|

<!-- 0건이면 첫머리 설명도 없이 "해당 없음" 한 줄 -->

## 6. 후속 조치

- (스크립트가 판정 결과에 맞춰 넣음)
- CQ 등급이 바뀌어 필수 CQ가 달라지면 판정 재수행 필요
```

**5절에 줄이 있으면 판정은 그만큼만 믿는다.** 규격 검사를 수행하지 못했으면 반입되는지
모르는 것이고, 그 항목에 치명이 있을 수 있다. 「확정 가능」 이 나왔어도 5절을 함께 읽는다.

## 판정에서 보이는 신호

| 신호 | 의미 |
|---|---|
| 5절에 「스킬 확인 항목」 줄이 남아 있다 | 세 항목을 짚지 않았다. 짚고 `--manual-checked` 로 다시 수행한다 |
| 치명이 0건인데 판정이 「확정 불가」 다 | 손으로 고쳐 쓴 것이다. 판정은 치명 건수만 보고 정한다 |
| 2절 건수와 3절 줄 수가 다르다 | 손으로 줄을 더하거나 지웠다. `--add-major` 로 넘겨 다시 수행한다 |
| 4절이 「해당 없음」 이다 | 규칙대로 비운 항목이 하나도 없다는 뜻이다. 정말 없는지 검증 리포트 6절과 3절을 맞대 본다 |
| 5절에 줄이 있는데 1.2 에 판정 범위 문장이 없다 | 스크립트를 거치지 않고 손으로 쓴 것이다 |
| 검증 리포트 2절의 「구조 판정」 과 이 문서의 판정이 다르다 | 둘 중 하나가 낡았다. 검증 리포트를 고친 뒤 판정을 다시 수행한다 |
| 3.1 에 데이터를 채우는 일이나 대상 환경 작업이 있다 | 등급을 잘못 매겼다. 위 「등급이 붙지 않는 것」 으로 옮긴다 |
| 스크립트가 「판정하지 않음」 으로 멈췄다 | 입력이 어긋났다. 위 「판정하지 않고 멈추는 경우」 대로 고친 뒤 다시 수행한다. 판정 문서를 손으로 쓰지 않는다 |
| 인용 블록·줄표·조사 띄어쓰기가 보인다 | 옛 서식이다. [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 6장으로 점검한다 |
