# 리포트 작성 규칙

설계 리포트·검증 리포트·구조 판정 세 문서가 함께 따르는 규칙이다. 절 구성과 칸은 각 서식 문서에 있고, **문서의 꼴과 문체는 이 문서 한 곳에만 둔다.** 세 서식이 같은 규칙을 저마다 적으면 한쪽만 고쳐져 문서끼리 꼴이 어긋난다.

검증 리포트와 구조 판정이 함께 쓰는 지적 기록 칸과 위치·발생 경로 표기도 이 문서 7장에 둔다. 규칙마다 다른 내용(등급, 설명, 규칙별 발생 경로 표기, 조치 지침)은 [`검사-규칙.md`](검사-규칙.md)에 있다.

세 문서는 업무 보고서로 읽힌다. 받는 사람은 보고서를 읽는 방식대로 읽는다 — 목차로 위치를 잡고, 표 머리글로 칸의 뜻을 알고, 개조식 문장을 훑는다. 서술형 안내문이나 문장형 머리글은 그 읽기를 막는다.

---

## 1. 문서 구성

| 규칙 | 적용 |
|---|---|
| 제목 바로 아래에 **문서 정보 표**를 둔다 | 작성일(검사일·판정일)과 대상·참조 문서만 둔다. 경로 뒤에 CQ 건수·가이드 출처 같은 짧은 부가 정보는 붙여도 된다. 판정·집계 결과는 넣지 않는다 |
| 첫 절은 **1. 개요**다 | 1.1 목적을 두고, 문서마다 정한 소절(산출물 구성·판정 기준·문서 구성)을 이어 둔다 |
| 둘째 절은 **결과 요약**이다 | 설계 결과 요약·검증 결과 요약·판정 결과. 받는 사람이 이 절만 읽고도 결론을 안다 |
| 마지막 절은 **후속 조치**다 | 설계 리포트는 예외다. 할 일은 검증 리포트와 구조 판정이 갖는다 |
| 제목은 대·중·소 위계를 지킨다 | `##` 는 `1.`, `###` 는 `1.1`, 그 아래는 쓰지 않는다 |
| 본문 절마다 첫머리에 **개조식 설명**을 둔다 | 무엇을 적은 절인지와 표 읽는 법을 다섯 줄 이내로. 인용 블록(`>`)을 쓰지 않는다. 1. 개요, 결과 요약 절, 소절만 두는 상위 절에는 두지 않아도 된다 |
| 표 아래에는 **※ 주석**을 둘 수 있다 | 칸에 다 담지 못한 목록·경위·예외를 `※ No.n` 꼴로. 표 아래 개조식 보충 줄도 같은 자리에 둔다 |

**인용 블록을 쓰지 않는다.** 설명은 1. 개요나 절 첫머리 개조식으로 옮긴다. 인용 블록 안내문은 본문과 무게가 달라 보여 건너뛰어 읽히고, 표가 인용 블록 안에 들어가면 판정 스크립트가 본문 표와 가려 읽어야 한다.

**작성자용 지침을 산출물에 남기지 않는다.** 설계·검증 리포트의 뼈대는 `assets/` 의 뼈대 파일에 있고, 산출물에 들어갈 말만 담는다. 서식 문서(`references/`)의 지시문과 `<!-- -->` 주석은 산출물에 옮기지 않는다. 빈 칸을 채우라는 표시, 「(스킬이 채운다)」 같은 줄도 산출물에 남기지 않는다.

**※ 주석 가운데 둘은 수집 스크립트가 낸 줄을 그대로 붙인다.** 손으로 쓰는 `※ No.n` 주석이 아니므로 꼴을 바꾸거나 고치지 않는다.

| 주석 | 붙이는 곳 | 내용 |
|---|---|---|
| `※ 수집 조건:` | 검증 리포트 4.2절 표 아래 첫 주석 | 수집할 때의 입력·옵션·스크립트 판본을 해시와 함께 적은 한 줄. 지적이 없어 표 대신 '해당 없음'을 적어도 붙임 |
| `※ No.2 자동 채움:` | 검증 리포트 4.1절 표 아래 | 변환 스크립트가 스스로 채운 값을 알리는 줄 |

- 수집 조건은 해시가 든 기술 정보지만 업무 보고서에 남긴다. 담기는 것과 판정 스크립트가 맞대 보는 법은 [`검증-리포트-서식.md`](검증-리포트-서식.md) 4.2절에 있다
- 자동 채움 주석은 스킬이 따로 쓰지 않는다. 스킬은 변환 스크립트를 수행하지 않으므로 이 주석이 자동 채움의 유일한 출처다

## 2. 제목과 표 머리글

**절 제목은 명사형으로만 쓴다.** 설명을 붙이지 않는다. 등급이나 판정값의 뜻은 1. 개요에서 한 번만 정의한다.

| 잘못된 예 | 올바른 예 |
|---|---|
| 1. Error — 고치지 않으면 구조를 확정하지 못한다 | 3.1 Error |
| 3. 고칠 것이 아닌 자리 | 4. 조치 대상 외 항목 |
| 1. 돌린 검사 여섯 | 4. 검사 수행 결과 |

**표 머리글은 명사형으로 쓴다.** 물음꼴(`무엇이 걸렸나`, `어디에 있나`)을 쓰지 않는다.

| 잘못된 예 | 올바른 예 |
|---|---|
| 무엇이 걸렸나 · 어디 · 무엇을 하면 풀리나 | 지적 내용 · 근거 · 조치 방안 |
| 얼마나 · 어디에 있나 | 건수 · 참조 위치 |
| 답할 수 있나 · 무엇이 빠졌나 | 판정 · 누락 항목 |

**목록형 표는 맨 앞에 `No.` 열을 둔다.** 다른 절이나 문서가 「3.2절 No.2」 처럼 가리킬 수 있다. 항목·값 두 칸짜리 요약표에는 두지 않는다. 구조 판정 1.3(적용 규칙) 표에도 두지 않는다. 규칙 번호가 행을 가리키는 식별자이기 때문이다.

**한 칸에 한 가지만 적는다.** 지적의 갈래는 규칙 칸에, 가이드 항목 번호와 GOS 코드는 외부 코드 칸에, 요소는 위치 칸에 따로 적고 문제 설명에 섞지 않는다. 조치 방안 칸에는 조치만 적고, 영향 판단(「확정은 막지 않음」)은 문제 설명 칸에 적는다. 셀 안에 목록이 길어지면 표 아래 `※` 주석으로 옮긴다.

```markdown
| No. | 규칙 | 외부 코드 | 위치 | 문제 설명 | 발생 경로 | 조치 방안 | 조치 주체 | 참고 자료 |
|---|---|---|---|---|---|---|---|---|
| 1 | GDE-01 | C-01, R-01 | 개념 '사원' › 속성 '번호'(정의 문서 15줄) | 속성 이름이 원천 컬럼명과 같음. 질의에 쓰는 업무 용어와 달라 이 속성을 찾지 못할 수 있음 | 검사 항목 C-01 → 개념 '사원' › 속성 '번호' | 속성 이름을 업무 용어로 변경 | 설계 담당 | 스타일 가이드 1장(절대 규칙), 9.1절(이름 검사) |
| 2 | GDE-01 | C-01, R-01 | 개념 '부서' › 속성 '명칭'(정의 문서 31줄) | 속성 이름이 원천 컬럼명과 같음. 질의에 쓰는 업무 용어와 달라 이 속성을 찾지 못할 수 있음 | 검사 항목 C-01 → 개념 '부서' › 속성 '명칭' | 속성 이름을 업무 용어로 변경 | 설계 담당 | 스타일 가이드 1장(절대 규칙), 9.1절(이름 검사) |
```

두 행은 문제 설명과 조치 방안까지 같아 구조 판정에서 상세표 하나로 묶인다(7장).

## 3. 문체

**본문은 개조식으로 쓴다.** 종결은 `~함`·`~임`·`~필요`·`~없음` 으로 통일한다. 서술형 구어체를 쓰지 않는다.

| 잘못된 예 | 올바른 예 |
|---|---|
| 확정은 되지만 알고 넘긴다 | 확정을 막지 않음. 인지 필요 |
| 줄이려고 값을 채우지 않는다 | 건수를 줄이기 위해 값을 임의로 채우지 않음 |
| 그대로 남아 있으면 짚지 않은 것이다 | 미확인 항목으로 간주함 |
| 답에 이르는 경로를 만든다. 필수가 아니라 확정은 막지 않는다 | (조치 방안) 응답 경로 추가 · (문제 설명) 필수 CQ가 아니므로 확정을 막지 않음 |

**표 칸의 값은 명사구나 개조식 문장으로 끝낸다.** 한 칸에는 사실과 그 영향 판단까지 두 문장을 넘기지 않는다(「CQ-01 응답 불가. 필수 CQ가 아니므로 확정을 막지 않음」). 더 길어지면 표 아래 `※` 주석으로 옮긴다.

## 4. 용어

산출물에서는 아래 말을 쓴다. 스킬 본문과 서식 문서가 옛말을 쓰는 자리가 있어도 산출물에는 옮기지 않는다.

| 금지 용어 | 사용 용어 |
|---|---|
| 자리 (문서 안의 한 항목을 가리킬 때) | 항목 |
| 넘겨받는 쪽 · 넘겨받는 사람 | 인수 측 |
| 필수로 본 질문 · 필수 질문 | 필수 CQ |
| 질문 · 검증질문 (목록의 한 항목을 가리킬 때) | CQ |
| (검사를) 돌리다 | (검사를) 수행하다 |
| 걸림 (검사 결과를 가리킬 때) | 지적 |
| 하지 못함 | 미수행 |
| 없음 (절·표·칸 전체가 비었을 때) | 해당 없음. 문장 끝의 '~없음'(「매핑 없음」)은 그대로 씀 |
| 규칙 번호 (가이드의 C-xx·R-xx를 가리킬 때) | 가이드 항목 번호. 규칙 번호는 검사 규칙 번호(DOC-01 등)에만 씀 |

### 판정값 — 닫힌 목록

판정값은 아래 말만 쓴다. CQ별 판정과 매핑 판정은 판정 스크립트가 그대로 읽으므로, 목록 밖의 말이 있으면 스크립트가 판정하지 않고 멈춘다.

| 적용 위치 | 판정값 |
|---|---|
| CQ별 판정 (검증 리포트 5절) | `응답 가능` · `부분 응답` · `응답 불가` |
| 매핑 컬럼 대조 (검증 리포트 6절) | `일치` · `대체 매핑` · `의미 불일치 미매핑` · `원천 부재 미매핑` · `원천 확인 필요 미매핑` |
| 검사 항목별 결과 (검증 리포트 4.1절) | No.3~6은 `통과` · `지적 n건` · `미수행`. No.1 정의 문서 검사는 `Error n건, Warning n건, Info n건`, No.2 서식 변환 검사는 `변환 성공, 규격 Error n건, Warning n건, Info n건` 또는 `변환 실패(Error n건), 규격 검사 미수행` 꼴로 적는다. 수행하지 못했으면 `미수행` |
| 구조 판정 | `확정 가능` · `확정 불가` |
| 등급 | `Error` · `Warning` · `Info`. Info 지적은 구조 판정 3절(지적 사항)에 올리지 않고 4절에 건수만 적음. 첫 글자만 대문자로 쓰고 조사는 붙여 씀(Error가, Warning은) |

- No.1·No.2 행은 결과와 지적 내용까지 수집 스크립트가 낸 그대로 붙인다. 판정 스크립트가 다시 수행한 결과와 맞대 본다
- No.2의 건수는 위치 수다. 한 지적이 여러 요소를 가리키면 요소마다 센다. [`검사-규칙.md`](검사-규칙.md) 4절에 따라 DOC 행으로 옮긴 것도 세고 그 건수를 아래 꼴로 덧붙인다. 덧붙이지 않으면 규격 Error가 있는 파일이 No.2 통과로 세어진다
  - 규격 Error: `규격 Error n건(m건은 DOC-04 행으로 적음)`
  - Info: `Info n건(m건은 DOC-09 행으로 적음)`
  - 변환 실패: `변환 실패(Error n건, m건은 DOC-03 행으로 적음), 규격 검사 미수행`. 괄호가 겹치지 않게 같은 괄호 안에 쉼표로 잇는다
  - 변환 실패를 DOC-11 행으로 옮겼으면 `m건은 DOC-11 행으로 적음`, DOC-03과 함께면 `변환 실패(Error n건, m건은 DOC-03 행으로, k건은 DOC-11 행으로 적음), 규격 검사 미수행`

**규칙 번호도 닫힌 목록이다.** [`검사-규칙.md`](검사-규칙.md) 2절에 있고 상태가 `사용`인 번호만 쓴다. 목록 밖의 번호나 `사용하지 않음` 번호가 검증 리포트에 있으면 판정 스크립트가 판정하지 않고 멈춘다. 지적의 등급(Error·Warning·Info)은 규칙 번호로 정해지므로 지적마다 적지 않는다.

## 5. 표기

| 규칙 | 잘못된 예 | 올바른 예 |
|---|---|---|
| 조사는 붙여 쓴다. 영문·숫자·코드 뒤도 같다 | C-01 을 · Graphio 에 · `확인 필요` 로 | C-01을 · Graphio에 · '확인 필요'로 |
| 단위는 `건` 으로 통일한다 | 81자리 · 12개 · 3항 | 81건 · 12건 · 3건 |
| 빈 절·빈 표는 표 없이 `해당 없음` 한 줄로 적는다 | 머리글만 있는 표 · 「없음 — 구조를 확정해도 된다.」 | 해당 없음 |
| 다른 문서·절은 절 번호와 괄호 속 항목명으로 가리킨다 | 검증 리포트 1절 「가이드의 규칙을 지켰는가」 · 1절 첫째 줄 | 검증 리포트 4.1절(가이드 준수 검사) |
| 인용은 작은따옴표로 한다. 낫표(「」)를 쓰지 않는다 | 「확인 필요」 | '확인 필요' |
| 줄표(—)를 쓰지 않는다 | 필수 — 전체 47건 중 22건 | 22건 중 22건 응답 가능(전체 CQ 47건) |
| 굵은 글씨는 판정 결과 값에만 쓴다 | 문장마다 굵게 | 2절 판정 칸의 **확정 가능** |

**줄표 대신** 쉼표·괄호를 쓰거나 문장을 나눈다. 코드·식별자·경로는 백틱(`` ` ``)으로 감싼다. 판정값, 규칙 번호, 외부 코드는 백틱 없이 쓴다.

**가이드 항목 번호는 가이드 원문의 번호를 그대로 쓴다.** 한 지적 안에서 같은 항목을 가리키면 외부 코드 칸과 조치 방안에 같은 번호를 쓴다. 가이드가 검사 항목(C-xx)과 가이드 규칙(R-xx)에 번호를 따로 매겼으면 검사 항목 번호와 그 항목이 점검하는 가이드 규칙 번호를 함께 적는다. 외부 코드 칸에는 번호만 쉼표로 잇는다(C-01, R-01). 문장 안에서는 무엇의 번호인지 밝힌다(「검사 항목 C-01 지적, 가이드 규칙 R-01 위반」). 한쪽 번호만 적으면 두 번호가 같은 것을 가리키는지 읽는 사람이 알 수 없다. 번호 뒤 괄호에는 가이드 원문의 뜻을 적고, 뜻을 지어 붙이지 않는다.

**조치 주체가 정해지지 않았으면 `지정 필요` 라고 적는다.** 「사람이 정한다」 처럼 적지 않는다.

## 6. 작성 후 점검

산출물을 다 쓰면 아래를 짚는다. 스크립트 행 발생 경로의 원문 발췌는 정의 문서의 글을 옮긴 것이라 문체 점검(줄표·낫표·조사 띄어쓰기·굵은 글씨 같은 것)에서 뺀다. 발췌를 고치면 스크립트 행이 다시 수행한 결과와 달라진다.

- [ ] 인용 블록(`>`)이 남아 있지 않음
- [ ] `<!-- -->` 주석과 「(스킬이 채운다)」 줄이 남아 있지 않음
- [ ] 절 제목과 표 머리글이 명사형임
- [ ] 머리글만 있는 빈 표가 없음 (`해당 없음` 한 줄)
- [ ] 조사를 띄어 쓴 곳이 없음 (`` ` 을``, `` ` 에`` 같은 꼴)
- [ ] 판정값이 4장 닫힌 목록 안의 말임
- [ ] 줄표(—)와 낫표(「」)가 남아 있지 않음
- [ ] 단위가 '건'으로 통일됨 (개·자리·항 없음)
- [ ] 목록형 표 맨 앞에 `No.` 열이 있음
- [ ] 굵은 글씨가 판정 결과 값에만 쓰임
- [ ] 표 칸 안의 세로줄(`|`)이 `\|` 로 막혀 있음
- [ ] 세 문장 이상인 표 칸이 없음 (길면 표 아래 `※ No.n` 주석으로 옮김. 예외는 7장 발생 경로 표기)
- [ ] 지적 목록과 상세표의 칸이 7장 지적 기록 칸대로임
- [ ] 규칙 번호가 [`검사-규칙.md`](검사-규칙.md) 2절에 있고 상태가 `사용`인 번호임
- [ ] 위치가 7장 머리말 목록 안의 꼴임
- [ ] 문제 설명에 위치의 요소 이름을 되풀이하지 않음
- [ ] 스킬 행이 스크립트 행과 같은 결함을 다시 적지 않음 ([`검사-규칙.md`](검사-규칙.md) 4절)
- [ ] 스크립트 행, `※ 수집 조건:` 줄, `※ No.2 자동 채움:` 주석을 고치지 않음
- [ ] 검증 리포트 4.2절 발생 경로, 5절 근거, 6절 판정 근거를 ※ 주석으로 빼지 않음

## 7. 지적 기록

검증 리포트 4.2절(지적 목록)과 구조 판정 3.1·3.2절의 상세표는 지적을 같은 칸으로 적는다. 칸의 뜻과 위치·발생 경로의 꼴은 이 장에 있다. 규칙마다 다른 내용은 [`검사-규칙.md`](검사-규칙.md)에 있고 표의 칸 차례와 절 구성은 각 서식 문서에 있다.

### 지적 기록 칸

지적 한 건은 아래 아홉 칸을 가진다. 지적 목록은 탐지 방식을 뺀 여덟 칸을, 상세표는 아홉 칸을 모두 쓴다.

| 칸 | 쓰는 법 |
|---|---|
| 규칙 | 검사 규칙 번호. 지적 목록과 구조 판정 요약표에는 번호만, 상세표에는 이름을 붙여 적음(SPC-01 규격 오류) |
| 외부 코드 | 규칙 밖에서 온 번호. GOS 코드, 가이드 항목 번호(5장), 서식 가이드 절 번호. 여럿이면 쉼표로 잇고 없으면 '해당 없음' |
| 위치 | 지적이 가리키는 요소. 아래 위치 표기의 꼴로만 적음 |
| 문제 설명 | 무엇이 문제이고 어떤 영향이 있는지. 두 문장 이내(3장). 위치에 적은 요소 이름을 되풀이하지 않음 |
| 발생 경로 | 결함이 생긴 경로. 아래 발생 경로 표기를 따름 |
| 조치 방안 | 이 건을 고치는 조치만 적음(2장). 조치 대상 외 항목은 '해당 없음' |
| 조치 주체 | 조치할 담당이나 문서 작성자. 비우지 않음. 정해지지 않았으면 '지정 필요'(5장) |
| 참고 자료 | 받는 사람이 가진 문서의 위치(가이드 항목, 설계 리포트 절, 입력 문서 항목). 스킬의 참고 문서와 스크립트는 받는 사람이 볼 수 없어 적지 않음. 구조 판정에는 판정 스크립트가 검증 리포트 기록 위치를 덧붙임 |
| 탐지 방식 | 그 지적을 낸 검사. 판정 스크립트가 검사-규칙.md 2절에서 옮겨 상세표에만 적음 |

- 지적 목록의 행은 수집 스크립트가 낸 스크립트 행(규칙 접두어 DOC·CNV·SPC)과 스킬이 검사해 적는 스킬 행으로 나뉜다
- 스크립트 행은 수집 스크립트 출력을 그대로 붙이고 고치지 않는다. 판정 스크립트가 수집 스크립트를 다시 수행해 칸 단위로 맞대 보므로 고친 행이 있으면 판정하지 않고 멈춘다
- 문제 설명에 요소 이름을 넣지 않는다. 구조 판정은 규칙·외부 코드·문제 설명·조치 방안·조치 주체가 같은 지적을 상세표 하나로 묶는다. 문제 설명에 이름이 들어가면 같은 결함도 요소마다 상세표가 따로 생긴다

### 위치 표기

- 위치는 아래 머리말 가운데 하나로 시작한다. 머리말은 닫힌 목록이다
- 판정 스크립트는 지적 목록의 스킬 행과 검증 리포트 5절 부분 응답·응답 불가 행의 위치를 머리말로 해석해 정의 문서에서 찾는다. 목록 밖의 꼴이거나 정의 문서에서 찾지 못하거나 줄 번호가 다르면 판정하지 않고 멈춘다
- 스킬이 적는 위치는 줄 번호를 빼도 된다. '(정의 문서 n줄)'을 통째로 빼고 관계는 ', 정의 문서 n줄'만 뺀다(관계 '이어진 휴가사용'(휴가신청 → 휴가사용)). 판정 스크립트가 정의 문서에서 찾아 구조 판정에 채운다. 다만 같은 이름의 요소가 정의 문서에 여럿이면 어느 것인지 가릴 수 없어 멈추므로 줄 번호를 적는다
- 판정 스크립트는 검증 리포트 5절 응답 가능 행의 위치를 해석하지 않는다. 그 행에 적는 값은 [`검증-리포트-서식.md`](검증-리포트-서식.md) 5절에 있다

| 머리말 | 표기 | 예 |
|---|---|---|
| 개념 | 개념 '이름'(정의 문서 n줄) | 개념 '사원'(정의 문서 12줄) |
| 개념(없음) | 개념 '이름'(없음) | 개념 '강사'(없음) |
| 개념 › 속성 | 개념 '이름' › 속성 '이름'(정의 문서 n줄) | 개념 '사원' › 속성 '입사 시점'(정의 문서 17줄) |
| 개념 › 속성(없음) | 개념 '이름' › 속성 '이름'(없음) | 개념 '휴가신청' › 속성 '결재 진행 상태'(없음) |
| 관계 | 관계 '이름'(출발 → 도착, 정의 문서 n줄) | 관계 '이어진 휴가사용'(휴가신청 → 휴가사용, 정의 문서 64줄) |
| 관계(없음) | 관계(없음) 개념 '출발' → 개념 '도착' | 관계(없음) 개념 '교육' → 개념 '부서' |
| 데이터 구조 | 데이터 구조 '이름'(정의 문서 n줄) | 데이터 구조 'hr.TB_휴가신청내역'(정의 문서 110줄) |
| 데이터 구조(없음) | 데이터 구조 '이름'(없음) | 데이터 구조 'hr.TB_교육수강내역'(없음) |
| 데이터 구조 › 컬럼 | 데이터 구조 '이름' › 컬럼 '이름'(정의 문서 n줄) | 데이터 구조 'hr.TB_휴가신청내역' › 컬럼 '신청자번호'(정의 문서 115줄) |
| 매핑 | 매핑 '개념 ← 데이터 구조'(정의 문서 n줄) | 매핑 '휴가신청 ← hr.TB_휴가신청내역'(정의 문서 150줄) |
| 매핑(없음) | 매핑 '개념 ← 데이터 구조'(없음) | 매핑 '휴가사용 ← hr.TB_휴가사용내역'(없음) |
| 매핑 › 속성 | 매핑 '개념 ← 데이터 구조' › 속성 '이름'(정의 문서 n줄) | 매핑 '휴가신청 ← hr.TB_휴가신청내역' › 속성 '휴가 시작 시점'(정의 문서 154줄) |
| CQ | CQ 번호 | CQ Q1 |
| 입력 문서 | 입력 문서 '이름' 절·표 | 입력 문서 'CQ 문서' 등급 표기 |
| 정의 문서 | 정의 문서 n줄 | 정의 문서 7줄 |

- 줄 번호는 요소의 제목이나 표 행이 있는 줄이다. 줄 단위 규칙(DOC-01~03, DOC-11, CNV-01)과 DOC-05의 읽히지 않는 설명은 문제가 된 줄 자체를 적는다. 변환 스크립트가 제목 줄로만 알리는 오류(색·공개 칸, 속성 표 없음 등)는 제목 줄을 적는다
- '정의 문서 n줄'은 요소를 이름으로 가리킬 수 없을 때만 쓴다. 이름 칸이 빈 행, 출발이나 도착 칸이 빈 관계 행, 제목이 '개념 ← 데이터 구조' 꼴이 아닌 매핑 블록과 그 아래 행, 관계 절의 DOC-11(첫 표 뒤의 표, 첫 표 앞의 소제목), 요소를 특정할 수 없는 서식 손상이 그렇다
- 관계는 양끝 개념을 함께 적는다. 관계 이름은 겹칠 수 있기 때문이다(서식 가이드)
- 두 개념 사이에 다른 관계가 이미 있으면 관계(없음) 끝에 조인 속성을 붙인다. 꼴은 `관계(없음) 개념 '출발' → 개념 '도착'(조인 속성 '이름')`이고 괄호 앞을 띄우지 않는다(예: `관계(없음) 개념 '교육' → 개념 '부서'(조인 속성 '주관 부서 번호')`). 조인 속성이 출발·도착 어느 쪽 것인지는 적지 않는다
- 매핑의 화살표는 정의 문서 원문이 `<-`여도 `←`로 적는다
- CQ 번호는 CQ 문서가 붙인 번호를 그대로 쓴다
- 같은 이름의 요소가 여럿이라 한 지적이 여러 줄을 가리키면 줄마다 한 행으로 나눈다
- '(없음)' 꼴은 판정 스크립트가 아래처럼 확인한다
  - 상위 요소가 있는 꼴(개념 › 속성(없음))은 상위 요소가 있고 하위 요소가 없는지 본다
  - 상위 요소가 없는 꼴(개념·데이터 구조·매핑(없음))은 그 종류의 요소 제목에 그 이름이 없는지만 본다. 개념은 Object Type 절, 데이터 구조는 Meta Type 절, 매핑은 Object Mapping 절의 제목을 보고 설명·별칭·`[SQL]`에 나오는 이름은 보지 않는다
  - 관계(없음)은 두 개념이 정의 문서에 있는지 먼저 본다. 그다음 두 개념 사이에 그 방향의 관계가 없는지 본다. 조인 속성을 붙였으면 그 조인 속성으로 잇는 관계가 없는지 본다
- '정의 문서 n줄'은 판정 스크립트가 그 줄이 정의 문서 안에 있는지만 본다
- CQ 지적의 위치는 'CQ 번호'로 시작하고 끊긴 곳을 '; '로 이어 적는다. 작은따옴표 안의 '; '는 나누지 않는다(예: `CQ Q1; 관계(없음) 개념 '교육' → 개념 '부서'`)

### 발생 경로 표기

결함이 어디서 어떻게 생겼는지 단계 차례로 적는다. 공통 꼴은 아래와 같고 규칙마다 거치는 단계와 정보 출처는 [`검사-규칙.md`](검사-규칙.md) 3절의 발생 경로 표기 칸에 있다.

| 표기 | 뜻 |
|---|---|
| → | 앞 단계에서 뒤 단계로 이어짐 |
| ✕ | 경로가 끊긴 곳 |
| ↔ | 두 문서나 한 문서의 두 곳에 서로 다르게 적힌 내용을 맞댐 |
| 원문 발췌 | 정의 문서 검사(DOC) 지적. 경로 대신 문제가 된 줄을 `정의 문서 n줄: 발췌` 꼴로 옮겨 적음. 60자를 넘으면 …로 줄이고 발췌에 든 세로줄도 막음(6장) |

- 두 문장을 넘으면 3장대로 표 아래 ※ 주석으로 옮긴다. 다만 검증 리포트 4.2절 발생 경로, 5절 근거, 6절 판정 근거 칸은 길어도 칸 안에 적는다. 판정 스크립트가 이 칸을 그대로 구조 판정으로 옮기므로 주석으로 빼면 구조 판정에서 경로가 빠진다
- JSON 안의 경로는 정의 파일 안의 위치로 적는다(`objectTypes[i].properties[j]` 꼴). 임시 파일 경로는 적지 않는다. 실행마다 달라져 판정 스크립트의 대조가 깨진다

### 지적 식별자

- 지적 식별자는 규칙 번호와 줄 번호를 뺀 위치다(예: `GDE-01 · 개념 '사원' › 속성 '번호'`). 칸을 따로 두지 않는다. 실행끼리 같은 지적을 맞댈 때 쓴다
- 줄 단위 규칙(DOC-01~03, DOC-11, CNV-01)과 DOC-05의 읽히지 않는 설명은 줄 번호까지 넣는다. 한 요소 안에서 같은 규칙 지적이 둘 이상 나올 수 있기 때문이다
- 같은 위치에 같은 규칙 지적이 둘 이상이면 발생 경로로 가른다
