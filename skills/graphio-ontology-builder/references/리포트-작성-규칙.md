# 리포트 작성 규칙

설계 리포트·검증 리포트·구조 판정 세 문서가 함께 따르는 규칙이다. 절 구성과 칸은 각 서식 문서에 있고, **문서의 꼴과 문체는 이 문서 한 곳에만 둔다.** 세 서식이 같은 규칙을 저마다 적으면 한쪽만 고쳐져 문서끼리 꼴이 어긋난다.

세 문서는 업무 보고서로 읽힌다. 받는 사람은 보고서를 읽는 방식대로 읽는다 — 목차로 위치를 잡고, 표 머리글로 칸의 뜻을 알고, 개조식 문장을 훑는다. 서술형 안내문이나 문장형 머리글은 그 읽기를 막는다.

---

## 1. 문서 구성

| 규칙 | 적용 |
|---|---|
| 제목 바로 아래에 **문서 정보 표**를 둔다 | 작성일(검사일·판정일)과 대상·참조 문서만 둔다. 경로 뒤에 CQ 건수·가이드 출처 같은 짧은 부가 정보는 붙여도 된다. 판정·집계 결과는 넣지 않는다 |
| 첫 절은 **1. 개요**다 | 1.1 목적을 두고, 문서마다 정한 소절(산출물 구성·판정 기준·문서 구성)을 이어 둔다 |
| 둘째 절은 **결과 요약**이다 | 설계 결과 요약·검증 결과 요약·판정 결과. 받는 사람이 이 절만 읽고도 결론을 안다 |
| 마지막 절은 **후속 조치**다 | 설계 리포트는 예외다. 할 일은 검증 리포트와 구조 판정이 갖는다 |
| 제목은 대·중·소 위계를 지킨다 | `##` 는 `1.`, `###` 는 `1.1`, 그 아래는 쓰지 않는다 |
| 본문 절마다 첫머리에 **개조식 설명**을 둔다 | 무엇을 적은 절인지와 표 읽는 법을 다섯 줄 이내로. 인용 블록(`>`)을 쓰지 않는다. 1. 개요, 결과 요약 절, 소절만 두는 상위 절에는 두지 않아도 된다 |
| 표 아래에는 **※ 주석**을 둘 수 있다 | 칸에 다 담지 못한 목록·경위·예외를 `※ No.n` 꼴로. 표 아래 개조식 보충 줄도 같은 자리에 둔다 |

**인용 블록을 쓰지 않는다.** 설명은 1. 개요나 절 첫머리 개조식으로 옮긴다. 인용 블록 안내문은 본문과 무게가 달라 보여 건너뛰어 읽히고, 표가 인용 블록 안에 들어가면 판정 스크립트가 본문 표와 가려 읽어야 한다.

**작성자용 지침을 산출물에 남기지 않는다.** 설계·검증 리포트의 뼈대는 `assets/` 의 뼈대 파일에 있고, 산출물에 들어갈 말만 담는다. 서식 문서(`references/`)의 지시문과 `<!-- -->` 주석은 산출물에 옮기지 않는다. 빈 칸을 채우라는 표시, 「(스킬이 채운다)」 같은 줄도 산출물에 남기지 않는다.

## 2. 제목과 표 머리글

**절 제목은 명사형으로만 쓴다.** 설명을 붙이지 않는다. 등급이나 판정값의 뜻은 1. 개요에서 한 번만 정의한다.

| 잘못된 예 | 올바른 예 |
|---|---|
| 1. 치명 — 고치지 않으면 구조를 확정하지 못한다 | 3.1 치명 사항 |
| 3. 고칠 것이 아닌 자리 | 4. 조치 대상 외 항목 |
| 1. 돌린 검사 여섯 | 4. 검사 수행 결과 |

**표 머리글은 명사형으로 쓴다.** 물음꼴(`무엇이 걸렸나`, `어디에 있나`)을 쓰지 않는다.

| 잘못된 예 | 올바른 예 |
|---|---|
| 무엇이 걸렸나 · 어디 · 무엇을 하면 풀리나 | 지적 내용 · 근거 · 조치 방안 |
| 얼마나 · 어디에 있나 | 건수 · 참조 위치 |
| 답할 수 있나 · 무엇이 빠졌나 | 판정 · 누락 항목 |

**목록형 표는 맨 앞에 `No.` 열을 둔다.** 다른 절이나 문서가 「3.2절 No.2」 처럼 가리킬 수 있다. 항목·값 두 칸짜리 요약표에는 두지 않는다.

**한 칸에 한 가지만 적는다.** 유형과 내용을 한 칸에 이어 쓰지 않는다 — `구분` 열을 따로 둔다. 조치 방안 칸에는 조치만 적고, 영향 판단(「확정은 막지 않음」)은 지적 내용 칸에 적는다. 셀 안에 목록이 길어지면 표 아래 `※` 주석으로 옮긴다.

```markdown
| No. | 구분 | 지적 내용 | 조치 방안 | 조치 주체 | 근거 |
|---|---|---|---|---|---|
| 1 | 스타일 가이드 위반 | 속성 이름 12건이 원천 컬럼명과 같음(검사 항목 C-01 지적, 규칙 R-01 위반) | 속성 이름을 업무 용어로 변경 | 설계 담당 | 검증 리포트 4절(가이드 준수 검사) |

※ No.1 대상 속성: ORD_NO, CNTR_AMT, …
```

## 3. 문체

**본문은 개조식으로 쓴다.** 종결은 `~함`·`~임`·`~필요`·`~없음` 으로 통일한다. 서술형 구어체를 쓰지 않는다.

| 잘못된 예 | 올바른 예 |
|---|---|
| 확정은 되지만 알고 넘긴다 | 확정을 막지 않음. 인지 필요 |
| 줄이려고 값을 채우지 않는다 | 건수를 줄이기 위해 값을 임의로 채우지 않음 |
| 그대로 남아 있으면 짚지 않은 것이다 | 미확인 항목으로 간주함 |
| 답에 이르는 경로를 만든다. 필수가 아니라 확정은 막지 않는다 | (조치 방안) 응답 경로 추가 · (지적 내용) 필수 CQ가 아니므로 확정을 막지 않음 |

**표 칸의 값은 명사구나 개조식 문장으로 끝낸다.** 한 칸에는 사실과 그 영향 판단까지 두 문장을 넘기지 않는다(「CQ-03 응답 불가. 필수 CQ가 아니므로 확정을 막지 않음」). 더 길어지면 표 아래 `※` 주석으로 옮긴다.

## 4. 용어

산출물에서는 아래 말을 쓴다. 스킬 본문과 서식 문서가 옛말을 쓰는 자리가 있어도 산출물에는 옮기지 않는다.

| 금지 용어 | 사용 용어 |
|---|---|
| 자리 (문서 안의 한 항목을 가리킬 때) | 항목 |
| 넘겨받는 쪽 · 넘겨받는 사람 | 인수 측 |
| 필수로 본 질문 · 필수 질문 | 필수 CQ |
| 질문 · 검증질문 (목록의 한 항목을 가리킬 때) | CQ |
| (검사를) 돌리다 | (검사를) 수행하다 |
| 걸림 (검사 결과를 가리킬 때) | 지적 |
| 하지 못함 | 미수행 |
| 없음 (절·표·칸 전체가 비었을 때) | 해당 없음. 문장 끝의 '~없음'(「매핑 없음」)은 그대로 씀 |

### 판정값 — 닫힌 목록

판정값은 아래 말만 쓴다. CQ별 판정과 매핑 판정은 판정 스크립트가 그대로 읽으므로, 목록 밖의 말이 있으면 스크립트가 판정하지 않고 멈춘다.

| 적용 위치 | 판정값 |
|---|---|
| CQ별 판정 (검증 리포트 5절) | `응답 가능` · `부분 응답` · `응답 불가` |
| 매핑 컬럼 대조 (검증 리포트 6절) | `일치` · `대체 매핑` · `의미 불일치 미매핑` · `원천 부재 미매핑` · `원천 확인 필요 미매핑` |
| 검사 수행 결과 (검증 리포트 4절) | No.3~6은 `통과` · `지적 n건` · `미수행`. No.1 정의 문서 검사는 `오류 n건, 경고 n건, 확인 n건`, No.2 서식 변환 검사는 `변환 성공, 규격 오류 n건, 경고 n건, 보류 n건` 꼴로 적는다. 수행하지 못했으면 `미수행` |
| 구조 판정 | `확정 가능` · `확정 불가` |
| 등급 | `치명` · `중대` |

## 5. 표기

| 규칙 | 잘못된 예 | 올바른 예 |
|---|---|---|
| 조사는 붙여 쓴다. 영문·숫자·코드 뒤도 같다 | C-01 을 · Graphio 에 · `확인 필요` 로 | C-01을 · Graphio에 · '확인 필요'로 |
| 단위는 `건` 으로 통일한다 | 81자리 · 12개 · 3항 | 81건 · 12건 · 3건 |
| 빈 절·빈 표는 표 없이 `해당 없음` 한 줄로 적는다 | 머리글만 있는 표 · 「없음 — 구조를 확정해도 된다.」 | 해당 없음 |
| 다른 문서·절은 절 번호와 괄호 속 항목명으로 가리킨다 | 검증 리포트 1절 「가이드의 규칙을 지켰는가」 · 1절 첫째 줄 | 검증 리포트 4절(가이드 준수 검사) |
| 인용은 작은따옴표로 한다. 낫표(「」)를 쓰지 않는다 | 「확인 필요」 | '확인 필요' |
| 줄표(—)를 쓰지 않는다 | 필수 — 전체 47건 중 22건 | 22건 중 22건 응답 가능(전체 CQ 47건) |
| 굵은 글씨는 판정 결과 값에만 쓴다 | 문장마다 굵게 | 2절 판정 칸의 **확정 가능** |

**줄표 대신** 쉼표·괄호를 쓰거나 문장을 나눈다. 코드·식별자·경로는 백틱(`` ` ``)으로 감싼다. 판정값은 백틱 없이 쓴다.

**규칙 번호는 가이드 원문의 번호를 그대로 쓴다.** 지적 내용과 조치 방안에서 같은 규칙을 가리키면 같은 번호를 쓴다. 가이드가 검사 항목(C-xx)과 규칙(R-xx)에 번호를 따로 매겼으면, 검사 항목이 점검하는 규칙 번호를 함께 적는다(「검사 항목 C-01 지적, 규칙 R-01 위반」). 한쪽 번호만 적으면 두 번호가 같은 것을 가리키는지 읽는 사람이 알 수 없다. 번호 뒤 괄호에는 가이드 원문의 뜻을 적고, 뜻을 지어 붙이지 않는다.

**조치 주체가 정해지지 않았으면 `지정 필요` 라고 적는다.** 「사람이 정한다」 처럼 적지 않는다.

## 6. 작성 후 점검

산출물을 다 쓰면 아래를 짚는다.

- [ ] 인용 블록(`>`)이 남아 있지 않음
- [ ] `<!-- -->` 주석과 「(스킬이 채운다)」 줄이 남아 있지 않음
- [ ] 절 제목과 표 머리글이 명사형임
- [ ] 머리글만 있는 빈 표가 없음 (`해당 없음` 한 줄)
- [ ] 조사를 띄어 쓴 곳이 없음 (`` ` 을``, `` ` 에`` 같은 꼴)
- [ ] 판정값이 4장 닫힌 목록 안의 말임
- [ ] 줄표(—)와 낫표(「」)가 남아 있지 않음
- [ ] 단위가 '건'으로 통일됨 (개·자리·항 없음)
- [ ] 목록형 표 맨 앞에 `No.` 열이 있음
- [ ] 굵은 글씨가 판정 결과 값에만 쓰임
- [ ] 표 칸 안의 세로줄(`|`)이 `\|` 로 막혀 있음
- [ ] 세 문장 이상인 표 칸이 없음 (길면 표 아래 `※ No.n` 주석으로 옮김)
