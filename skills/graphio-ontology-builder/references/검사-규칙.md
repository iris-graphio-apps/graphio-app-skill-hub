# 검사 규칙

검증 리포트와 구조 판정 문서의 지적은 모두 이 문서의 규칙 번호를 단다. 규칙의 이름·등급·탐지 방식·설명은 **이 문서 한 곳에만 둔다.** 스킬 본문이나 서식 문서가 같은 규칙을 저마다 적으면 한쪽만 고쳐져 판정이 어긋난다.

**판정 스크립트(`judge_structure.py`)와 수집 스크립트(`collect_findings.py`)가 2절과 3절의 표를 읽는다.** 판정 스크립트는 2절의 등급을 지적마다 붙인다. 두 스크립트는 3절의 기본 조치 주체와 기본 참고 자료로 지적 칸을 채운다. 스크립트가 읽는 표는 이 두 표뿐이다. 두 절에는 표를 하나씩만 둔다. 머리글을 바꾸지 않고 칸 안에 세로줄을 쓰지 않는다.

**두 스크립트는 이 문서를 읽을 때 아래를 확인하고 하나라도 어긋나면 멈춘다(종료 코드 2).** 판정 스크립트는 판정 문서를 쓰지 않고 수집 스크립트는 지적 목록 행을 내지 않는다. 규칙 목록을 잘못 읽은 채 판정하면 Error가 가려진 판정 문서가 '확정 가능'으로 나갈 수 있기 때문이다.

- 규칙 번호가 영문 대문자 세 자, 붙임표, 두 자리 숫자의 꼴(`DOC-01`)이고 겹치지 않음
- 등급 값이 `Error`·`Warning`·`Info` 가운데 하나임
- 상태 값이 `사용`·`사용하지 않음` 가운데 하나임
- 스크립트가 스스로 내는 규칙(DOC-01~11, CNV-01, SPC-01~03, CQS-01~04, CQS-06, MAP-01~04)이 모두 있고 상태가 `사용`임
- 2절과 3절의 규칙 번호가 같은 차례로 같음

스킬을 수행하다 멈추면 이 문서와 스크립트를 고치지 말고 까닭을 사용자에게 알린다. 규칙을 더하거나 바꾸는 사람은 메시지대로 이 문서를 고친 뒤 다시 수행한다(5절). 검증 리포트에 쓸 수 있는 규칙 번호의 제약은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 4장에 있다.

**2절의 이름·등급·탐지 방식과 3절의 설명·기본 조치 주체·기본 참고 자료는 산출물로 옮겨진다.** 판정 문서 1.3(적용 규칙)과 상세표, 검증 리포트 4.2절(지적 목록)에 그대로 나오므로 이 칸들은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md)의 문체로 쓴다. 발생 경로 표기와 조치 지침은 산출물을 쓰는 기준이라 옮겨지지 않는다. 스킬은 검증 리포트에 지적을 적을 때 이 두 칸을 따른다.

## 1. 규칙 번호 체계

규칙 번호는 접두어 세 글자와 두 자리 번호를 붙임표로 잇는다(`DOC-01`). 접두어는 지적을 낸 검사를 가리킨다.

| 접두어 | 검사 | 탐지 방식 |
|---|---|---|
| DOC | 정의 문서 검사 | 스크립트(`check_design_doc.py`) |
| CNV | 서식 변환 | 스크립트(`build_graphio_json.py`) |
| SPC | Graphio 규격 검사 | 스크립트(`validate_graphio_json.py`) |
| GDE | 가이드 준수 검사 | 스킬 검사 |
| CQS | CQ-구조 정합성 검사, CQ 통과 조건 검사 | 스킬 검사. CQS-06만 판정 스크립트 |
| MAP | 매핑 의미 검사 | 스킬 검사 |
| INP | 입력 문서 간 불일치 | 스킬 검사(설계 리포트 11절 확인) |

- 탐지 방식의 '스킬 검사'는 이 설계를 수행한 온톨로지 설계 스킬이 문서를 읽고 판단한 검사다. '스킬'은 검증·설계 리포트 1.2절이 정한 뜻 그대로다. 판정 스크립트는 판정 문서 1.3에 이 뜻을 한 줄 적는다
- 산출물에는 '모델 검사'라고 쓰지 않는다. 온톨로지 문서에서 '모델'은 데이터 모델로 읽히기 때문이다
- 지시문도 스킬이 적는 행을 '스킬 행'이라 부른다. 수집 스크립트의 안내 줄과 판정 스크립트의 멈춤 문구가 같은 말을 쓰기 때문이다
- CQ 규칙의 접두어는 `CQ`가 아니라 `CQS`다. CQ 문서가 CQ마다 'CQ-' 꼴 번호를 붙이는 일이 있어 `CQ`로 두면 규칙 번호와 CQ 번호가 겹친다
- 변환 스크립트와 규격 검사기는 converter 스킬(`graphio-ontology-converter`)의 것이다. 이 스킬은 두 스크립트의 출력을 읽기만 한다
- 외부 코드(GOS 코드, 가이드 항목 번호, 서식 가이드 절 번호)는 규칙 번호가 아니다. 지적마다 외부 코드 칸에 따로 적는다

규칙마다 지적이 적히는 곳이 다르다.

| 검사 | 규칙 | 검증 리포트 기록 위치 | 기록 방법 |
|---|---|---|---|
| 정의 문서 검사 | DOC-01~09, DOC-11 | 4.1 No.1 결과값, 4.2 지적 목록 | 수집 스크립트 출력을 그대로 붙임 |
| 서식 변환 검사 | CNV-01, SPC-01~03 | 4.1 No.2 결과값, 4.2 지적 목록 | 수집 스크립트 출력을 그대로 붙임 |
| 가이드 준수 검사 | GDE-01·02 | 4.1 No.3 결과, 4.2 지적 목록 | 스킬이 한 행씩 적음 |
| CQ-구조 정합성 검사 | CQS-01~05 | 4.1 No.4 결과, 5절(CQS-01~04), 4.2 지적 목록(CQS-05) | 스킬이 적음 |
| CQ 통과 조건 검사 | CQS-02·04 | 4.1 No.5 결과, 5절 부분 응답 행 | 스킬이 적음 |
| 매핑 의미 검사 | MAP-01~04 | 4.1 No.6 결과, 6절 | 스킬이 적음 |
| 설계 리포트 11절 확인 | INP-01 | 4.2 지적 목록 | 스킬이 적음 |
| 필수 CQ 기준 | CQS-06 | 2절 필수 CQ 기준 | 판정 스크립트가 올림 |
| '확인 필요' 표기 | DOC-10 | 3절 산출 규모 | 정의 문서 검사기 `--stats` 출력을 붙임 |

- 검증 리포트 5·6절에는 규칙 번호를 적지 않는다. 판정 스크립트가 5절 판정값과 필수 여부로 CQS-01~04를, 6절 판정값으로 MAP-01~04를, 2절 필수 CQ 기준으로 CQS-06을 정한다
- 위 규칙(CQS-01~04, CQS-06, MAP-01~04)이 4.2 지적 목록에 있으면 판정 스크립트가 멈춘다
- DOC-10은 건수만 세는 규칙이라 지적 목록에 행으로 올리지 않는다

## 3. 규칙 설명

2절과 같은 규칙을 같은 차례로 적는다. 칸마다 쓰이는 곳이 다르다.

- **설명**은 무엇을 잡는 규칙이고 왜 그 등급인지를 두 문장 이내로 적는다. 판정 문서 1.3에 그대로 옮겨진다
- **발생 경로 표기**는 규칙마다 발생 경로 칸을 쓰는 방식과 정보 출처다. 화살표와 끊김 표시 같은 공통 꼴은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장에 있다
- **조치 지침**은 조치 방안을 쓰는 기준이다. 건별 조치 방안은 지적마다 따로 적는다. 스크립트 규칙은 수집 스크립트의 변환표가 이 기준대로 문구를 정한다. 스킬이 적는 지적 목록 행과 검증 리포트 5·6절의 조치 방안은 스킬이 이 기준대로 적는다
- **기본 조치 주체**와 **기본 참고 자료**는 스크립트가 지적을 만들 때 그 칸에 넣는 값이다

**기본 조치 주체와 기본 참고 자료는 규칙만으로 정해질 때만 적고 그렇지 않으면 '해당 없음'으로 둔다.**

- 스크립트 규칙(DOC·CNV·SPC)과 판정 스크립트가 만드는 지적(CQS-01~04, CQS-06, MAP-01)의 조치 주체는 지금까지 판정이 쓰던 값을 이어받는다. 나중에 더한 DOC-11은 다른 DOC 규칙과 같이 설계 담당이다
- 스킬이 지적마다 적는 규칙(GDE-01·02, CQS-05, INP-01)은 두 칸 모두 '해당 없음'이다. 조치 주체와 참고 자료가 지적마다 달라 스킬이 행마다 적는다
- 조치 대상 외 규칙(Info 6건)은 기본 조치 주체가 '해당 없음'이다. 판정 문서가 조치를 요구하지 않는다. 누가 할지는 검증 리포트 7절(후속 조치)이 정한다
- 조치 대상 외 규칙의 기본 참고 자료는 확인 필요 목록이나 후속 조치를 적는 곳을 가리킨다. 판정 문서 4절 참조 위치에서 검증 리포트 기록 위치 뒤에 붙는다
- 기본 참고 자료는 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장의 참고 자료 칸 규칙대로 쓴다. 판정 스크립트가 덧붙이는 검증 리포트 기록 위치(4.2절 No.n 등)는 넣지 않는다
- 스타일 가이드와 서식 가이드는 `--style`·`--format`으로 다른 문서가 올 수 있어 절 번호 없이 항목 이름으로 가리킨다. 여러 곳은 쉼표로 잇는다

| 규칙 | 설명 | 발생 경로 표기 | 조치 지침 | 기본 조치 주체 | 기본 참고 자료 |

## 5. 규칙을 더하거나 바꿀 때

- **번호를 다시 쓰지 않는다.** 새 규칙은 그 접두어의 다음 번호를 쓴다. 번호를 다시 쓰면 지난 검증 리포트와 판정 문서의 번호가 다른 규칙을 가리킨다
- **쓰지 않게 된 규칙은 지우지 않고** 2절 상태 칸을 `사용하지 않음`으로 바꾼다. 3절의 행도 그대로 둔다. [`스타일-가이드.md`](스타일-가이드.md) 11장의 G-01·G-02와 같은 방식이다
- 더하거나 바꾼 까닭은 아래 변경 기록에 남긴다
- 2절과 3절은 같은 차례로 함께 고친다. 한쪽만 고치면 두 스크립트가 멈춘다
- 스크립트가 스스로 내는 규칙을 더하거나 쓰지 않게 되면 두 스크립트의 규칙 목록 확인도 함께 고친다
- 등급은 Error·Warning·Info만 쓴다. 넷째 등급을 만들지 않는다. 등급을 바꾸면 같은 입력의 판정이 달라지므로 변경 기록에 까닭을 반드시 남긴다
- 겹치는 규칙을 새로 찾으면 4절 표에 행을 더하고 수집 스크립트나 정의 문서 검사기의 겹침 처리를 함께 고친다
- converter 스킬이 규격 코드나 메시지를 바꾸면 수집 스크립트의 변환표를 함께 고친다. 변환표에 없는 코드나 메시지 꼴이 나오면 수집이 멈추므로 바뀐 것을 놓치지 않는다
  - 새 규격 코드는 규격 검사기가 매긴 단계(오류·경고·보류)에 따라 SPC-01~03 가운데 하나가 되고 코드는 외부 코드 칸에 적힌다. 규칙은 더하지 않는다. 변환표에 줄을 더하고 2절 외부 코드 칸의 코드 목록과 건수를 고친다
  - 변환표의 문제 설명과 조치 방안은 3절 조치 지침과 뜻이 맞아야 한다
- 이 문서를 고치면 수집 조건의 빌더 판본 해시가 바뀐다. 고치기 전에 수집한 검증 리포트는 판정 스크립트가 멈추므로 다시 수집한다
