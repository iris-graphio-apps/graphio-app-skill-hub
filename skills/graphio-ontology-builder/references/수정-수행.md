# 수정 수행

구조 판정의 지적을 읽고 정의 문서를 고치는 절차다. 판정이 확정 불가일 때 주로 부르고, 확정 가능이어도 "Warning도 고쳐"로 부를 수 있다. 스킬이 고칠 수 있는 지적은 다음 차수 정의 문서 초안에 고치고, 사람이 정할 지적은 묻고, 입력 문서를 바꿔야 풀리는 지적은 알린다. 고친 뒤에는 검증만 모드를 이어 수행해 새 판정을 낸다. 검증만 모드는 ①~⑧을 다시 하지 않고 고친 정의 문서로 검사와 판정만 다시 하는 단계이며, 1차 설계의 ⑨와 다르다.

**절차를 이 문서 한 곳에만 둔다.** [`../SKILL.md`](../SKILL.md)의 `--fix` 문단은 이 문서를 가리키기만 한다. 고친 뒤의 검사와 판정은 [`검증-수행.md`](검증-수행.md) 5장(검증만 모드)을 그대로 따르고, 이 문서에 다시 적지 않는다.

명령과 경로를 적는 꼴은 [`검증-수행.md`](검증-수행.md) 첫머리와 같다.

---

## 1. 흐름

스킬은 생성 → 검증 → 수정 → 검증으로 돈다. 수정 단계는 판정을 보고 정의 문서를 고치는 단계다.

| 차례 | 하는 쪽 | 일 |
|---|---|---|
| 1 | 스킬(생성) | 설계 전체를 수행해 1차 산출물 네 문서를 냄. 확정 불가면 2차 정의 문서 초안을 둠 |
| 2a | 스킬(수정, `--fix`) | 1차 판정 지적을 세 갈래로 나눔. 스킬 수정과 답을 받은 결정 필요를 2차 초안에 고침. 남은 결정 필요·입력 변경 필요는 수정 요청서 1차에 남김 |
| 2b | 사용자(밖에서 수정) | 2차 초안을 직접 고치거나 CQ 문서를 고침. 2a와 함께 써도 됨 |
| 3 | 스킬(검증만 모드) | 2a에 이어서, 또는 `--verify`로 부르면 2차 정의 문서로 설계 리포트를 다시 맞추고 검사와 판정을 다시 수행함. 설계 리포트·검증 리포트·구조 판정 2차를 냄 |
| 4 | 사용자 | 2차 판정 6절(앞 판정 대조)과 수정 요청서로 풀린 것과 남은 것을 확인함. Error가 남으면 3차 초안으로 2a나 2b |

- 한 번 부르면 수정 한 번과 검증 한 번을 하고 결과를 보고한다. 새 판정이 다시 확정 불가여도 스스로 되풀이하지 않는다. 되풀이하면 사람이 한 차수의 판정과 수정 요청서를 보기 전에 다음 차수의 수정이 이어진다
- 사람이 초안을 직접 고치는 길(`--verify`)은 그대로 있다. 사람이 초안을 고쳐 둔 뒤 `--fix`로 부르면 스킬은 그 초안 위에서 고친다
- 스킬이 고치는 것은 다음 차수 정의 문서 초안뿐이다. CQ 문서·원천 구조 문서·참고 문서·가이드는 입력이라 고치지 않는다. 입력을 바꿔야 풀리는 지적은 알리기만 한다
- 검증만 모드의 예외 규칙(사람이 정한 구조를 고치거나 지우지 않음, [`검증-수행.md`](검증-수행.md) 5.1)은 검증만 모드에만 적용한다. 수정 단계는 3장의 갈래대로 정의 문서를 고치고 지운다

## 2. 부르는 법

```
/graphio-ontology-builder --fix outputs/인사관리-온톨로지-구조-판정.md
```

| 표기 | 지정 대상 | 주지 않으면 |
|---|---|---|
| `--fix` | 고칠 구조 판정 | 수정 단계가 아님 |

- 판정 경로 없이 `--fix`만 주거나 문장으로만 부르면 판정이 있는 가장 높은 차수의 판정을 쓴다. 찾는 폴더는 이번 대화에서 산출물을 낸 폴더이고, 그런 폴더가 없으면 `--out`으로 준 폴더다. 그 폴더에 설계 리포트가 한 벌(이름 앞부분 하나)만 있을 때 그 벌을 쓴다. 폴더를 모르거나 여러 벌이면 판정 경로를 묻는다
- 판정 경로를 주면 그 판정이 있는 폴더와 판정 파일 이름의 앞부분으로 찾는다. 파일을 고르고 차수를 가르는 법은 [`검증-수행.md`](검증-수행.md) 5.3과 같다
- 받는 판정은 판정이 있는 가장 높은 차수의 것뿐이다. 더 높은 차수의 판정이 있는 판정을 주면 멈추고 가장 높은 차수의 판정을 알린다. 옛 판정으로 고치면 이미 판정까지 있는 다음 차수 산출물을 덮어쓰게 된다
- 문장으로 불러도 받는다. "판정대로 고쳐 줘", "판정 Error 고쳐 줘", "수정 요청서에 답 적었어, 이어서 고쳐 줘"가 그렇다
- 기본은 판정 3.1의 Error만 고친다. "Warning도 고쳐"라고 하면 3.2의 Warning까지 고친다. 기본으로 부르면 Warning은 고치지도 묻지도 않고, 그 가운데 스킬 수정 갈래의 건수만 결과 보고에 알린다. 수정 요청서에 새로 물을 결정 필요·입력 변경 필요는 수정 범위 안에서만 센다. 기본 호출이면 판정 3.1에서 나온 것만 적고, 3.2의 Warning은 결정 필요든 입력 변경 필요든 올리지 않는다. 그 Warning은 판정 3.2에 그대로 남는다. 앞 요청서에서 답을 받은 행은 범위와 상관없이 옮긴다(5장)
- 판정 N차가 확정 가능이면(Error 0건) 초안 N+1차는 고칠 것이 1건 이상일 때만 만든다. 결정 17대로 확정 가능 판정에는 초안을 두지 않기 때문이다. 기본 호출은 고칠 Error가 없으므로 초안 없이 결과 보고로 끝난다(7장)
- 일반 설계의 표기 `--cq`·`--ref`·`--style`·`--format`도 함께 받는다. 주면 앞 차수에 적힌 경로 대신 그것을 쓴다
- `--out`은 판정을 찾는 폴더로만 쓴다. N+1차 산출물과 수정 요청서는 늘 판정 N차가 있는 폴더에 쓴다. 다른 폴더에 쓰면 다음 차수 자동 찾기가 짝을 찾지 못한다
- 받는 것과 멈추는 경우는 검증만 모드와 같다([`검증-수행.md`](검증-수행.md) 5.2·5.4). 다만 사용자가 주는 것은 정의 문서가 아니라 판정이고, 주지 않아도 된다. 판정 N차의 짝(정의 문서·설계 리포트·검증 리포트 N차)과 입력 문서는 스킬이 찾아 읽는다

## 3. 지적의 세 갈래

| 갈래 | 뜻 | 스킬이 하는 일 |
|---|---|---|
| 스킬 수정 | 정의 문서만 고치면 풀리고, 고칠 내용을 지금 입력 문서로 정할 수 있음 | 다음 차수 초안을 고침. 설계 규칙(①~⑧)과 참고 문서를 그대로 따름. 개념·관계를 새로 더하는 수정은 결정 필요를 묻는 자리에서 함께 보여 주고 확인받음(4장) |
| 결정 필요 | 정의 문서를 고치면 풀리지만, 어느 쪽으로 고칠지 입력 문서만으로 정할 수 없음 | 선택지를 보여 주고 물음. 답하면 스킬 수정처럼 고침. 답하지 못하면 수정 요청서에 남김 |
| 입력 변경 필요 | 정의 문서만으로는 풀리지 않음. CQ 문서·원천 구조 문서·참고 문서·가이드를 바꿔야 함 | 고치지 않음. 어느 입력을 어떻게 바꿔 다시 부를지 수정 요청서와 결과 보고에 적음 |

입력 변경 필요를 다시 부르는 법은 바꿀 입력에 따라 갈린다.

- CQ 문서만 바꾸면 `--verify <다음 차수 초안 경로>`로 다시 부른다. 초안이 없으면(확정 가능 판정) N차 정의 문서 경로를 준다. CQ를 더하거나 빼거나 문장·등급을 바꿔도 검증만 모드가 설계 리포트를 바뀐 CQ로 다시 맞춘다([`검증-수행.md`](검증-수행.md) 5.4·5.7)
- 원천 구조 문서·참고 문서·가이드를 바꾸면 재생성(설계 전체를 다시 수행)을 안내한다. 설계 리포트 3·6·11절의 판단이 그 문서들에 매여 있는데 검증만 모드는 그 판단을 새로 하지 않는다
- 재생성은 새 폴더(`--out`)로 부르라고 적는다. 같은 폴더로 부르면 1차 네 문서를 덮어쓰고, 남은 2차 이후 파일이 앞 차수 자동 찾기에 걸린다

**규칙마다 갈래를 아래처럼 정한다.** 표에 적은 조건 밖에서는 갈래를 바꾸지 않는다. 같은 판정을 두 번 고쳐도 갈래가 실행마다 달라지지 않게 하기 위함이다. 조치 지침은 [`검사-규칙.md`](검사-규칙.md) 3절에 있다.

| 규칙 | 갈래 | 조건과 비고 |
|---|---|---|
| DOC-01~07, DOC-11 | 스킬 수정 | 조치 지침대로 정의 문서를 고침 |
| DOC-08 | 결정 필요 | 데이터 구조 이름을 원천 이름으로 고칠지, 아직 없는 구조로 두고 설명에 그 표기를 넣을지. 뒤를 고르면 검증만 모드가 설계 리포트 7.1절에 올림 |
| CNV-01, SPC-01 | 스킬 수정 | 변환 스크립트·규격 검사기가 가리킨 요소를 서식 가이드대로 고침 |
| SPC-02 | 결정 필요 | 조치 지침이 의도 확인임. 의도한 것이라는 답이면 정의 문서를 고치지 않음. 답은 수정 요청서 3절에 남기고(5장), 검증을 수행하면 검증 리포트 4.1절 `※ No.2 Warning 확인:` 주석에도 `(사용자 답)` 표시를 붙여 적음. 1차 ⑨에서 스킬이 스스로 적은 주석(표시 없음)이 있어도 결정 필요임(4장) |
| GDE-01·02 | 스킬 수정 | 가이드 항목이 가리킨 요소를 가이드대로 고침 |
| CQS-01·02 | 결정 필요 | 선택지는 늘 둘: 구조를 더함(답하면 스킬 수정으로 고침. 더할 구조를 선택지에 함께 보여 줌), 필수 CQ에서 뺌(CQ 문서를 사람이 고쳐야 하므로 입력 변경 필요로 넘김). 스타일 가이드가 막아 설계 리포트 11절에 적힌 CQ는 입력 변경 필요 |
| CQS-03·04 | 스킬 수정 | 답할 경로를 더함. 스타일 가이드가 막아 설계 리포트 11절에 적힌 CQ는 입력 변경 필요 |
| CQS-05 | 스킬 수정 | 쓰는 CQ가 없는 요소를 지움. 조인 속성처럼 규격이 요구하는 속성은 지우지 않음. 사람이 더한 요소면 결정 필요(일부러 더했을 수 있음) |
| CQS-06 | 입력 변경 필요 | CQ 문서 작성자가 필수 등급을 밝혀야 함 |
| MAP-01 | 스킬 수정 | 원천 구조 문서에서 1차 매핑과 같은 판별 차례([`검증-리포트-서식.md`](검증-리포트-서식.md) 6절)로 뜻이 같은 컬럼을 찾아, 지금 매핑 블록의 데이터 구조 안에서 하나로 정해지면 그 컬럼으로 바꿈. 찾지 못하면 매핑을 비우고, 필요한 컬럼은 검증만 모드가 설계 리포트 7.2절에 올림. 뜻이 같은 컬럼이 둘 이상이거나 다른 데이터 구조에만 있으면 결정 필요(매핑 블록이나 조인을 새로 정해야 함). 사람이 이은 매핑이면 결정 필요 |
| INP-01 | 입력 변경 필요 | 입력 문서 작성자가 어느 쪽을 따를지 정해야 함. 정의 문서를 고쳐도 설계 리포트 11절이 그대로라 판정에 남음 |
| DOC-09·10, SPC-03, MAP-02~04 | 해당 없음 | Info라 판정 3절에 오르지 않음 |

- 사람이 더한 요소는 1차부터 N차까지 설계 리포트 2절의 `※ 외부 수정 n:` 줄과 N차 설계 리포트 근거 칸의 '외부 수정(…)' 표기로 가린다. 사람이 이은 매핑은 같은 줄 가운데 매핑 › 속성의 '더함'·'컬럼 바뀜' 줄로 가린다([`검증-수행.md`](검증-수행.md) 5.6 차례 3). 스킬이 수정 단계에서 더하거나 바꾼 것은 사람이 한 것이 아니다
- 스타일 가이드가 막은 CQ인지는 N차 설계 리포트 11절에서 가린다
- MAP-01에서 뜻이 같은 컬럼을 먼저 찾는 까닭: 맞는 컬럼이 원천에 있는데 매핑을 비우면 그 값이 정의 문서에서 빠지고, 이미 있는 컬럼이 설계 리포트 7.2절에 '더할 컬럼'으로 오른다. 검증만 모드에는 이 손실을 잡는 규칙이 없다
- MAP-01을 맞는 컬럼으로 바꿔도 판정 문서의 조치 방안 칸에는 검사 규칙의 조치 지침('해당 매핑을 지우고 필요한 컬럼을 설계 리포트 7.2절(기존 메타타입 추가 컬럼)에 올림')이 그대로 나오고, 실제로 한 일은 기록 줄과 수정 요청서 5절에 남는다
- 구조를 더할 때도 일반 설계의 원칙을 따른다. CQ가 요구하면 원천에 값이 없어도 만들고, 없는 구조와 컬럼은 검증만 모드가 설계 리포트 7절에 올린다([`../SKILL.md`](../SKILL.md) ⑤·⑦)
- 판정 N차를 만든 뒤 CQ 문서가 바뀌었는지는 CQ 문서 해시를 N차 검증 리포트 수집 조건 줄과 맞대 가린다. CQ 문서가 여럿이거나 수집 조건 줄에 CQ 해시가 없으면(0.2.0 산출물) 맞대지 않고 CQ 문서를 늘 다시 읽어 판정 N차의 CQS 지적과 맞댄다([`검증-수행.md`](검증-수행.md) 5.4). 바뀌었으면 CQS 지적을 바뀐 CQ 문서로 다시 본다. 빠진 CQ의 지적은 고치지 않고 결과 보고에 적는다. 필수 여부가 바뀐 CQ는 바뀐 필수 여부로 갈래를 정한다. 이어지는 검증이 바뀐 CQ로 설계 리포트를 다시 맞춘다

## 4. 결정 필요를 받는 법

**고치기 전에 한 번에 묻는다.** 수정을 시작할 때 결정 필요 지적과 개념·관계를 새로 더하는 스킬 수정을 모아 묻고, 답을 모두 받은 뒤 고친다.

- 묻기 전에 앞 수정 요청서 3절의 답(5장 '답은 이렇게 읽는다')과 N차 검증 리포트 4.1절의 `※ No.2 Warning 확인:` 주석을 읽는다. 이미 답이 있는 지적은 다시 묻지 않는다. 주석의 4.2절 No.로 검증 리포트 행을 찾아 지적 식별자로 판정 N차의 지적에 맞댄다
- 주석 가운데 줄 끝에 `(사용자 답)` 표시가 붙은 것만 묻지 않는 근거로 쓴다. 사용자가 의도한 것으로 답한 주석이기 때문이다. 그 SPC-02는 '의도한 것' 답을 받은 것과 같게 다룬다(5장). 표시가 없는 주석은 1차 ⑨에서 스킬이 스스로 판단해 적은 것이라, 그 SPC-02는 다른 결정 필요처럼 묻는다
- `AskUserQuestion`으로 묻는다. 한 번에 네 개까지 물을 수 있으므로 넘으면 네 개씩 이어서 묻는다. 그 도구가 없으면 같은 내용을 문장으로 묻는다
- 묻기 전에 무엇을 왜 묻는지와 선택지마다 무엇이 달라지는지를 먼저 설명한다. 판정 지적 번호·규칙·위치·문제 설명을 함께 보여 준다
- 선택지마다 '답을 모름(나중에)'을 둔다. 이 답을 고른 물음과 대답하지 않은 물음은 수정 요청서 3절에 남긴다
- 정의 문서를 바꾸지 않는 답(SPC-02 '의도한 것', 구조 추가 '더하지 않음', 사람이 더한 요소·이은 매핑을 '그대로 둠')도 수정 요청서 3절에 답과 함께 남긴다. 파일에 남겨 두어야 다음 호출이 같은 것을 다시 묻지 않는다(5장)
- CQS-01·02의 선택지는 '구조를 더함'·'필수 CQ에서 뺌'·'답을 모름(나중에)'이다. '구조를 더함'에는 더할 구조를 함께 적는다. 이 답이 곧 더할 구조의 확인이다. '필수 CQ에서 뺌'을 고르면 입력 변경 필요로 옮겨 수정 요청서 4절에 적는다
- 개념·관계를 새로 더하는 스킬 수정은 ⑥ 설계안 확인과 같은 뜻으로 확인받는다. 더할 개념(이름, 근거 CQ)과 관계(출발 → 도착, 조인 속성, 근거 CQ)를 보여 주고 '이대로 더함'·'더하지 않음'·'답을 모름(나중에)'을 둔다. '더하지 않음'이면 고치지 않고 수정 요청서 3절에 답과 함께 남기며 결과 보고에도 적는다
- 개념·관계를 더하지 않는 스킬 수정(서식·설명·매핑을 고치거나 쓰는 CQ가 없는 요소를 지우는 것)은 묻지 않는다

묻기 전에 보여 주는 설명은 이런 꼴이다. "Warning도 고쳐"로 부른 경우라 Warning인 DOC-08도 묻는다. 기본 호출이면 Warning-2는 묻지 않는다.

```
판정 지적 가운데 정해 주셔야 고칠 수 있는 것이 2건 있습니다.
답을 모두 받은 뒤 2차 초안을 고칩니다.

  1차 판정 Error-3   CQS-01   CQ-54   필수 CQ에 답할 경로가 없음
    1) 구조를 더함        개념 교육이수(CQ-54), 관계 교육이수 → 사원, 조인 사원번호(CQ-54)
                         원천에 이수 기록이 없으면 설계 리포트 7절에 만들 구조로 오름
    2) 필수 CQ에서 뺌      CQ 문서를 고쳐야 함. 수정 요청서에 적고 스킬은 고치지 않음
    3) 답을 모름(나중에)   수정 요청서에 남김

  1차 판정 Warning-2   DOC-08   데이터 구조 'hr.TB_교육수강'   원천 구조 문서에 없는 이름
    1) 원천 이름으로 고침   원천의 'hr.TB_교육수강내역'으로 바꾸고 매핑 제목도 함께 바꿈
    2) 새로 만들 구조로 둠  설명에 대상 환경에 아직 없다는 표기를 넣음. 설계 리포트 7.1절에 오름
    3) 답을 모름(나중에)   수정 요청서에 남김
```

**'확인 없이 이어 가라'고 했으면 ⑥과 같게 한다.** 개념·관계를 더하는 스킬 수정은 더할 구조를 보여 주고 고친다. 결정 필요는 물을 수 없으므로 수정 요청서에 남긴다.

**사용자에게 물을 수 없는 환경**(평가 실행처럼 묻지 말라는 지시를 받은 실행)에서는 결정 필요와 개념·관계를 더하는 스킬 수정을 모두 수정 요청서 3절에 남긴다. 나머지 스킬 수정은 고친다.

## 5. 수정 요청서

**답을 받지 못한 결정 필요, 입력 변경 필요, 정의 문서를 바꾸지 않는 답 가운데 하나라도 있으면 만든다.** 새로 물을 결정 필요·입력 변경 필요는 수정 범위(2장) 안에서만 센다. 앞 요청서에서 답을 받은 행은 범위와 상관없이 옮기고 센다. 셋 다 없으면 새로 만들지 않는다. 다만 같은 이름의 요청서가 이미 있으면 남은 것이 없어도 이번 결과로 다시 쓴다(아래). 확인받지 못한 구조 추가(4장)도 결정 필요로 센다.

- 파일 이름은 `<이름>-온톨로지-수정-요청-N차.md`다. N은 이 요청서를 만들 때 읽은 판정의 차수다. 1차 판정을 읽었어도 `-1차`를 붙인다. 짝이 되는 판정의 차수를 이름에서 바로 읽기 위함이다. 폴더는 판정과 같은 폴더다
- 3절에는 답을 받지 못한 결정 필요와, 정의 문서를 바꾸지 않는 답을 받은 결정 필요가 함께 있다. 뒤의 행은 답 칸에 그 답이 적혀 있다. 2절 '결정 필요'는 둘을 합한 3절 행 수 n이고, 답 칸이 채워진 행이 있으면 그 수 m을 붙여 `n건(답 있음 m건)`으로 적는다. 2절만 읽고도 아직 정할 것이 몇 건인지 알게 하기 위함이다
- 요청서 N차의 5절은 늘 정의 문서 초안 N+1차에 N+1차로 적은 기록 줄과 1:1이다. 예외는 검증이 종료 코드 2로 멈춘 호출 하나다. 그 호출은 요청서를 쓰지 않아 앞 요청서가 다음 호출까지 남는다(7장)
- 같은 이름의 요청서가 이미 있으면(고친 것 없이 끝난 앞 호출이 남긴 요청서) 남은 것이 없어도 이번 결과로 다시 쓴다. 지우지 않는다. 그대로 두면 이미 고친 항목이 3절에 답할 일로 남고, 5절이 초안의 기록 줄과 맞지 않는다. 앞 요청서의 답은 그 전에 읽어 반영했다(7장 차례 4)
- 다시 쓰면 앞 요청서에 사용자가 적은 답은 이렇게 남는다. 그 답대로 고친 항목은 5절과 기록 줄의 고친 내용이 '사용자 답에 따라'로 시작하고(6장), '필수 CQ에서 뺌'은 4절 행으로, 정의 문서를 바꾸지 않는 답('의도한 것'·'더하지 않음'·'그대로 둠')은 3절 행의 답 칸으로 남는다. SPC-02의 '의도한 것'은 검증을 수행했으면 검증 리포트 `※ No.2 Warning 확인:` 주석에도 `(사용자 답)` 표시와 함께 남는다
- 앞 요청서 3절에서 정의 문서를 바꾸지 않는 답을 받은 행은, 그 지적이 판정 N차(검증을 수행했으면 N+1차)에 남아 있으면 수정 범위와 상관없이 새 요청서 3절에 답과 함께 옮긴다. 판정 지적 번호는 새 요청서의 대상 판정 번호로 고친다. 차수가 바뀌거나 "Warning도 고쳐" 호출 뒤에 기본 호출이 끼어도 같은 것을 다시 묻지 않기 위함이다
- 뼈대는 [`../assets/수정-요청서-뼈대.md`](../assets/수정-요청서-뼈대.md)에 있다. 그 파일을 복사해 자리표시만 채운다. 문서의 꼴과 문체는 [`리포트-작성-규칙.md`](리포트-작성-규칙.md)를 따른다
- 판정과 겹치는 내용(위치·문제)을 줄이지 않는다. 받는 사람이 요청서만 펴고도 답할 수 있어야 한다
- 검증을 수행했으면 남은 항목을 새 판정(N+1차)의 지적과 지적 식별자([`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장)로 맞대 본다. 짝이 없는 항목(이번 수정으로 함께 풀린 지적)은 요청서에 적지 않고 결과 보고에 적는다

**칸마다 이렇게 적는다.**

| 절 | 칸 | 적을 것 |
|---|---|---|
| 문서 정보 표 | 차수 | 읽은 판정의 차수. 파일 이름의 차수와 같음 |
| 문서 정보 표 | 대상 판정 | 읽은 판정 경로 |
| 문서 정보 표 | 정의 문서 초안 | 다음 차수 정의 문서 경로. 고친 것이 없어도 초안이 있으면 그 경로. 확정 가능 판정이라 초안을 만들지 않았으면 '해당 없음' |
| 2절 | 수정 범위 | 기본은 `Error`. "Warning도 고쳐"로 불렀으면 `Error·Warning` |
| 2절 | 스킬 수정 · 결정 필요 · 입력 변경 필요 | 5절·3절·4절 표의 행 수를 `n건`으로 적음. 0건이면 '해당 없음'. 결정 필요는 답 칸이 채워진 3절 행이 있으면 `n건(답 있음 m건)` |
| 3·4·5절 | 판정 지적 번호 | 읽은 판정의 지적 번호(Error-n·Warning-n). 사람이 판정을 펴 볼 때 쓰는 번호 |
| 3·4절 | 규칙 · 위치 | 읽은 판정 요약표의 규칙 번호와 위치를 그대로 옮김. 스킬이 답을 지적에 맞댈 때 쓰는 값 |
| 3절 | 정할 것 | 무엇을 정해야 하는지 한 문장 |
| 3절 | 선택지 | `1) …`, `2) …`처럼 번호를 붙여 한 칸에 이어 적음. '답을 모름'은 넣지 않음(답 칸을 비우면 됨). 구조를 더하는 선택지에는 더할 개념·관계를 적음 |
| 3절 | 선택지별 영향 | 선택지 번호마다 정의 문서와 판정에서 무엇이 달라지는지 |
| 3절 | 답 | 답을 받지 못했으면 비워 둠. 사람이 선택지 번호나 짧은 글로 채움. 정의 문서를 바꾸지 않는 답을 받았으면 스킬이 그 선택지를 '2) 의도한 것'처럼 번호와 이름으로 적음 |
| 4절 | 바꿀 입력 | CQ 문서, 원천 구조 문서, 참고 문서(문서 이름), 스타일 가이드, 서식 가이드 가운데 무엇인지. 작성자가 어느 쪽을 고칠지 정해야 하면 둘 다 |
| 4절 | 바꿀 내용 | 무엇을 어떻게 바꾸면 이 지적이 풀리는지 |
| 4절 | 바꾼 뒤 부르는 법 | CQ 문서만 바꾸면 `--verify <정의 문서 초안 경로>`로 경로까지 적음(초안이 없으면 N차 정의 문서 경로). 그 밖의 입력을 바꾸면 재생성. 바꿀 입력이 둘이면 입력마다 적음 |
| 5절 | 위치 · 고친 내용 | 정의 문서 초안의 `## 스킬 수정 기록`에 이번 차수로 적은 줄의 요소와 고친 내용을 글자 그대로 옮김(6장). 행은 기록 줄과 1:1 |

- 3·4·5절 표가 0건이면 절 첫머리 설명도 표도 없이 '해당 없음' 한 줄만 둔다
- 6절(후속 조치)에는 아래 줄 가운데 조건에 맞는 것만 이 차례로 둔다. 맞는 줄이 하나도 없으면 `- 해당 없음` 한 줄을 둔다. "Warning도 고쳐"로 불러 SPC-02에 '의도한 것'만 답해 고친 것이 없는 호출이 그렇다

| 조건 | 6절에 두는 줄 |
|---|---|
| 3절에 답 칸이 빈 행이 있고, 그 가운데 판정 지적 번호가 `Warning-n`인 행은 없음 | 3절 '답' 칸 기재 후 `--fix`로 수정 재수행 필요 |
| 3절에 판정 지적 번호가 `Warning-n`이고 답 칸이 빈 행이 하나라도 있음 | 3절 '답' 칸 기재 후 `--fix`에 "Warning도 고쳐"를 붙여 수정 재수행 필요 |
| 4절에 행이 있음 | 4절 입력 문서 변경 후 '바꾼 뒤 부르는 법' 칸대로 재수행 필요 |
| 검증을 수행함 | 고친 결과는 (다음 차수 구조 판정 경로) 6절(앞 판정 대조)에서 확인 필요 |
| 수정 범위가 Error이고 Warning 가운데 스킬 수정 갈래가 있음 | Warning 가운데 스킬 수정 대상 n건은 Warning까지 수정 요청 시 처리함 |

- 표의 첫 두 행은 둘 가운데 하나만 둔다. 답 칸이 빈 Warning 행이 있으면 "Warning도 고쳐"를 붙이라고 적는 까닭: 이어진 판정이 확정 가능이고 남은 결정 필요가 Warning이면, 기본 `--fix`는 고칠 Error가 없어 초안 없이 끝나고 적은 답이 반영되지 않는다(2장). 답이 채워진 Warning 행(앞 요청서에서 옮긴 '의도한 것' 같은 답)은 이미 반영된 답이라 다음 호출이 할 일이 없으므로 따지지 않는다

**답은 이렇게 읽는다.**

- 판정 N차에 `--fix`를 부르면 수정 요청서 N차가 있으면 그것을, 없으면 N-1차를 읽는다. 요청서 N차는 앞 호출이 고친 것 없이 끝나 검증을 건너뛰었을 때 생긴다. 그보다 앞 차수의 요청서는 읽지 않는다. 그 사이에 판정이 여러 번 바뀌어 답이 지금 지적과 맞지 않을 수 있다
- 3절 '답' 칸만 읽는다. 사람이 다른 칸을 고쳤어도 읽지 않는다
- 답을 지적에 맞댈 때 판정 지적 번호는 쓰지 않는다. 번호는 판정마다 새로 매겨진다. 요청서의 규칙과 위치로 지적 식별자를 만들어 판정 N차의 지적에 맞댄다. 식별자에 외부 코드가 드는 규칙(SPC-02)은 요청서의 대상 판정에서 그 지적 번호의 외부 코드를 가져와 더한다
- 짝이 없으면(이미 풀린 지적) 답을 쓰지 않고 결과 보고에 적는다
- 정의 문서를 바꾸지 않는 답은 고치지 않고 다시 묻지 않는다. 그 지적이 남아 있으면 새 요청서 3절에 답과 함께 옮긴다
- 답을 읽을 수 없으면(선택지에 없는 번호, 두 뜻으로 읽히는 글) 쓰지 않고 다시 묻는다. 답 칸이 빈 항목도 다시 묻는다
- '구조를 더함'으로 답했으면 그 행의 선택지 칸에 적은 구조를 더한다. 지금 초안에 이미 있는 것은 다시 더하지 않는다

## 6. 스킬 수정 기록

**스킬이 고친 목록은 두 곳에 남긴다.** 정의 문서 초안 맨 끝의 `## 스킬 수정 기록` 절과, 수정 요청서를 만들면 그 5절이다. 초안에 남기는 까닭은 둘이다. 검증만 모드가 이 절로 스킬이 고친 것과 사람이 고친 것을 가른다([`검증-수행.md`](검증-수행.md) 5.6). 검증이 멈춰 다시 부를 때도 기록이 파일에 있으므로 같은 수정을 다시 얹지 않는다.

- 네 절이 아닌 `##` 절이라 변환할 때 읽히지 않고 변환 결과가 바뀌지 않는다. 수집 조건의 정의 문서 해시에는 들어간다
- 절은 정의 문서 맨 끝에 둔다. 이미 있으면 그 절 끝에 줄을 더한다. 이번에 고친 것이 없으면 절을 새로 만들지 않는다
- `###` 제목과 표를 쓰지 않고 한 줄에 한 건을 적는다
- 줄의 꼴은 `- N차 · 규칙 · 요소 · 판정 지적 번호 · 고친 내용`이다. 칸은 ' · '(앞뒤를 띄운 가운뎃점)으로 나눈다

| 칸 | 적을 것 |
|---|---|
| N차 | 이 기록을 적은 초안의 차수. 2차 초안이면 `2차` |
| 규칙 | 규칙 번호 |
| 요소 | 위치 꼴([`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장)에서 줄 번호를 뺀 것. 고치면 줄이 밀리므로 줄 번호를 적지 않음. 요소를 이름으로 가리킬 수 없는 '정의 문서 n줄' 꼴만 읽은 판정의 위치를 그대로 둠(줄 번호를 빼면 가리킬 것이 남지 않음). 그 줄 번호는 판정 N차가 가리킨 N차 정의 문서의 줄이고 초안의 줄이 아님 |
| 판정 지적 번호 | 고칠 때 읽은 판정의 지적 번호(Error-n·Warning-n) |
| 고친 내용 | 무엇을 어떻게 고쳤는지 말로 적음 |

- 지적 하나와 요소 하나가 한 줄이다. 한 지적을 풀려고 요소 여럿을 바꿨으면 요소마다 한 줄을 적고 같은 지적 번호를 쓴다. 지웠으면 지운 요소를 적는다
- 결정 필요를 사용자 답대로 고쳤으면 고친 내용을 '사용자 답에 따라'로 시작한다. 그 자리에서 받은 답이든 요청서 답이든 같다. 요청서를 다시 쓰거나 판정이 바뀌어도 사람이 정한 수정인지 이 줄에서 가린다
- 고친 내용에 고치기 전 문구를 옮기지 않는다. 정의 문서 검사기는 DOC-02(조사 괄호 잔존)를 문서의 모든 줄에서 찾는다. 옛 문구 `사원이(가)`를 옮기면 기록 줄이 다시 Error로 잡힌다. '조사 괄호를 받침에 맞게 고침'처럼 적는다. 이름을 바꿨으면 앞 이름만 '앞 이름 …'으로, 매핑 컬럼을 바꿨으면 앞 컬럼만 '앞 컬럼 …'으로 적는다
- 다음 차수 초안은 이번 차수 정의 문서를 바이트 그대로 복사하므로 기록 절도 그대로 옮겨진다. 앞 차수 표시가 붙은 줄은 이력으로 남는다. 검증만 모드는 이번 차수 표시가 붙은 줄만 읽으므로 섞이지 않는다

```markdown
## 스킬 수정 기록

- 2차 · DOC-02 · 개념 '휴가신청' · Error-1 · 설명의 조사 괄호를 받침에 맞게 고침
- 2차 · MAP-01 · 매핑 '휴가신청 ← hr.TB_휴가신청내역' › 속성 '휴가 종류' · Error-2 · 뜻이 같은 원천 컬럼이 없어 뜻이 다른 컬럼 매핑을 비움
- 2차 · MAP-01 · 매핑 '휴가신청 ← hr.TB_휴가신청내역' › 속성 '신청자 이름' · Error-4 · 뜻이 같은 원천 컬럼 '신청자명'으로 바꿈(앞 컬럼 '신청자번호')
- 2차 · CQS-01 · 개념 '교육이수' · Error-3 · 사용자 답에 따라 CQ-54에 답할 개념을 더함
- 2차 · CQS-01 · 관계 '교육이수의 사원'(교육이수 → 사원) · Error-3 · 사용자 답에 따라 CQ-54에 답할 관계를 더함
```

## 7. 처리 흐름

| 차례 | 할 일 | 나오는 것 |
|---|---|---|
| 1 | 판정 N차(가장 높은 차수)와 그 짝(정의 문서·설계 리포트·검증 리포트 N차)을 찾는다. 입력 문서를 모으고 멈춤 조건을 확인한다([`검증-수행.md`](검증-수행.md) 5.2·5.4). 수정 요청서 N차나 N-1차가 있으면 읽는다(5장) | 입력 목록 |
| 2 | 다음 차수 초안(정의 문서 N+1차)을 확인한다. 있으면 그 파일을 작업본으로 쓴다. 없으면 N차 정의 문서를 바이트 그대로 복사해 만든다. 다만 판정 N차가 확정 가능이면 차례 5에서 고칠 것이 1건 이상일 때만 만든다 | 작업본 |
| 3 | 판정 3.1(기본) 또는 3.1·3.2("Warning도 고쳐")의 지적을 세 갈래로 나눈다(3장) | 갈래 목록 |
| 4 | 수정 요청서의 답과, N차 검증 리포트의 `※ No.2 Warning 확인:` 주석 가운데 `(사용자 답)` 표시가 붙은 것을 지적에 맞대 먼저 반영한다. 아직 답이 없는 결정 필요와 개념·관계를 더하는 스킬 수정을 한 번에 묻는다(4장) | 답 |
| 5 | 스킬 수정과 답을 받은 결정 필요를 작업본에 고친다. 설계 규칙과 참고 문서를 그대로 따른다. `## 스킬 수정 기록`에 줄을 더한다(6장) | 정의 문서 N+1차 |
| 6 | 작업본을 받은 정의 문서로 삼아 검증만 모드를 수행한다([`검증-수행.md`](검증-수행.md) 5.6). 작업본이 N차 정의 문서와 바이트까지 같으면(고친 것이 없음) 검증을 건너뛴다. 초안을 만들지 않았으면 검증도 하지 않는다 | 설계 리포트·검증 리포트·구조 판정 N+1차 |
| 7 | 답을 받지 못한 결정 필요, 입력 변경 필요, 정의 문서를 바꾸지 않는 답 가운데 하나라도 있으면 수정 요청서 N차를 쓴다. 요청서 N차가 이미 있으면 남은 것이 없어도 다시 쓴다(5장) | 수정 요청서 N차 |
| 8 | 결과를 보고한다(8장) | 사용자 알림 |

- 차례 2의 초안은 대개 N차 판정 때 만들어 둔 사본이다. 사람이 고쳐 두었거나 멈춘 수정이 고친 초안이어도 덮어쓰지 않고 그 위에서 고친다. 사람이 고친 요소는 검증만 모드가 외부 수정으로 적는다
- 판정 N차가 확정 가능이면 초안 N+1차가 없는 것이 정상이다(결정 17). 차례 5에서 고칠 것이 생겼을 때만 N차 정의 문서를 복사해 만든다. 고칠 것이 없으면 초안도 검증도 없이 결과 보고로 끝낸다. 남길 답이 있으면 수정 요청서는 5장대로 쓰고 '정의 문서 초안' 칸은 '해당 없음'이다
- 차례 3에서 작업본의 기록 절에 N+1차 줄로 이미 적힌 지적(멈춘 수정이 고친 것)은 다시 고치지 않는다. 그 기록 줄의 판정 지적 번호는 지금 읽는 판정 N차의 번호이므로 번호로 맞댄다
- 차례 5에서 요소 하나를 고치면 그 요소를 가리키는 다른 줄도 함께 맞춘다. 이름을 바꾼 데이터 구조의 매핑 제목, 지운 개념의 관계와 매핑, 이름을 바꾼 개념을 가리키는 경고문, 매핑 컬럼을 바꾸거나 매핑을 비운 속성의 설명에서 옛 컬럼을 가리키던 줄(`[SQL]` 같은 것)이 그렇다. 함께 고친 요소도 기록 줄을 적는다
- 차례 5에서 확인되지 않은 값은 지어내지 않고 '확인 필요'로 적는다. 규모 표는 고치지 않는다. 검증만 모드가 `--stats`로 갱신한다
- 차례 6의 검증만 모드는 정의 문서를 더 고치지 않는다. 수정은 차례 5에서 끝났다
- 차례 6에서 검증을 건너뛰는 것은 같은 정의 문서로 N+1차 판정을 만들면 N차와 같은 판정이 한 벌 더 생기기 때문이다. 건너뛰어도 초안은 만들어 둔 그대로 둔다. 사람이 초안을 고쳐 두었거나 멈춘 수정이 고친 것이 있으면 바이트가 달라 검증을 수행한다
- 차례 6에서 수집·판정 스크립트가 종료 코드 2로 멈추면 [`검증-수행.md`](검증-수행.md) 5.4대로 알리고 멈춘다. 수정 요청서는 쓰지 않는다. 앞 호출이 남긴 요청서 N차가 있으면 그대로 남고, 다시 불러 검증까지 마치면 5장대로 다시 쓴다. 고친 것은 작업본의 기록 절에 남아 있어 다시 부르면 그 위에서 이어 간다

## 8. 결과 보고

사용자에게 아래를 이 차례로 알린다. 검증을 수행했으면 [`검증-수행.md`](검증-수행.md) 5.9의 항목을 함께 알리고, 겹치는 것은 한 번만 적는다.

1. 경고: 판정 뒤 CQ 문서가 바뀜, 사람이 고쳐 둔 초안 위에서 고침, 고친 것이 없어 검증을 건너뜀, 확정 가능 판정이라 초안을 만들지 않음, 검증이 멈춤(까닭). 해당하는 것만
2. 고친 것: 스킬 수정과 답을 받은 결정 필요. 판정 지적 번호, 규칙, 요소, 고친 내용. 이미 풀린 지적이라 쓰지 않은 요청서 답도 함께
3. 남은 것: 수정 범위 안에서 답을 받지 못한 결정 필요와 입력 변경 필요, 정의 문서를 바꾸지 않은 답('의도한 것'·'더하지 않음'·'그대로 둠'. 앞 요청서에서 옮긴 답은 범위와 상관없음), 빠진 CQ라 고치지 않은 지적. 수정 요청서 경로
4. 기본(Error만)으로 불렀으면 Warning 가운데 스킬 수정 갈래의 건수와 "Warning도 고쳐"로 부르면 고친다는 안내
5. 새 판정: 확정 가능 또는 확정 불가, Error·Warning 건수, 앞 판정 대조 건수(해소·유지·신규·기준 변경·확인 불가)
6. CQ 문서가 바뀐 차수면 바뀐 CQ. 뺀 CQ가 있으면 그 CQ의 앞 판정 지적이 대조에서 해소로 셈해졌다는 것. 구조를 고쳐 풀린 것이 아니다([`구조-판정-서식.md`](구조-판정-서식.md) '알려진 한계')
7. 다음에 할 일: 수정 요청서 3절에 답을 적고 `--fix`(3절에 답 칸이 빈 Warning 행이 있으면 "Warning도 고쳐"를 붙임), 초안을 직접 고치고 `--verify <초안 경로>`, CQ 문서만 바꿨으면 `--verify <초안 경로>`(초안이 없으면 N차 정의 문서 경로), 원천 구조 문서·참고 문서·가이드를 바꿨으면 새 폴더로 재생성, 확정 가능이면 `graphio-ontology-converter`로 변환
