# 원천 대조

이 문서는 CQ 답 요소가 원천 문서에 근거를 갖는지 가리는 규칙을 다룬다. 정의 문서의 데이터 구조 이름이 원천 구조 문서에 있는지 대조하는 DOC-08(원천에 없는 데이터 구조 이름, `scripts/check_design_doc.py`)과는 대상이 다르다.

짝 스크립트 `scripts/source_match.py`는 설계 리포트 4.2절 원천 대조표의 대조 ①~③을 맡는다.

- ① 근거 위치 글자 대조: 판정 있음·형태 다름·경유 행의 근거 위치에 적힌 테이블·컬럼·연결 키 이름, 또는 비정형 문서 타입의 문서 이름이 원천 문서 글자에 있는지
- ② 없음 판정의 같은 이름 컬럼: 판정 없음 행의 답 요소와 같은 이름의 컬럼이 원천에 있는지
- ③ 처리와 정의 문서 요소 유무: 처리가 만듦이면 정의 문서에 요소가 있고 빼고 보고면 없는지

DOC-08(정의 문서의 데이터 구조 이름이 원천에 없음) 대조는 맡지 않는다. 그 규칙은 수집 스크립트(`scripts/collect_findings.py`)와 판정 스크립트(`scripts/judge_structure.py`)가 맡는다.

CQ 답 요소마다 원천 문서에 근거가 있는지 가리고, 없을 때 무엇을 보이고 어디에 적는지 정하는 절차다.

**규칙 원문을 이 문서 한 곳에만 둔다.** [`../SKILL.md`](../SKILL.md) ②-1·②-2·③·④·⑤·⑨, [`fix-procedure.md`](fix-procedure.md)(수정 단계), [`verification-procedure.md`](verification-procedure.md)(검증만 모드)는 이 문서를 가리키기만 한다. 단계마다 판정 규칙을 저마다 적으면 한쪽만 고쳐져 같은 답 요소가 단계마다 다르게 판정된다. 설계 중간에 새로 만든 요소(가운데 개념·마디 개념·조인 속성)도 같은 규칙으로 근거를 확인한다.

**판정·처리 규칙은 번호 붙은 표 행으로 적는다.** 사람이 확인하거나 스크립트가 맞댈 때 행 번호로 가리키기 위함이다.

## 1. 쓰는 자리

| No. | 자리 | 이 문서에서 쓰는 것 |
|---|---|---|
| 1 | ②-1 원천 대조 | 답 요소마다 2.3 판별 차례로 판정(있음·형태 다름·경유·없음·확인 필요)을 내고 설계 리포트 4.2절 원천 대조표에 적는다(7장) |
| 2 | ②-2 원천에 없는 항목 확인 | 판정이 있음이 아닌 항목을 3장의 선택지·기본값과 근거와 함께 보인다. 새 컬럼·새 테이블은 선택지에 두지 않는다 |
| 3 | ③ 개념 | 원천 대조표에 근거(테이블·코드 마스터·문서 종류·채택한 매핑 테이블)가 있어야 개념으로 둔다. 구조 꼴은 [`structure-patterns.md`](structure-patterns.md)에서 CQ 꼴과 원천 꼴이 둘 다 맞을 때만 고른다 |
| 4 | ④ 이름·속성 | 근거 컬럼·문서 항목이 있는 값만 속성으로 둔다. 같은 데이터 구조 안에 뜻이 같은 후보 컬럼이 둘 이상이면 2.3 판별 차례 2′를 따른다 |
| 5 | ⑤ 관계 | CQ가 요구하고 원천에 연결 키(또는 잇는 테이블)가 있을 때, 또는 ②-2·⑥에서 조인·매핑 테이블을 고른 경로만 만든다. 원천이 연결 없음으로 적은 경로는 만들지 않는다. 조인 속성은 연결 키 컬럼에 매핑될 때만 둔다 |
| 6 | ③~⑤의 새 요소, ⑦ 매핑, ⑨ 매핑 의미 검사 | 8장 No.1~3 |
| 7 | 수정 단계(`--fix`) | 구조를 더할 때는 원천 근거가 있을 때만 더한다(8장 No.4·6) |
| 8 | 검증만 모드(`--verify`) | 8장 No.5 |

- ②-2 멈춤에서 항목을 보이는 꼴, 답을 기다리는 법, 기본값을 쓰는 때는 [`design-report-review.md`](design-report-review.md)를 따른다. 이 문서는 무엇을 보이고 어디에 적는지만 정한다

## 2. 근거로 치는 원천과 판별 차례

### 2.1 근거로 인정하는 원천

| 원천 | 근거로 인정하는 것 | 근거로 인정하지 않는 것 |
|---|---|---|
| 정형 원천 문서 | 적힌 테이블·컬럼(뜻 설명 포함)·연결 키·'연결 없음'과 '값 없음' 진술·확정 가정 | API 명세에만 있고 적재 테이블에 없는 항목(적재 테이블만 매핑 대상) |
| 비정형 원천 문서 | 적힌 문서 종류·문서 안 항목·저장 경로와 파일명 규칙·건마다 있기도 없기도 한 조건 | 원문을 읽어 내기 어렵다고 적은 항목(조건 속성으로 만들지 않음, [`reading-input-documents.md`](reading-input-documents.md) 5장) |
| 용어 자료·업무 이해서·결정 사항 | 뜻을 가르는 데 씀(같은 말·다른 말) | 개념·속성이 있다는 근거 |
| CQ 문서 | 답 요소와 등급 | '출처' 칸(인터뷰 위치라 데이터 원천이 아님) |
| 채택한 매핑 테이블 | 유도 규칙이 원천 문서의 글자(결합 규칙·반복 구조·경로 규칙)에 기댈 때 | 이름이 비슷해서 짝지은 매핑 테이블 |

**원천에 있다고 볼 범위는 아래 네 갈래로 닫는다.**

| No. | 갈래 | 판정과 처리 |
|---|---|---|
| 1 | 모양만 다른 데이터(결합 값·한 칸 목록·파일 경로 안의 값) | 판정 '형태 다름'. 4장 꼴에 맞을 때만 매핑 테이블 후보로 보임 |
| 2 | 비정형 문서 타입 | 비정형 자료 목록에 문서 종류와 문서 안 항목이 적혀 있으면 근거로 인정함. 표본 품질 문제는 판정 '확인 필요'로 두고, 표본이 일부 건에만 있으면 그 범위를 조건으로 붙임(예: '첨부 확보 공고에 한함') |
| 3 | 있는지 모르는 값 | 판정 '확인 필요'. 기본값은 빼고 보고 |
| 4 | 문서 설명만 있는 개념(용어 자료·업무 이해서·결정 사항에만 나옴) | 근거로 인정하지 않음 |

### 2.2 요소 종류와 근거 꼴

- 요소 종류는 CQ가 그 값을 어떻게 쓰는지로 가른다. 조건으로 걸면 값, 답으로 내보내는 덩어리면 대상, 답이 두 대상을 거치면 둘을 잇는 값이다
- 근거 꼴은 원천 구조에서 개념을 뽑는 대응(테이블 → 개념, 외래 키 → 관계, 분류 코드 테이블 → 개념)을 거꾸로 쓴 것이다. 원천 목록에서 출발하지 않고 CQ 요소에서 출발해 원천의 근거 꼴을 찾는다

| No. | 요소 종류 | 찾는 근거 꼴 |
|---|---|---|
| 1 | 대상 | 대상 한 건이 한 행인 테이블(기본키 있음), 코드 마스터, 문서 한 건이 대상 한 건인 문서 종류 |
| 2 | 값 | 뜻이 같은 컬럼, 문서 안 항목 |
| 3 | 잇는 값 | 양쪽 테이블의 같은 연결 키, 두 식별자를 함께 가진 잇는 테이블, 문서 경로·파일명의 키 |
| 4 | 시점이 붙은 이어짐 | 시점 컬럼을 가진 이력 테이블, 변경 전후를 적은 문서 항목 |
| 5 | 순서 | 뒤 단계 테이블의 앞 단계 키, 순번 컬럼 |
| 6 | 계층 | 상위 식별자 컬럼, 층별 테이블. 같은 종류끼리의 상위 식별자는 속성으로만 둔다(GOS61106: 같은 개념끼리 잇는 관계 금지) |

- 구조 꼴 요소의 원천 요구는 이 표의 근거 꼴 이름으로 적는다([`structure-patterns.md`](structure-patterns.md) 3장 요소 표)

### 2.3 판별 차례

답 요소마다 위에서부터 짚어 처음 답이 나온 판정을 쓴다. 실행마다 같은 답 요소를 다르게 판정하지 않기 위함이다.

| 차례 | 확인 | 결과 |
|---|---|---|
| 1 | 원천 문서가 그 값·연결이 없다고 글자로 적었는지(연결 없음 표, 값이 없어 CQ를 낮춘 표) | 적었으면 **없음**. 단 원천 문서가 거쳐 갈 연결 키를 함께 적었으면 차례 4(경유)로 넘김 |
| 2 | 근거 꼴이 원천에 있고 뜻 판별 차례(결정 사항 → 용어 사전 → 컬럼 설명 → 컬럼 이름이 가리키는 업무 절차, [`verification-report-format.md`](verification-report-format.md) 6절)로 하나로 정해지는지 | 정해지면 **있음** |
| 2′ | 같은 데이터 구조 안에 뜻이 같은 후보 컬럼이 둘 이상인지 | **있음**. 원천이 정한 컬럼, 없으면 원천 문서에 먼저 적힌 컬럼을 잇고 설계 리포트 8절에 적음 |
| 3 | 값은 기존 데이터에 있으나 결합 값 안·한 칸 목록 안·파일 경로 안에 있어 그대로는 잇지 못하는지 | **형태 다름**(매핑 테이블 후보) |
| 4 | 직접 연결 키도 잇는 테이블도 없으나, 원천이 적은 연결 키를 업무 테이블 둘 이상 거쳐 이어 붙이면 닿는지, 또는 뜻이 같은 값이 연결 키로 닿는 다른 데이터 구조에만 있는지 | **경유**(조인 후보) |
| 5 | 원천 문서가 그 범위의 목록을 전부라고 밝혔는데(컬럼 목록 전수, 범위 절) 뜻이 같은 것이 없는지 | **없음** |
| 6 | 그 밖(전부라고 밝히지 않은 목록에 없음, 문서끼리 있다·없다가 갈림, 비정형 표본 품질 문제) | **확인 필요**. 무엇을 확인할지 적음 |

- 뜻이 다른 컬럼으로 대신하지 않는다. 이름이 비슷해도 뜻 판별 차례로 뜻이 다르면 그 컬럼은 근거가 아니다. 같은 갈래의 값(수량·시점·금액)이라도 무엇의 수량·시점인지가 다르면 대신하지 않는다
- 값 수준의 '확인 필요'(코드 저장값·단위·대표 컬럼)는 이 판정과 다르다. 그 값은 정의 문서에 '확인 필요'로 적고 설계 리포트 8절에 모은다(DOC-10('확인 필요' 표기) 건수 규칙 그대로)
- CQ 문서가 '답할 수 없다'고 밝힌 질문과 '구조에 넣지 않을 값'(판정·집계)은 원천 대조 대상이 아니다. 앞은 질문 목록 밖이라 판정하지 않고, 뒤는 질의가 계산한다

## 3. 판정값과 처리

| 판정 | 뜻 | 선택지 | 기본값 | 미응답 사유로 옮길 때 |
|---|---|---|---|---|
| 있음 | 원천에 근거가 정해짐 | 만듦 | 만듦(멈춤에 올리지 않음) | 해당 없음 |
| 형태 다름 | 데이터는 기존 테이블에 있으나 꼴이 달라 매핑 테이블이 있어야 이어짐 | 빼고 보고 / 매핑 테이블 | 빼고 보고 | 원천 선택 미채택 |
| 경유 | 실재 연결 키로 업무 테이블 둘 이상을 거쳐야 이어짐 | 빼고 보고 / 조인 | 빼고 보고 | 원천 선택 미채택 |
| 없음 | 원천 어디에도 없음 | 빼고 보고 / 매핑 테이블(기존 데이터만으로 잇는 매핑 테이블을 만들 수 있을 때만 후보로 보임) | 빼고 보고 | 원천 부재 |
| 확인 필요 | 있는지 가리지 못함 | 빼고 보고 | 빼고 보고 | 원천 확인 필요 |

- 조인 선택지는 원천 문서가 밝힌 연결 키로 경로의 모든 이음이 닿을 때만 보인다
- 사람에게 보이는 선택지는 빼고 보고·조인·매핑 테이블 셋 안에서만 고른다. 기본값은 판정과 관계없이 빼고 보고다
- 처리는 닫힌 목록이다: 만듦 · 빼고 보고 · 빼고 보고(후보 미채택) · 조인 · 매핑 테이블 · 연쇄 제외 · 규격 제약. 규격 제약은 판정이 있음이나 Graphio 서식이 담지 못하는 경우다(예: 같은 개념끼리 여러 단계 따라가야 답하는 계층 CQ는 GOS61106(같은 개념끼리 잇는 관계 금지)에 막힘)
- 판정 정정: 사람이 원천 위치를 짚으면 ②-1 판정을 2장 판별 차례로 다시 하고 '있음'이 될 때만 만든다. 원천에 없는 항목의 선택지 셋(빼고 보고·조인·매핑 테이블) 밖의 절차다
- 정정은 설계 리포트 4.2절 해당 행 판정 칸에 「있음(판정 정정: 확인 필요 → 있음)」으로 적고, 근거 위치 칸에 사람이 짚은 원천 위치를, 결정 No. 칸에 12절 행 번호를 적는다
- 12절에는 고른 값 「판정 정정」, 정한 쪽 「사람」 행을 남긴다
- 판정 칸 값은 괄호 앞 낱말로 가른다(`judge_structure.py`·`source_match.py`·`check_design_report.py`가 같은 규칙으로 읽음)
- '없음'은 2.3 판별 차례 1·5로 판정하고, '형태 다름'은 차례 3으로 판정한다. 값이 원천에 모양만 달리 있으면 '형태 다름'이고, 원천 어디에도 없으면 '없음'이다
- 미응답 사유는 판정과 처리를 함께 보고 가른다

| No. | 판정 | 처리 | 미응답 사유 |
|---|---|---|---|
| 1 | 없음 | 빼고 보고. 매핑 테이블 후보 없음 | 원천 부재 |
| 2 | 없음 | 빼고 보고(후보 미채택). 매핑 테이블 후보를 보였으나 고르지 않음 | 원천 선택 미채택 |
| 3 | 형태 다름·경유 | 빼고 보고 | 원천 선택 미채택 |
| 4 | 확인 필요 | 빼고 보고 | 원천 확인 필요 |
| 5 | (처리 값) | 규격 제약 | 규격 제약 |
| 6 | 있음 | (설계 누락만 허용) | 설계 누락. 설계 밖 사유면 '설계 누락 숨김'으로 멈춤 |

- 설계 리포트 4.2절 처리 칸에는 후보를 보였으나 고르지 않은 경우 「빼고 보고(후보 미채택)」로 적어 원천 부재와 가른다

## 4. 매핑 테이블 예외

### 4.1 정의와 판별 기준

매핑 테이블은 고객 시스템의 기존 테이블 값(또는 비정형 저장소의 경로·파일명)만으로 행을 만드는 테이블이다. 새 업무 사실을 담지 않고, 두 기존 구조를 잇거나 한 칸에 결합되거나 뭉친 식별 값을 나눠 CQ 경로를 잇는다. 두 모델을 고치지 않고 대응만 선언하는 연결용 구조를, 고객 시스템을 고칠 수 없는 처지에서 기존 데이터로 구현한 것이다.

| No. | 판별 | 기준 |
|---|---|---|
| 1 | 재료 | 모든 행과 값이 이미 적재된 기존 테이블(또는 4.2에서 인정한 저장소 경로·파일명)에서 나옴 |
| 2 | 결정적 규칙 | 재료에서 행을 만드는 규칙이 원천 문서의 글자(결합 규칙·반복 구조·경로 규칙)에 기대어 정해져 있음. 같은 재료면 같은 행이 나옴. 사람이 고르거나 손으로 채우는 단계 없음 |
| 3 | 내용 | 대응 유형 하나만 담음. 새 업무 사실(새로 입력할 값, 이력·기간·수량, 판정·집계 결과)을 담지 않음 |
| 4 | 채택 | ②-2·⑥에서 사람이 채택한 것만 정의 문서에 넣음 |

### 4.2 꼴

| No. | 꼴 | 뜻 | 예외 해당 |
|---|---|---|---|
| 1 | 식별자 대응표 | 결합 값을 나누거나 두 식별 체계를 짝지음 | 해당 |
| 2 | 목록 펼침표 | 한 칸에 뭉친 식별 값을 행으로 폄 | 해당 |
| 3 | 키 결합표 | 기존 키 둘을 맞대 짝을 미리 만듦(여러 테이블을 거치는 경로를 한 테이블로 줄임) | 해당. 조인으로 답이 나오면 기본 제안하지 않음 |
| 4 | 문서-식별자 대응표 | 비정형 파일의 경로·이름에서 정형 키를 읽어 문서와 행을 이음 | 해당 |
| 5 | 코드 모음표 | 여러 테이블에 흩어진 (코드, 이름) 짝을 모아 마스터를 만듦 | 고객 확인 뒤 |
| 6 | 역할 칸 펼침표 | 역할마다 칸이 따로 있는 것을 (대상, 역할, 인원) 행으로 폄 | 고객 확인 뒤 |

- 꼴은 근거 위치의 생김새로 가른다. 결합 값이면 식별자 대응표, 반복 구조면 목록 펼침표, 저장 경로면 문서-식별자 대응표다
- '고객 확인 뒤' 꼴은 고객 원천 담당이 그 재료로 만들어도 된다고 확인한 뒤에만 후보로 보인다

### 4.3 매핑 테이블이 아닌 것

| No. | 대상 | 까닭 | 처리 |
|---|---|---|---|
| 1 | 새 데이터 입력이 필요한 테이블(이력·기간·수량·판정 기록) | 더해도 데이터가 없음 | 빼고 보고. 풀 방법 '풀 수 없음' |
| 2 | 기존 테이블에 더하는 새 컬럼 | 같음 | 제안하지 않음 |
| 3 | 재료 일부가 원천 밖에 있는 테이블 | 빠진 재료를 밖에서 받아야 하므로 새 데이터와 같음 | 빼고 보고 |
| 4 | 적재되지 않은 API 항목을 담는 테이블 | 적재 테이블만 매핑 대상(2.1) | 빼고 보고 |
| 5 | 이름 유사도로 짝지은 매핑 테이블 | 값 대응을 확인하지 않은 짐작. 대체 매핑(MAP-01)과 같은 결함 | 만들지 않음 |
| 6 | 판정·집계 결과 테이블 | 판정은 질의가 함(스타일 가이드 R-05: 판정 결과와 집계 결과를 속성으로 만들지 않음) | 만들지 않음 |
| 7 | 이미 펼친 테이블의 사본 | 원천에 펼친 테이블이 있으면 그것을 씀([`intermediate-concepts.md`](intermediate-concepts.md) 5장) | 원천 테이블 사용 |

### 4.4 조인과의 구분

| No. | 원천 상태 | 처리 | 새 테이블 |
|---|---|---|---|
| 1 | 두 테이블에 같은 뜻·같은 꼴의 연결 키가 있음 | 관계 하나(판정 있음, 묻지 않음) | 없음 |
| 2 | 두 식별자를 함께 가진 잇는 테이블이 원천에 있음 | 가운데 개념 + 관계 둘(판정 있음, [`intermediate-concepts.md`](intermediate-concepts.md) 2장) | 없음 |
| 3 | 실재 연결 키로 업무 테이블 둘 이상을 거쳐야 이어짐, 또는 같은 뜻 값이 연결 키로 닿는 다른 데이터 구조에만 있음(판정 경유) | 조인 선택지. 거쳐 가는 테이블을 가운데 개념으로 올려 관계로 이음. 사람이 고름 | 없음 |
| 4 | 값은 기존 데이터에 있으나 꼴이 다름(결합·반복·경로 안, 판정 형태 다름) | 매핑 테이블 선택지. 사람이 고름 | 매핑 테이블 |
| 5 | 값이 어디에도 없음(판정 없음) | 빼고 보고. 기존 데이터만으로 잇는 매핑 테이블을 만들 수 있으면 후보로 보임 | 매핑 테이블(채택 때만) |

### 4.5 후보가 나오는 자리

| 단계 | 후보가 나오는 경로 |
|---|---|
| ②-1 | 판정 형태 다름. 꼴은 근거 위치의 생김새로 가름(4.2) |
| ③~⑤ | [`intermediate-concepts.md`](intermediate-concepts.md)의 축이 가운데 개념이나 마디 개념을 요구하는데 그 데이터 구조가 원천에 없음(펼친 테이블 없음, 마스터 없음, 역할 기록 없음). 새 요소도 이 문서의 규칙으로 근거를 확인하는 경로로 ⑥에 오름 |
| ⑨ | 매핑 의미 검사에서 뜻이 같은 컬럼이 다른 데이터 구조에만 있음. 원천 문서가 밝힌 연결 키로 그 데이터 구조에 닿을 때만 조인 후보로 검증 리포트 5.2절에 적음(1차는 묻지 않고 기록만). 닿지 않으면 2.3 판별 차례 5·6으로 '없음'(원천 부재)이나 '확인 필요'(원천 확인 필요)를 가림 |
| 수정 단계 | CQS-07(설계 밖 사유 필수 CQ 미응답)·CQS-01·02(필수 CQ 응답 불가·부분 응답) 지적의 풀 방법이 매핑 테이블·조인 |

### 4.6 제안 칸(설계 리포트 7.1절)

| 칸 | 기재 내용 |
|---|---|
| No. | MT-01부터. 정의 문서 데이터 구조 설명의 표지와 같음. 차수가 바뀌어도 같은 후보는 같은 번호 |
| 이름 | [`filling-document-format.md`](filling-document-format.md) 2.1 규칙(쓰는 개념 이름 + 원천 테이블 공통 접두·접미어) |
| 꼴 | 4.2 꼴 이름 |
| 재료 | 기존 테이블.컬럼 또는 저장 경로 규칙과 원천 문서 절 |
| 생성 방법 | 한 행을 어떻게 만드는지(나누는 자리·구분 기호·거르는 값, 빈 값·오류 행 처리, 한 행이 무엇 하나인지) |
| 근거 CQ | 채택하면 답이 생기는 CQ |
| 쓰는 요소 | 이 테이블에 매핑할 개념·관계 |
| 데이터 확인 사항 | 결합 자릿수·구분 기호처럼 실제 데이터로 확인할 것 |
| 결정 | 채택(사람) · 빼고 보고(사람) · 빼고 보고(기본값, 사람 확인 없음). 12절 No. |
| 만드는 곳 | 고객 DB 테이블 · 고객 DB 뷰 · Graphio 메타 타입 워크플로우 · 지정 필요(기본) |
| 조치 주체 | 고객 원천 담당(기본) · 지정 필요 |

- 채택하지 않은 후보도 행을 남긴다. 받는 사람이 무엇을 고르면 어느 CQ를 답할 수 있게 되는지 보게 하기 위함이다
- 칸(컬럼) 목록은 채택하면 정의 문서 데이터 구조 절에, 채택하지 않으면 표 아래 '※ MT-nn 칸:' 주석에 적는다
- '만드는 곳'은 매핑 테이블을 만들 수단을 기록만 하는 칸이다. 메타 타입 워크플로우는 이 칸에 적을 수 있는 값일 뿐 ②-2·⑥ 선택지에 넣지 않는다. 선택지는 3장 판정값 표의 셋(빼고 보고·조인·매핑 테이블)만 둔다

### 4.7 정의 문서에 싣는 꼴

가운데 Object Type 하나와 Link Type 두 건으로 싣는 꼴만 쓴다. 정의 문서 서식은 바꾸지 않는다.

| 차례 | 할 일 | 기재 위치 |
|---|---|---|
| 1 | 고객 DB(또는 대상 환경)에 매핑 테이블을 만들고 기존 데이터로 채움 | 정의 문서 밖(검증 리포트 7.2절) |
| 2 | 대상 환경에서 사람이 연결 정보 → 원천 데이터 → Meta Type(`CUSTOM`)으로 등록·게시. 정의 파일은 Meta Type을 만들지 않음(이름이 다르면 GOS61014: 대상 환경에서 Meta Type 이름을 찾지 못함) | 정의 문서 밖(검증 리포트 7.1절) |
| 3 | Meta Type 블록: 종류 `CUSTOM`, 설명에 '대상 환경에 아직 없음(매핑 테이블 MT-nn). 기존 테이블 값으로 만듦: (생성 방법 한 줄)' | Meta Type 절 |
| 4 | 가운데 개념: 양쪽 식별 값과 딸린 값을 속성으로, 대표 표시 속성 1건(DOC-04: 대표 표시 속성 오류 검사). 두 키를 합쳐야 행이 가려지면 식별 속성은 비움([`intermediate-concepts.md`](intermediate-concepts.md) 2장) | Object Type 절 |
| 5 | 매핑: 가운데 개념 ← 매핑 테이블 | Object Mapping 절 |
| 6 | 관계 둘: 가운데 개념 → 양쪽 개념. 조인 속성 자료형을 맞춤 | Link Type 절 |

- 기존 개념에 둘째 매핑을 붙여야 하는 결정 사항은 그대로 싣지 못한다. 가운데 개념을 거치는 꼴로 담고, 결정 사항과 모양이 달라진 사실을 설계 리포트 11절에 적는다
- Link Type 하나로 매핑 테이블을 거쳐 가는 꼴은 조인 쌍이 하나뿐이라 쓸 수 없다

## 5. 조인 후보

판정 '경유'인 답 요소는 조인 선택지를 함께 보인다. 원천 문서가 밝힌 연결 키로 경로의 모든 이음이 닿을 때만 보이고(3장), 사람이 조인을 고르면 거쳐 가는 테이블을 가운데 개념으로 올려 관계로 잇는다(4.4 No.3). 고르지 않으면 기본값 빼고 보고로 두고 미응답 사유는 원천 선택 미채택이다.

조인을 Graphio 정의에 싣는 꼴은 Link Type의 조인 속성 한 쌍뿐이다. 한 개념을 여러 데이터 구조에 매핑하는 꼴은 두 매핑의 행을 합치는지 더하는지 확인되지 않아 쓰지 않는다. 그래서 다른 데이터 구조에만 있는 값을 잇는 길은 그 데이터 구조를 가운데 개념으로 올려 관계로 잇는 꼴 하나다.

## 6. 교집합·차집합과 연쇄 제외

CQ가 요구하는 것과 원천에 있는 것을 맞대면 세 갈래가 나온다.

| No. | 갈래 | 뜻 | 처리 | 기록 위치 |
|---|---|---|---|---|
| 1 | CQ ∩ 원천 | CQ가 요구하고 원천에 근거가 있음 | 만듦 | 설계 리포트 4.2절(판정 있음), 5·6절 |
| 2 | CQ − 원천 | CQ가 요구하나 원천에 없음·형태 다름·경유·확인 필요 | ②-2·⑥에서 빼고 보고·조인·매핑 테이블 | 설계 리포트 4.2·7.1·12절, 검증 리포트 5.2절 |
| 3 | 원천 − CQ | 원천에 있으나 어느 CQ도 쓰지 않음 | 만들지 않음 | 설계 리포트 9.1절('CQ가 값을 쓰지 않아 만들지 않은 항목'). 테이블 단위로 적음 |

- 원천 − CQ 갈래는 만들지 않는 원칙을 지키고 목록으로만 남긴다
- 빼고 보고로 요소 하나를 빼면, 그 요소를 지나야만 닿던 요소가 어느 CQ의 조건에서도 닿지 않게 될 수 있다. 그런 요소도 빼고 원천 대조표 처리 칸에 '연쇄 제외(No.n 때문)'로 적는다
- 범위는 '어느 CQ 조건에서도 닿지 않음'으로 좁게 둔다. 부분 응답에 쓰이는 구조는 남긴다
- ②-2에서 연쇄로 빠질 요소를 해당 항목 아래 함께 보인다
- 꼴 요소를 빼서 어느 CQ 조건에서도 닿지 않게 된 요소도 같은 범위로 연쇄 제외하고 설계 리포트 4.3절 구조 꼴 적용표 '뺀 꼴 요소' 칸에 적는다

## 7. 기록 자리와 응답 불가 CQ 보고

원천 대조의 결과는 아래 자리에 적는다.

| No. | 자리 | 적는 것 |
|---|---|---|
| 1 | 설계 리포트 4.2절 원천 대조표 | 답 요소마다 판정·근거 위치·처리 |
| 2 | 설계 리포트 7.1절 매핑 테이블 제안 | 매핑 테이블 후보(4.6) |
| 3 | 설계 리포트 12절 결정 기록 | ②-2·⑥에서 보인 항목과 고른 값, 판정 정정 |
| 4 | 검증 리포트 5.1절 | CQ마다 미응답 사유(3장 미응답 사유 표) |
| 5 | 검증 리포트 5.2절 응답 불가 CQ 보고 | 답하지 못하는 CQ의 요약표와 CQ별 상세표 |

**설계 리포트 4.2절 원천 대조표는 답 요소 하나가 한 행이다.** 같은 요소를 여러 CQ가 쓰면 한 행에 모은다. 원천에만 있는 테이블 수는 표 위 첫머리 한 줄로 적고 9.1절을 가리킨다.

| 칸 | 기재 내용 |
|---|---|
| No. | 1부터. 12절 결정 기록, 검증 리포트 5.2절, 4.3절 구조 꼴 적용표가 이 번호로 가리킴 |
| 답 요소 | 값 이름과 짧은 뜻 |
| 요소 종류 | 대상·값·잇는 값 |
| 사용 CQ | 그 요소를 쓰는 CQ 번호 모두 |
| 판정 | 있음·형태 다름·경유·없음·확인 필요 가운데 하나. 판정 정정은 「있음(판정 정정: 확인 필요 → 있음)」 꼴(3장) |
| 근거 위치 | 있음이면 테이블.컬럼·연결 키·문서 항목과 원천 문서 절. 없음이면 없다고 본 근거(그 절의 문장, 또는 '컬럼 목록 전수에 없음'). 확인 필요면 무엇을 확인할지 |
| 처리 | 만듦·빼고 보고·빼고 보고(후보 미채택)·조인·매핑 테이블·연쇄 제외·규격 제약 가운데 하나. 조인이면 연결 키, 매핑 테이블이면 MT-nn |
| 결정 No. | 12절 행 번호. 판정이 있음이면 「해당 없음」. 판정 정정이면 그 12절 행 번호 |

**설계 리포트 12절에는 원천 대조에서 나온 멈춤의 답을 적는다.** 아래는 원천 대조가 채우는 칸이다. 칸 차례와 나머지 칸은 [`design-report-format.md`](design-report-format.md) 12절을 따른다.

| 칸 | 기재 내용 |
|---|---|
| 멈춤 | '원천 확인'·'설계안 확인'. 스킬 단계 번호는 적지 않음 |
| 대상 | 4.2절 No.와 답 요소, ③~⑤의 새 요소, 또는 4.3절 No.(⑥에서 대안 꼴을 고른 경우) |
| 선택지 | 보인 선택지(3장) |
| 기본값 | 빼고 보고 |
| 근거 | 판정과 근거 위치 요약 |
| 고른 값 | 적용한 선택지. 판정 정정이면 「판정 정정」 |
| 정한 쪽 | '사람'·'기본값(사람 확인 없음)' |
| 적용 상태 | '적용'·'적용 안 됨(대상이 사라짐)'. 뒤 단계에서 대상이 바뀌어 지난 답을 쓸 수 없으면 뒤를 씀 |

**응답 불가 CQ 보고는 검증 리포트 5.2절에 적는다.** 칸과 꼴은 [`verification-report-format.md`](verification-report-format.md)를 따르고, 원천 대조에 걸린 칸은 아래처럼 적는다.

- 응답 불가 CQ 보고(검증 리포트 5.2절) CQ별 상세표의 '대조한 원천 위치' 칸에는 없다·모른다는 근거(문서·절·문장)와, 대신 쓰지 않은 비슷한 컬럼과 그 까닭을 적는다
- 원천 문서가 적재 범위 밖이라고 밝힌 항목(공개 API에는 있으나 적재 테이블에 없음)은 '대조한 원천 위치' 칸에 그 사실만 적는다. 풀 방법은 '풀 수 없음'으로 둔다. 적재 범위 밖 항목은 근거로 치지 않기 때문이다(2.1)
- '없는 요소' 칸에는 요소마다 종류(개념·속성·관계)와 원천 대조 판정, 4.2절 No.를 적는다
- '미응답 사유' 칸 값은 3장 미응답 사유 표를 따른다

## 8. 다시 대조하는 때

| No. | 때 | 다시 대조하는 것 |
|---|---|---|
| 1 | ③~⑤에서 새 요소(가운데 개념·마디 개념)를 둘 때 | 그 요소를 2.3 판별 차례로 판정하고 설계 리포트 4.2절에 행을 더함. 판정이 '있음'이 아니면 ⑥에 올림 |
| 2 | ⑦에서 매핑할 컬럼을 원천에서 찾지 못할 때 | 그 값을 2.3 판별 차례로 다시 판정함. 판정이 바뀌면 설계 리포트 4.2절을 먼저 고친 뒤 정의 문서에 옮김 |
| 3 | ⑨ 매핑 의미 검사 | 뜻이 같은 컬럼이 다른 데이터 구조에만 있을 때. 연결 키로 닿으면 '경유'(조인 후보), 닿지 않으면 '없음'이나 '확인 필요' |
| 4 | 수정 단계에서 구조를 더할 때 | 더할 요소마다 2.3 판별 차례로 판정함. 근거 없는 요소는 선택지에 두지 않음. 설계 수정 차수에서 설계 리포트 4.2절·12절에 먼저 적고 다시 연 ⑥([`design-report-review.md`](design-report-review.md) 4.9)을 거침 |
| 5 | 검증만 모드(`--verify`) | 설계를 바꾸는 차이(요소 더함·뺌·이름 바꿈, 관계 방향·조인 속성, 원천 선택, 구조 꼴)가 있으면 대조·판정하지 않고 멈춤. 수정 요청서 -N차에 사람 요청 행 초안(성격 설계 변경, 상태 해석 필요)을 쓰고 외부 수정본은 -N+1차-외부수정으로 옮김. 정비 차이만 받음. 다시 대조는 그 요청을 반영하는 설계 수정 차수(No.6)에서 함. 설계를 바꾸는 차이는 `scripts/check_design_report.py --stage 검증뒤` 맞대기로 가름 |
| 6 | 설계 수정 차수에서 원천 선택이 바뀌는 항목 | ②-2 규칙으로 다시 대조하고 설계 리포트 4.2절·12절을 먼저 고친 뒤 ⑥을 거침([`design-report-review.md`](design-report-review.md) 4.9) |

## 9. 자주 빗나가는 자리

| No. | 빗나가는 자리 | 바른 처리 |
|---|---|---|
| 1 | 원천 목록에서 출발함 | CQ 답 요소에서 출발해 원천의 근거 꼴을 찾는다(2.2). 어느 CQ도 쓰지 않는 원천 항목은 만들지 않고 9.1절에 목록으로만 남긴다(6장) |
| 2 | CQ 문서 '출처' 칸을 근거로 씀 | '출처' 칸은 인터뷰 위치라 데이터 원천이 아니다. 근거는 원천 문서에서 찾는다(2.1) |
| 3 | API 명세에만 있는 항목을 근거로 씀 | 적재 테이블만 매핑 대상이다. 적재 테이블에 없으면 근거로 치지 않는다(2.1, 4.3 No.4) |
| 4 | 이름이 비슷한 컬럼으로 대신함 | 뜻 판별 차례로 뜻이 같을 때만 근거로 친다. 뜻이 다르면 대신하지 않고 '대조한 원천 위치' 칸에 대신 쓰지 않은 까닭을 적는다(2.3, 7장) |
| 5 | 모름을 있음으로 봄 | 전부라고 밝히지 않은 목록에 없거나 문서끼리 갈리면 '확인 필요'로 두고 무엇을 확인할지 적는다(2.3 차례 6) |
| 6 | 매핑 테이블에 새 사실을 담음 | 매핑 테이블은 기존 데이터에서 결정적 규칙으로 만든 대응 하나만 담는다. 새로 입력할 값·이력·판정 결과를 담으면 매핑 테이블이 아니다(4.1, 4.3) |
