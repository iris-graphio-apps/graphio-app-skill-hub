# 구조 꼴

디자인 패턴을 Graphio 구조로 옮긴 구조 꼴과 고르는 법을 다룬다. ③~⑤에서 개념·관계를 정할 때 CQ 꼴에 맞는 꼴을 이 문서에서 고르고 업무 이름으로 복제한다. 꼴의 근거(원래 디자인 패턴의 뜻·한계)는 [`pattern-catalog.md`](pattern-catalog.md)에서 본다.

**꼴 요소는 CQ가 요구하고 원천이 채우는 것만 만든다.** 원천 근거는 [`source-match.md`](source-match.md)가 가린다.

**가운데 개념을 둘지는 이 문서가 정하지 않는다.** [`intermediate-concepts.md`](intermediate-concepts.md)의 네 축을 따른다.

---

## 1. 쓰는 자리와 차례

| 단계 | 하는 일 |
|---|---|
| ② | CQ(조각)마다 CQ 꼴 표지와 근거 낱말을 적음 |
| ③~⑤ | 표지와 설계 리포트 4.2절 원천 판정으로 2장 차례를 짚어 꼴을 고르고 업무 이름으로 복제함. 설계 리포트 4.3절에 적음 |
| ⑥ | 후보 꼴이 둘 이상이면 기본값과 대안을 함께 보임 |
| 수정 단계 | 관계에 시점·수량·역할이 붙어야 하면 가운데 개념으로 다시 짬. 딸린 값 컬럼을 가진 잇는 테이블이 원천에 없으면 다시 짜지 않고 원천 부재로 보고 |

## 2. 고르는 법

**위에서부터 짚고 처음 맞는 꼴을 쓴다.** 실행마다 같은 CQ에 다른 꼴을 고르지 않기 위해서다([`source-match.md`](source-match.md) 2.3 판별 차례와 같은 원칙).

- **CQ 꼴 표지는 아래 닫힌 목록에서 하나를 고른다.** ②에서 CQ(조각)마다 표지와 근거 낱말(질문 문장이나 답 요소의 원문 낱말)을 적는다
- 꼴 표지 11건: 3.1 꼴 목록 No.1~11의 꼴 이름(참여 사건·역할 관계·구성 가운데 개념·절차 차례·소속·위치·분류 코드·목록 펼침·식별자 대응·정보 실현·시점 색인·경유 연결). 꼴마다 맞는 질문 꼴은 3.1 'CQ 꼴' 칸에 있다
- 대상 하나의 값: 특정 대상 한 건의 값 하나만 묻는 질문. 꼴을 고르지 않고 [`source-match.md`](source-match.md) 2.2 '값' 근거 꼴로 속성을 둔다(차례 1)
- 맞는 꼴 없음: 위 열두 표지 어디에도 맞지 않는 질문(차례 8)
- 표지 값은 설계 리포트 4.3절 'CQ 꼴 표지' 칸에 그대로 적는다. 원래 이름(괄호 안 영문 패턴 이름)은 표지에 쓰지 않는다

| 차례 | 확인 | Graphio에서 하는 일 |
|---|---|---|
| 1 | CQ 꼴 표지가 3.1 꼴 목록의 어느 꼴과 맞는지 | 맞는 꼴을 후보로 둠. 꼴 이름이 아니라 CQ 꼴로 고름. 표지가 '대상 하나의 값'이면 꼴을 고르지 않고 [`source-match.md`](source-match.md) 2.2 '값' 근거 꼴로 속성을 둠 |
| 2 | 그 꼴의 필수 요소가 설계 리포트 4.2절 원천 대조표에 있는지 | 없으면 3.2 '빈 요소 처리' 칸이 정한 꼴로 내려감. 마지막 꼴에서도 없으면 그 조각은 원천 부재로 보고. 내려간 까닭은 설계 리포트 4.3절 구조 꼴 적용표에 남김 |
| 3 | 꼴이 CQ와 같음(Precise) | 꼴을 업무 이름으로 그대로 복제 |
| 3′ | 꼴에 CQ가 쓰지 않는 요소가 있음(redundant: 꼴이 CQ보다 복잡함) | CQ가 쓰는 요소만 복제하고 나머지 요소는 만들지 않음 |
| 4 | 꼴이 CQ보다 일반적임(Broader) | 업무 이름·업무 속성으로 좁혀 복제(하위 개념 대신 업무 개념 하나) |
| 5 | 꼴이 CQ보다 구체적임(Narrower) | 꼴의 일부만 씀(가운데 개념 없이 관계 하나 등) |
| 6 | 꼴이 CQ 일부만 다룸(Partial) | CQ를 조각내 조각마다 꼴을 고르고 조합 |
| 7 | 후보 꼴이 둘 이상이고 둘 다 원천 근거가 있음 | 새 구조가 적고 홉이 적은 쪽을 기본값으로 두고(속성 < 관계 1건 < 원천 테이블 가운데 개념 < 경유 개념 < 문서 타입 < 매핑 테이블), ⑥에서 대안을 함께 보임 |
| 8 | CQ 꼴 표지가 '맞는 꼴 없음' | 꼴 없이 [`intermediate-concepts.md`](intermediate-concepts.md) 판단과 원천 대조만으로 설계함. 실행 중 새 꼴을 만들지 않고 설계 리포트 4.3절에 '맞는 꼴 없음'으로 남겨 꼴 추가 후보로 보임 |

## 3. 구조 꼴 목록

### 3.1 꼴 목록

| No. | 꼴 이름(원래 이름) | CQ 꼴 | Graphio 구조 | 원천 요구 | 적용 예 | 장단점 | 바뀐 판본 |
|---|---|---|---|---|---|---|---|
| 1 | 참여 사건(Participation·Situation) | 이 사건에 무엇이 참여했나, 이 대상은 어떤 사건에 참여했나 | 사건 개념 → 대상 개념 관계. 참여에 딸린 값이 있으면 참여 가운데 개념 + 관계 둘 | 사건 한 건이 한 행인 테이블과 대상 외래 키 | 교육 이수 이력 → 직원·교육 과정 | 단순함. 사건 시점뿐이라 '언제 참여했나'를 따로 묻는 CQ는 못 받음 | 0.4.0 |
| 2 | 역할 관계(AgentRole·ParticipantRole) | 어떤 대상이 이 역할을 맡나 | 역할마다 관계 하나(같은 도착 개념). 역할에 딸린 값·기간·역할 목록 테이블이 있을 때만 역할 가운데 개념 | 역할별 외래 키 컬럼. 역할 개체는 역할 기록 테이블 | 인사 평가 → 직원(평가 대상자·평가자) | 관계 이름만으로 대부분 풀림. 역할 기간은 기록 테이블이 없으면 원천 부재 | 0.4.0 |
| 3 | 구성 가운데 개념(Componency·N항 관계) | 이 대상의 구성요소는 무엇이고 몇 개인가 | 가운데 개념(양쪽 식별 값 + 딸린 값) + 관계 둘 | 두 식별자를 함께 가진 잇는 테이블 | 프로젝트와 사번을 함께 가진 투입 테이블 → 프로젝트 투입 | 근거가 확실함. 홉 하나 늚 | 0.4.0 |
| 4 | 절차 차례(Sequence) | 무엇이 무엇보다 앞서나, 다음 단계는 | 뒤 단계 → 앞 단계 관계를 차례로. 같은 개념 안의 차례는 순번·앞 단계 식별 속성(같은 개념끼리 잇는 관계는 GOS61106으로 막힘) | 뒤 단계 테이블의 앞 단계 키 | 채용 공고 → 서류 전형 → 면접 전형 | 업무 흐름이 보임. 여러 단계 전이는 질의가 홉을 따라감 | 0.4.0 |
| 5 | 소속·위치(Constituency·Place·PartOf) | 이것은 어디에 속하나 | 하위 → 상위 관계. 같은 종류 계층은 상위 식별자를 속성으로만 | 하위 테이블의 상위 외래 키 | 직원 → 부서. 부서의 상위 부서는 상위 부서 코드 속성 | 단순함. 같은 종류 계층은 관계로 못 그림 | 0.4.0 |
| 6 | 분류 코드(Classification·Value Set) | 이 대상은 어느 범주인가 | 거르기만 하면 코드 속성. 코드를 든 개념이 둘 이상이고 그 코드에서 양쪽으로 뻗는 CQ가 있으면 코드 개념 | 코드 컬럼. 코드 개념은 코드 마스터나 채택한 코드 모음표 | 직원의 직급 코드 속성 | 속성이면 홉이 늘지 않음. 이름이 원천에 없으면 코드를 대표 표시 | 0.4.0 |
| 7 | 목록 펼침(Collection 항목만) | 이 모음에 든 것은 무엇인가 | 항목 개념 → 칸을 든 개념 관계 하나. 모음 개념은 두지 않음 | 이미 펼친 테이블, 없으면 목록 펼침 매핑 테이블(채택) | 한 칸에 뭉친 보유 자격 목록 → 보유 자격 펼침 매핑 테이블 | 펼친 테이블이 없으면 채택 없이는 못 만듦 | 0.4.0 |
| 8 | 식별자 대응(Mapping의 데이터판) | 같은 식별 번호의 차수들은 | 대응 가운데 개념 + 관계 둘 | 결합·경로 규칙이 원천 문서에 적힘 + 식별자 대응 매핑 테이블 | 옛 사번과 새 사번의 대응 | 결합 규칙을 데이터로 확인해야 함 | 0.4.0 |
| 9 | 정보 실현(Information realization) | 이 대상의 문서는 무엇인가 | 문서 타입(`DOC_TYPE`) 개념 → 정형 개념 관계. 문서 안 항목은 사용자 정의 프로퍼티 | 비정형 목록의 문서 종류·항목 + 정형 키를 잇는 값(문서-식별자 대응표나 문서 안 키 항목) | 인사 발령 문서 → 직원 | 문서 표본 품질에 좌우됨 | 0.4.0 |
| 10 | 시점 색인(Time indexed participation·TimeIndexedSituation·Transition) | 언제 무엇이 참여했나, 그 시점의 상태는 | 이력 가운데 개념(시작·종료 시점) + 관계 | 시점 컬럼을 가진 이력 테이블 | 부서 이동 이력(발령 일자) → 직원·부서. 현재 소속만 있으면 이동 시점은 원천에 없음 | 이력 테이블이 없으면 적용 불가. 고객 원천이 현재 값만 보관하면 시점 CQ는 응답 불가 | 0.4.0 |
| 11 | 경유 연결(조인 경로) | A의 C인데 원천은 A–B, B–C만 이음 | 경로의 가운데 테이블 B를 개념으로 두고 관계 둘 | 경로의 모든 이음에 원천이 밝힌 연결 키 | 직원–프로젝트(투입 테이블 경유) | 새 테이블 없이 닿음. 홉 늘고 B의 범위가 답에 섞이므로 사람이 고름 | 0.4.0 |

- '꼴 이름(원래 이름)' 칸의 괄호 안 원래 이름은 [`pattern-catalog.md`](pattern-catalog.md)에서 그 패턴을 다룬 절을 가리킨다. 꼴의 뜻과 한계를 확인할 때 그 절을 편다
  - No.1·2·4·9·10: 4.1, 4.2
  - No.3: 4.2, 4.3, 2.1(N항 관계)
  - No.5·7: 4.1, 4.2, 4.3
  - No.6: 4.1, 4.2, 2.1(Value Partition과 Value Set)
  - No.8: 3.2
  - No.11: 해당 절 없음(원래 이름이 디자인 패턴이 아님)
- 계산 값(마지막 점검 시각, 고장률처럼 질의가 계산할 값)은 꼴로 만들지 않는다
- '바뀐 판본'은 그 꼴 행이 생기거나 CQ 꼴·Graphio 구조·원천 요구·요소 가운데 하나라도 바뀐 가장 늦은 스킬 판본이다. 앞 판정과 대조할 때 꼴 목록이 바뀌어 생긴 변화를 가르는 데 쓴다([`rule-catalog.md`](rule-catalog.md) 규칙 목록의 '바뀐 판본'과 같은 쓰임)
- **꼴 목록은 고정 목록이다.** 실행 중에 꼴을 더하거나 빼지 않고, 입력에 맞춰 목록을 줄이지도 않는다. 고객이 더한 꼴 파일은 받지 않는다

### 3.2 꼴 요소와 줄이는 차례

| No. | 구조 꼴 | 필수 요소(원천 요구) | 선택 요소(원천 요구, 만드는 조건) | 빈 요소 처리 | 적용 예 |
|---|---|---|---|---|---|
| 1 | 참여 사건 | 사건 개념(대상: 사건 한 건이 한 행인 테이블), 사건 → 대상 관계(잇는 값: 사건 테이블의 대상 외래 키) | 참여 가운데 개념과 딸린 값(잇는 값·값: 참여 하나가 한 행이고 딸린 값 컬럼을 가진 잇는 테이블). CQ가 참여에 딸린 값(수량·역할)을 물을 때. 참여의 시작·끝을 따로 물으면 No.10 시점 색인으로 옮김 | 선택 요소가 비면 사건 → 대상 관계 하나에 머물고 딸린 값은 원천 부재. 필수 요소가 비면 그 조각은 원천 부재 | 교육 이수 이력 → 직원·교육 과정(이수 이력 테이블의 사번·과정 코드). 직원별 이수 점수를 물어도 점수 컬럼을 가진 테이블이 없으면 이 관계에 머물고 점수는 원천 부재 |
| 2 | 역할 관계 | 역할마다 관계(잇는 값: 역할별 외래 키 컬럼) | 역할 가운데 개념(대상: 역할 기록 테이블). CQ가 역할 기간·역할에 딸린 값을 물을 때 | 역할 기록 테이블이 없으면 역할마다 관계에 머물고 역할 기간을 묻는 조각은 원천 부재(3.1 No.2 역할 관계) | 인사 평가 → 직원 관계 둘(평가 대상자 사번·평가자 사번 컬럼). 평가자를 맡은 기간을 물어도 평가자 지정 기록 테이블이 없으면 관계 둘에 머물고 기간은 원천 부재 |
| 3 | 구성 가운데 개념 | 가운데 개념과 관계 둘(잇는 값: 두 식별자를 함께 가진 잇는 테이블) | 딸린 값(값: 그 잇는 테이블의 컬럼). CQ가 그 값(수량 등)을 물을 때 | 잇는 테이블이 없고 한 칸에 뭉친 목록만 있으면 No.7 목록 펼침(매핑 테이블 채택 때). 둘 다 없으면 원천 부재 | 프로젝트 투입(프로젝트 코드와 사번을 함께 가진 투입 테이블) → 프로젝트·직원. 투입 비율은 그 비율을 묻는 CQ가 있을 때만 딸린 값으로 둠 |
| 4 | 절차 차례 | 뒤 단계 → 앞 단계 관계(순서: 뒤 단계 테이블의 앞 단계 키) | 해당 없음 | 앞 단계 키가 없으면 원천 부재(이름·시각이 비슷하다고 잇지 않음). 같은 개념 안의 차례는 순번·앞 단계 식별 속성으로 두고 여러 단계를 따라가야 답하는 CQ는 규격 제약([`source-match.md`](source-match.md) 3장, GOS61106: 같은 개념끼리 잇는 관계 금지) | 면접 전형 → 서류 전형 → 채용 공고(뒤 전형 테이블의 앞 단계 번호). 면접 전형 테이블에 서류 전형 번호가 없으면 일자가 가깝다고 잇지 않고 원천 부재 |

| 11 | 경유 연결 | 가운데 테이블 개념과 관계 둘(잇는 값: 경로의 모든 이음에 원천이 밝힌 연결 키) | 해당 없음 | 사람이 조인을 고르지 않으면 원천 선택 미채택 | 직원–프로젝트를 투입 테이블 경유로 이음(사번·프로젝트 코드 연결 키). 사람이 이 조인을 고르지 않으면 원천 선택 미채택 |

- 괄호 안은 [`source-match.md`](source-match.md) 2.2 근거 꼴 이름으로 적은 원천 요구다
- 다른 꼴로 옮기는 조건은 하나다. CQ가 지금 꼴이 담지 못하는 값(시점·역할·수량)을 물으면 그 한계를 메운 꼴로 옮긴다
- 옮긴 꼴의 요소에도 원천 요구가 있다. 원천이 없으면 다시 내려간다
- 꼴 요소가 빠지는지는 설계 리포트 4.2절 원천 판정을 그대로 따른다. **내려가는 폭은 이 표가 정하고 모델이 정하지 않는다**

## 4. Graphio가 담지 못하는 것과 우회

| 담지 못하는 것 | 우회 |
|---|---|
| 하위 개념·공리·추론 | 꼴을 업무 이름으로 복제함 |
| 관계 속성 | 딸린 값이 있으면 가운데 개념으로 풂 |
| 같은 개념끼리 잇는 관계(GOS61106) | 상위 식별 속성이나 가운데 개념으로 둠 |
| 다중성·허용값·배타 제약 칸 | 설명·경고문에 적음 |

## 5. 오류 없이 의도와 어긋나는 꼴

반입은 되지만 의도와 어긋나는 꼴과 그 꼴을 잡는 규칙이다. 규칙의 등급과 설명은 [`rule-catalog.md`](rule-catalog.md)에 있다.

| 꼴 | Graphio에서 생기는 모양 | 잡는 규칙과 처리 |
|---|---|---|
| 조인 근거 없는 관계(Graphio 고유) | 조인 속성이 매핑되지 않은 관계. 반입은 되고 늘 빈 관계 | DOC-14(조인 속성 매핑 없는 관계) Error |
| 데이터가 붙지 않은 개념(Graphio 고유) | 매핑 0건 개념. 규격 검사기는 GOS61017(Object Mapping 0건)을 보류로 내고 Graphio 적용 단계에서 막힘 | DOC-12(매핑 없는 개념) Error. 같은 개념의 SPC-03(규격 검사 보류) GOS61017 행은 겹치므로 뺌 |
| 근거 없는 속성(Graphio 고유) | 매핑 없는 속성. 늘 빈 값 | DOC-13(매핑 없는 속성) Error |
| 예외 근거 없는 새 구조(Graphio 고유) | 원천에도 없고 매핑 테이블·문서 타입도 아닌 '아직 없음' 데이터 구조 | DOC-15(예외 표지 없는 새 데이터 구조) Error. DOC-09(대상 환경 미생성 데이터 구조) Info는 MT-nn 표지가 있거나 종류가 `DOC_TYPE`인 데이터 구조만 가리킴 |
| 같은 대상 두 개념 | 같은 데이터 구조·식별 컬럼에 매핑된 두 개념 | 스타일 가이드 C-04(같은 대상을 다른 이름으로 부른 곳 점검) |
| 이름만 다른 중복 관계 | 출발·도착·조인 속성이 같은데 이름만 다른 관계 둘 | GOS61105(관계 완전 중복)는 이름까지 같아야 잡음. 후보로만 기록 |
| 같은 컬럼 두 속성 | 한 개념 안 같은 컬럼에 매핑된 속성 둘 | 잡는 규칙 없음. 후보로만 기록 |
| 미사용 요소 | 어느 CQ도 쓰지 않는 요소 | CQS-05(미사용 개념·속성·관계) Warning |
| 같은 이름 다른 도착 관계 | 같은 이름 관계가 다른 도착 개념으로 둘 | SPC-02(규격 경고)의 GOS61330(이름이 같고 양끝이 다른 관계 경고) |
| 비식별 조인 확산 | 도착 쪽 비식별 조인으로 관계가 넓게 퍼짐 | 규격 검사기의 코드 없는 경고. 샘플 데이터가 생기면 다시 봄 |

## 6. 리포트에 적는 법

**원래 이름(꼴 이름 뒤 괄호 안 영문 패턴 이름)은 설계 리포트와 대화 출력에 적지 않는다.** 표 칸에도, 구조 꼴 선택 근거 절에도 적지 않는다. 산출물에는 꼴 이름(참여 사건·역할 관계 등)과 근거만 적는다. 원래 이름은 모델이 꼴을 고를 때 읽는 이 문서에만 둔다.

### 6.1 구조 꼴 적용표

설계 리포트 4.3절 구조 꼴 적용표에는 CQ 조각마다 한 행을 두고 아래 칸을 적는다.

| 칸 | 기재 내용 |
|---|---|
| No. | 1부터. 설계 리포트 12절 결정 기록이 대안 꼴을 고른 행을 이 번호로 가리킴 |
| CQ | CQ 번호와 짧은 내용. 2장 차례 6으로 조각냈으면 조각마다 한 행이고 조각 낱말을 괄호에 적음 |
| CQ 꼴 표지 | 2장 닫힌 목록 값(꼴 표지 11건·「대상 하나의 값」·「맞는 꼴 없음」)과 근거 낱말(질문 문장이나 답 요소의 원문 낱말) |
| 고른 꼴 | 3.1 꼴 이름. 표지가 「대상 하나의 값」이면 「해당 없음(속성)」, 「맞는 꼴 없음」이면 「맞는 꼴 없음」 |
| 맞춤 경우 | 같음·요소가 남음·넓음·좁음·일부(2장 차례 3·3′·4·5·6). 조각낸 CQ는 「일부」 |
| 채운 꼴 요소 | 요소 이름과 근거 데이터 구조 |
| 뺀 꼴 요소 | 요소 이름, 설계 리포트 4.2절 No., 미응답 사유. 없으면 「해당 없음」 |
| 내려간 꼴 | 3.2 '빈 요소 처리' 칸을 따라 내려간 꼴. 없으면 「해당 없음」 |
| 대안 꼴 | 2장 차례 7로 ⑥에 함께 보인 꼴. 없으면 「해당 없음」 |
| 결정 No. | 설계 리포트 12절 행 번호. 사람이 대안 꼴을 고르지 않았으면 「해당 없음」 |

### 6.2 구조 꼴 선택 근거

- 설계 리포트에는 표 셋(4.3절 구조 꼴 적용표, 2절 '구조 꼴 적용' 행, 6절 관계 표 '구조 꼴' 칸)에 더해 4.3절 바로 뒤 `### 4.4 구조 꼴 선택 근거` 소절을 쓴다. 사람이 직접 설계한 것이 아니어서 받는 사람이 스킬의 판단과 까닭을 확인할 수 있어야 하기 때문이다
- 표가 아닌 개조식 글머리 묶음으로 쓴다. 꼴마다(또는 같은 판단으로 묶인 CQ 조각마다) 글머리 묶음 하나를 두고 다음을 적는다: 고른 꼴, CQ 꼴 표지, 설계 리포트 4.2절 원천 판정, 정한 단계(2장 고르는 차례), 버린 대안 꼴과 까닭(⑥에 함께 보였으면 그 대안), 줄인 꼴이면 뺀 꼴 요소
- 문장은 `~함`·`~임`으로 맺는다
- 원래 이름을 적지 않는 규칙은 이 소절에도 걸린다
