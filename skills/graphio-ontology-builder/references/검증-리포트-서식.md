# 검증 리포트 서식

검증 리포트는 **무엇을 검사했고 무엇이 지적되었는지 적는다.** 설계 리포트는 「이 구조가 왜 이렇게 생겼나」에 답한다. 이 문서는 「그 구조가 CQ에 답하고 서식대로 읽히는가」에 답한다.

세 문서를 나눈 까닭이 있다. 설계 판단과 검사 결과를 한 문서에 담으면, 읽는 사람이 **설계자가 스스로 매긴 점수**와 **검사로 나온 값**을 가려내지 못한다. 설계를 고칠 때 보는 문서와 넘겨받은 것을 믿어도 되는지 볼 때 보는 문서는 읽는 때도 읽는 사람도 다르다.

**무엇을 고쳐야 하는지는 이 문서가 판정하지 않는다.** 검사 결과에 등급을 매기는 일은 구조 판정 문서가 한다 — [`구조-판정-서식.md`](구조-판정-서식.md) 에 있다. 검사 기록과 등급을 한 문서에 담으면 「지적 15건」 이 고칠 일인지 규칙을 지킨 항목인지 갈리지 않는다.

**⑨ 단계가 이 문서를 통째로 쓴다.** 설계 단계(①~⑧)는 여기에 아무것도 적지 않는다.

**문서의 꼴과 문체는 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 를 따른다.** 해당 없는 절은 지우지 않고 「해당 없음」 한 줄로 남긴다. 절을 지우면 읽는 사람이 빠뜨린 것으로 읽는다. 「해당 없음」은 확인했는데 없다는 뜻이라 다르다.

## 뼈대

뼈대는 [`../assets/검증-리포트-뼈대.md`](../assets/검증-리포트-뼈대.md) 에 있다. **그 파일을 복사해 자리표시만 채운다.** 개조식 문장과 표는 그대로 옮긴다 — 받는 사람은 누구나 이 리포트를 처음 읽고, 스킬의 참고 문서도 볼 수 없다.

**자리표시는 괄호로 적은 설명이다** — 「(경로)」·「(구조 판정 문서 경로)」·「n건」·「YYYY-MM-DD」 같은 것. 채워서 바꾼다. 본문 문장 속의 괄호(2절 「필수 CQ 기준」 칸의 「(스킬 판단)」 같은 풀이)는 그대로 둔다.

**뼈대와 이 문서를 나눠 둔 까닭이 있다.** 뼈대 파일에는 산출물에 들어갈 말만 있고, 무엇을 어떻게 채우는지는 아래 「절마다 적을 것」 에만 있다. 한 파일에 섞여 있으면 지시문이 산출물로 새어 나간다.

**5절과 6절에는 판정 표를 하나만 둔다.** 판정 스크립트가 절 안에서 '판정' 열이 있는 첫 표를 읽는다. 판정값의 뜻은 1.3 에 있다.

**4.2절(지적 목록)에도 표를 하나만 둔다.** 표가 둘 이상이면 판정 스크립트가 판정하지 않고 멈춘다.

자리표시를 채울 때 빠뜨리기 쉬운 것:

- 3절 산출 규모 표는 `check_design_doc.py --stats` 가 낸 표를 그대로 붙인다. 손으로 세지 않는다
- 4.1절 검사 항목별 결과의 여섯 줄을 지우지 않는다
- 4.1절 No.1·No.2 행, `※ No.2 자동 채움:` 주석, 4.2절 스크립트 행, `※ 수집 조건:` 줄은 수집 스크립트 출력을 그대로 붙인다. 손으로 세거나 고치지 않는다

## 절마다 적을 것

### 모든 절에 — 이 리포트만 보고 알 수 있게 적는다

설계 리포트와 같은 규칙을 따른다([`설계-리포트-서식.md`](설계-리포트-서식.md) 「모든 절에」). 받는 사람은 스킬의 참고 문서를 볼 수 없고 입력 문서도 펴 두지 않는다. 검증 리포트에서 특히 틀리기 쉬운 곳이 셋이다.

| 잘못된 예 | 올바른 예 |
|---|---|
| ②의 값 표에서 뽑은 값 | 설계 리포트 4절의 사용 값 |
| ⑦에서 이은 매핑 | 정의 문서의 매핑 |
| 가이드 9장 12항 중 2항 걸림 | 스타일 가이드 검사 항목 12건 확인, 2건 지적. 지적 항목은 요구 내용을 함께 기재 |

**스킬의 단계 번호(①~⑨)를 적지 않는다.** 단계는 스킬 안의 차례라 받는 사람에게는 뜻이 없다. 그 단계가 만든 것을 문서 이름과 절로 가리킨다.

**리포트 안에 풀이가 있는 번호는 써도 된다.** 6절 판정 근거 앞의 1)~4) 는 1.3 이 풀어 두었으므로 번호로 적는다. 풀이가 리포트 밖에 있는 번호만 막는다.

### 문서 정보 표와 2절 — 필수 CQ와 구조 판정

**필수 CQ를 먼저 정한다.** 정하는 법은 [`입력-문서-읽기.md`](입력-문서-읽기.md) 2장 「필수 질문」 에 있다. 2절 「필수 CQ 기준」 칸에 무엇을 필수로 보았는지 적는다. 차례 ①(CQ 문서가 필수 등급을 밝혔다)이면 그 말을 적는다 — 「CQ 문서 등급 '상'」. 필수 등급이 둘 이상이면 말마다 작은따옴표로 싸서 쉼표로 잇는다 — 「CQ 문서 등급 '필수', '상'」. 차례 ②(등급만 매겼고 필수 등급은 밝히지 않았다)이면 스킬이 가장 높은 등급을 필수로 본 것이라 「CQ 문서 최고 등급 '상'(스킬 판단)」 이라 적는다. 차례 ③(등급이 없거나 높낮이를 가릴 수 없다)이면 「전체 CQ(필수 등급 판별 불가)」 라 적는다. ②·③ 이면 구조 판정 스크립트가 'CQ 등급 미확정' 을 Warning으로 올린다. **이 말을 구조 판정 스크립트의 `--required-grade` 에 그대로 넘긴다** — 양쪽이 같은 CQ를 필수로 보아야 판정이 맞는다.

**문서 정보 표의 참조 문서 행을 빠뜨리지 않는다.** 판정 스크립트가 설계 리포트·CQ 문서·원천 구조 문서·스타일 가이드·서식 가이드 다섯 행을 이 표에서 구조 판정 문서로 옮긴다. 행 이름을 바꾸지 않는다.

**'원천 구조 문서' 행에는 수집할 때 `--source`로 준 문서를 모두 적는다.** 원천 테이블과 컬럼을 적은 입력 문서로, 설계 리포트 3절의 정형 원천이다. 받지 않았으면 「해당 없음」으로 적는다. 판정 스크립트는 이 행에 문서가 있는데 `--source`를 받지 못하면 판정하지 않고 멈춘다. 텍스트로 읽을 수 없는 형식이면 수집 조건에 「대조 불가(형식)」로 남고 원천 구조 문서 대조(DOC-08)는 미수행이 된다.

**「필수 CQ 기준」 칸의 작은따옴표 안 말을 판정 스크립트가 `--required-grade` 와 맞대 본다.** 둘이 다르면 판정하지 않고 멈춘다. 등급 말은 따옴표 안에만 적고, 전체 CQ를 필수로 보았으면 따옴표를 쓰지 않는다.

**2절 「검사 수행 결과」 칸은 4.1절 여섯 줄을 센 것이다.** No.1은 Error 0건이면, No.2는 변환에 성공하고 규격 Error가 0건이면 통과로 센다 — Warning·Info는 통과로 센다. 통과도 미수행도 아닌 줄은 「Error·지적」으로 센다. 건별 내용은 4.2절에 있다. No.3~6은 결과 칸이 `통과` 인 줄만 통과로 센다.

**2절 「지적 목록」 칸은 4.2절 표의 행 수다.** 스크립트 행과 스킬 행을 나눠 「8건 중 스크립트 6건, 스킬 2건」처럼 적는다. 지적이 없으면 「해당 없음」으로 적는다.

**2절 「필수 CQ 응답」·「필수 CQ 미응답」 칸은 5절에서, 「매핑 컬럼 대조」 칸은 6절에서 센다.** 필수 CQ 응답은 필수 CQ 수와 그 가운데 `응답 가능` 수, 5절 전체 CQ 수다. 필수 CQ 미응답은 필수 CQ 가운데 `부분 응답`·`응답 불가` 수이고 둘 다 0이면 「해당 없음」이다. 매핑 컬럼 대조는 6절 행 수와 판정별 행 수이고 미매핑은 미매핑 판정 셋을 더한 수다. 0건인 판정도 적는다. 6절에 표가 없으면(매핑 단계 미수행) 「미수행」이다.

**2절의 건수 칸은 판정 스크립트가 다시 세어 맞대 본다.** 필수 CQ 응답, 필수 CQ 미응답, 매핑 컬럼 대조, 지적 목록, 검사 수행 결과가 그렇다. 하나라도 다르면 판정하지 않고 멈춘다. 손으로 세면 틀리기 쉬운 칸이라 스크립트가 맞대 본다.

**2절 「구조 판정」 칸은 판정 문서를 가리키기만 한다.** 이 리포트를 다 쓴 뒤 판정 스크립트를 수행해, 나온 판정과 문서 경로를 옮겨 적는다. 판정 스크립트는 이 칸을 읽지 않으므로 판정하기 전에는 뼈대의 자리표시를 그대로 둔다. **까닭은 여기 적지 않는다** — 무엇이 지적되어 그런 판정이 나왔는지는 판정 문서 3절이 갖는다. 두 문서가 같은 까닭을 각자 적으면 한쪽을 고칠 때 다른 쪽이 낡는다.

판정을 무엇으로 가르는지, 어느 검사 결과가 Error이고 어느 것이 조치 대상 외 항목인지는 [`구조-판정-서식.md`](구조-판정-서식.md) 에 있다.

### 3. 산출 규모 — 세지 말고 뽑는다

`check_design_doc.py --stats` 가 낸 표를 그대로 붙인다. 같은 표를 정의 문서 맨 앞에도 붙인다.

**정의 문서 맨 앞의 표는 수집 전에 붙인다**(SKILL.md ⑨ 차례 1). 수집 뒤에 정의 문서를 고치면 규모 표나 서식 밖 절만 고쳐도 수집 조건의 정의 문서 해시가 달라져 판정 스크립트가 멈춘다. 맨 앞에 표가 들어가면 모든 줄 번호도 밀린다. 수집 뒤에 정의 문서를 고쳤으면 `--stats`로 규모 표를 먼저 갱신한 뒤 다시 수집한다.

**손으로 세면 틀린다.** 개념과 속성이 늘면 사람이 정확히 세지 못하고, 틀려도 아무도 알아채지 못한다. 스크립트가 세면 두 문서의 숫자가 어긋날 일도 없다.

이 표는 규모만 보여 주는 것이 아니라 **신호**로도 읽는다.

| 값 | 의미 |
|---|---|
| 데이터가 붙지 않은 개념 | 아직 데이터가 없는 개념이다. 설계 리포트 7.1절에 그 개념이 쓸 메타타입이 적혀 있는지 본다 |
| 확인 필요 표기 | 참고 문서가 모자라거나, 알 수 없는 것을 억지로 만들었다 |
| 식별 속성이 있는 개념이 적다 | 관계가 의도보다 넓게 퍼질 수 있다. 규격 검증의 경고와 함께 본다 |
| 대표 표시 속성이 1건이 아닌 개념 | 0이어야 한다. 0이 아니면 반입이 막힌다 |

**「확인 필요 표기」 를 줄이려고 값을 채우지 않는다.** 이 수가 크다는 것은 다음 단계에서 확인할 일이 많다는 뜻이지 설계가 덜 됐다는 뜻이 아니다. 모르는 값을 `확인 필요` 로 둔 것은 규칙을 지킨 것이고, 그럴듯한 값을 채워 이 수를 줄인 것이 규칙을 어긴 것이다. CQ가 요구하지 않는데 만든 것이 있으면 그것만 고치고, 그 밖의 항목은 7.4절로 옮긴다.

### 4.1 검사 항목별 결과 — 했다는 것을 남긴다

검증 리포트 4절은 4.1 검사 항목별 결과와 4.2 지적 목록 두 소절로 나눈다. 4.1은 검사마다 한 줄로 결과를 남기고 4.2는 검사가 찾은 문제를 위치마다 한 행으로 모은다.

**여섯 줄을 지우지 않는다.** 하지 않은 검사도 줄을 남기고 결과 칸에 「미수행」, 지적 내용 칸에 사유를 적는다.

짚기만 하고 흔적을 남기지 않으면 짚었는지 건너뛰었는지 아무도 알 수 없다. 여섯 검사가 각각 무엇을 잡는지는 SKILL.md ⑨ 에 있다 — No.1 정의 문서 검사가 「조용히 사라지는 항목」, No.2 서식 변환 검사가 「서식이 실제로 읽히는가」, No.3 가이드 준수 검사가 「가이드의 규칙을 지켰는가」, No.4 CQ-구조 정합성 검사가 「질문과 구조가 맞물리는가」, No.5 CQ 통과 조건 검사가 「CQ 문서가 정한 통과 조건을 지켰는가」, No.6 매핑 의미 검사가 「뜻이 다른 컬럼으로 대신 답하지 않았는가」 다.

**No.1·No.2 행은 수집 스크립트가 낸 행을 그대로 붙이고 No.3~6 행은 스킬이 적는다.** 수집 스크립트(`scripts/collect_findings.py`)가 정의 문서 검사와 서식 변환 검사를 한 번에 수행한다. 두 행은 손으로 고치지 않는다([`리포트-작성-규칙.md`](리포트-작성-규칙.md) 4장).

```bash
python3 scripts/collect_findings.py <정의 문서> --converter <converter 스킬 폴더> [--source <원천 구조 문서> …] [--warn-mark <기호>]
# converter 스킬이 없으면 --converter 대신 --spec-skipped 를 준다
```

- 명령은 스킬 폴더에서 수행하는 꼴로 적었다. 수행하는 폴더에 따라 스크립트와 converter 경로, 파일 경로를 주는 법은 SKILL.md 2.5에 있다
- 출력은 `[4.1 검사 항목별 결과]`·`[4.1 표 아래 주석]`·`[4.2 지적 목록]` 같은 대괄호 머리말 아래에 붙일 조각을 둔다. 대괄호 머리말 줄은 붙이지 않는다
- 수집하면 지적이 있어도 종료 코드 0이다. 멈추면 종료 코드 2로 끝나고 표준 오류의 '수집하지 않음:' 줄에 까닭을 낸다. 멈췄으면 검증 리포트에 손으로 적지 않는다
- 둘째 줄이 할 일을 가른다. '입력이나 옵션을 고친 뒤 다시 수행한다.'로 시작하면 아래 첫 갈래이고, '스킬 스크립트·규칙 목록 문서·converter 쪽 문제라'로 시작하면 둘째 갈래다. 예상하지 못한 오류로 멈춘 것도 둘째 갈래로 나온다
- 까닭이 옵션·파일 경로·정의 문서에 있으면 고쳐 다시 수행한다
- 까닭이 스킬 스크립트·규칙 목록 문서·converter 쪽에 있으면 입력을 고쳐도 풀리지 않는다. 변환표에 없는 코드나 메시지, 색인과 변환 스크립트가 정의 문서를 다르게 읽음, 경로를 정의 문서 위치로 되돌리지 못함, 규격 검사기가 짚은 대상 수가 색인과 다름, 하위 스크립트 출력에 칸이 없음, 규칙 목록 문서 확인에 걸림이 그렇다. 하위 스크립트(정의 문서 검사기·변환 스크립트·규격 검사기)가 시간 안에 끝나지 않거나, 수행되지 못하거나, 0이 아닌 종료 코드로 끝나거나, JSON을 내지 못한 것도 여기에 든다. 스크립트와 규칙 목록 문서를 고치지 말고 까닭을 사용자에게 알리고 멈춘다

| 칸 | 기재 내용 |
|---|---|
| 결과 | No.3~6은 `통과` · `지적 n건` · `미수행` 셋 중 하나다. `지적 n건`의 n은 아래 표대로 센다. No.1·No.2는 수집 스크립트가 낸 값이다 |
| 지적 내용 | 지적된 것이 무엇인지, 또는 자세한 결과를 적은 절. 통과면 확인 범위(「검사 항목 12건 확인」)를 적는다. **두 문장 이내로 요약한다** — 확인한 항목 목록, 고쳐서 다시 수행한 경위 같은 상세는 표 아래 `※ No.n` 주석으로 옮긴다 |

검사마다 결과 칸에 적는 법이 다르다.

| 검사 | 결과 기재 방법 |
|---|---|
| No.1 정의 문서 검사 | 뼈대의 No.1 행을 수집 스크립트가 낸 행으로 바꾼다. 결과와 지적 내용을 모두 수집 스크립트가 정한다(결과 꼴은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 4장). 고쳐서 다시 수행했으면 **마지막에 수집한 행**으로 바꿔 붙이고 무엇을 고쳤는지는 표 아래 `※ No.1` 주석에 적는다 |
| No.2 서식 변환 검사 | 뼈대의 No.2 행을 수집 스크립트가 낸 행으로 바꾼다. 변환에 성공하고 변환 스크립트가 채운 값이 있으면 `※ No.2 자동 채움:` 주석도 나오므로 표 아래에 붙인다. 결과 꼴은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 4장에 있다. 건별 코드와 위치는 4.2절 행에 있으므로 주석에 옮겨 적지 않는다. **Warning은 의도한 것인지 짚는다.** 의도했으면 표 아래 `※ No.2 Warning 확인:` 주석에 4.2절 No.와 함께 적는다. **Info(규격 검사 보류)는 7.1절에도 올린다.** converter 스킬이 없으면 `--spec-skipped`로 수집한다. 그때 수집 스크립트는 결과 `미수행`, 지적 내용 「converter 스킬 없음」인 행을 낸다 |
| No.3 가이드 준수 검사 | 확인한 검사 항목 수와 지적 수를 적는다. 지적된 위반은 위치마다 4.2절에 GDE-01(스타일 가이드)·GDE-02(서식 가이드) 행으로 적는다. 결과 `지적 n건`의 n은 그 행 수다. 지적 내용에는 「스타일 가이드 검사 항목 19건 확인. C-01(이름이 원천 컬럼명과 같음) 지적 2건, 가이드 규칙 R-01 위반」 처럼 **무엇을 요구하는 항인지** 함께 적는다. 번호와 괄호 속 뜻은 가이드 원문 그대로 쓰고 검사 항목이 점검하는 가이드 규칙 번호를 함께 적는다([`리포트-작성-규칙.md`](리포트-작성-규칙.md) 5장). 값이 채워졌는지 묻는 검사 항목이면 **`확인 필요` 라고 적은 항목은 빈 값으로 보지 않는다** — 모른다고 적는 것이 가이드의 규칙을 지킨 것이다. `확인 필요`가 남았는지를 직접 묻는 항(기본 가이드 C-11)은 지적 내용에만 적고 4.2절 행과 지적 수에 넣지 않는다. 그 건수는 3절 「확인 필요 표기」가 갖는다. 스크립트 행이 이미 짚은 위반과 CQS 규칙이 보는 결함을 묻는 항(기본 가이드 C-12·C-13)도 지적 내용에만 적고 행과 지적 수에 넣지 않는다 — 「검사 항목 C-08은 4.2절 No.3(DOC-06)으로 적힘」([`검사-규칙.md`](검사-규칙.md) 4절). 서식 가이드에 번호 붙은 검사 항목이 없으면 확인한 절을 적는다 — 「서식 가이드 4~7장 확인」. 그 가이드의 위반은 GDE-02 행의 외부 코드 칸에 절 번호로 적는다 |
| No.4 CQ-구조 정합성 검사 | 5절과 4.2절을 가리킨다. 결과 `지적 n건`의 n은 5절에서 응답 경로나 답이 빠져 `응답 불가`·`부분 응답`으로 판정한 CQ 수와 4.2절 CQS-05 행 수를 더한 값이다. 어느 CQ도 쓰지 않는 개념·속성은 요소마다 4.2절에 CQS-05 행으로 적고 지적 내용에 그 수를 적는다 |
| No.5 CQ 통과 조건 검사 | 5절을 가리킨다. 결과 `지적 n건`의 n은 CQ 문서가 건 통과 조건을 지키지 못해 `부분 응답`으로 판정한 CQ 수다. 홉 수 조건은 **설계 리포트 4절의 홉 수 칸**과 맞대 본다. 스크립트가 세지 않는 조건을 몇 건 확인했는지 적는다. CQ 문서가 **CQ마다 다른 조건**을 걸어 두었으면 CQ마다 건 조건을 하나씩 짚고, 지키지 못한 조건은 5절 그 CQ의 누락 항목 칸에 조건의 말로 적는다. 「통과」 한 줄만 적으면 어느 CQ의 어느 조건을 짚었는지 되짚을 수 없다. 경로가 없어 `응답 불가`로 판정한 CQ는 통과 조건을 짚을 수 없으므로 여기서 세지 않는다. No.4가 세고, 지적 내용에 「경로 없는 CQ 2건은 통과 조건 확인에서 뺌」처럼 적는다 |
| No.6 매핑 의미 검사 | 6절을 가리킨다. 결과 `지적 n건`의 n은 6절에서 판정이 `일치`가 아닌 행 수다. 매핑 단계를 건너뛰어 6절에 표가 없으면 결과는 `미수행`이다. 결과와 6절 표 유무가 맞지 않거나 n이 6절에서 다시 센 수와 다르면 판정 스크립트가 멈춘다 |

**「통과」 를 적을 때는 무엇을 읽고 그렇게 보았는지가 남아 있어야 한다.** 가이드 준수 검사처럼 사람이 짚는 것이 특히 그렇다. 몇 건을 확인했는지 적지 않으면 짚지 않고 통과로 적은 것과 구분되지 않는다.

**판정 스크립트가 No.3과 No.6의 n을 다시 세어 맞대 본다.** No.3은 4.2절 GDE-01·02 행 수, No.6은 6절에서 판정이 `일치`가 아닌 행 수다. 다르면 판정하지 않고 멈춘다. No.4·No.5는 맞대 보지 않는다. `부분 응답`이 응답 경로나 답이 빠진 것인지 통과 조건을 지키지 못한 것인지는 스킬이 가르기 때문이다.

**4.1 표 아래 ※ 주석은 No. 차례로 둔다.** No.2에 자동 채움 주석과 Warning 확인 주석이 함께 있으면 자동 채움 주석을 먼저 둔다.

### 4.2 지적 목록 — 위치마다 한 행으로 모은다

**검사가 찾은 문제를 위치마다 한 행으로 이 표에 모은다.** 칸의 뜻과 위치·발생 경로 표기는 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장에 있다. 규칙마다 발생 경로를 쓰는 방식과 조치 지침은 [`검사-규칙.md`](검사-규칙.md) 3절에 있다.

**스크립트 행을 먼저 붙이고 스킬 행을 그 뒤에 둔다.** 두 행의 뜻은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장에 있다.

- 뼈대의 4.2 머리글과 `※ 수집 조건:` 자리표시를 수집 스크립트 출력의 `[4.2 지적 목록]` 조각으로 바꾼다. 조각은 머리글을 포함한 표, 빈 줄, `※ 수집 조건:` 줄이다
- 스킬 행은 표 끝에 이어 붙이고 No.를 이어 매긴다
- 스크립트 행이 없으면 표 대신 「해당 없음」 한 줄이 나온다. 스킬 행이 있으면 그 줄을 4.2 머리글로 바꾸고 No.1부터 적는다. 스킬 행도 없으면 「해당 없음」을 그대로 둔다
- 스킬 행은 규칙 번호 차례(GDE-01, GDE-02, CQS-05, INP-01)로 둔다. 같은 규칙 안에서는 근거 문서의 차례를 따른다. GDE는 가이드 검사 항목 차례와 그 안의 정의 문서 줄 차례, CQS-05는 정의 문서 줄 차례, INP-01은 설계 리포트 11절 No. 차례다

**스킬 행은 네 규칙만 적는다.** 가이드 준수 검사(4.1 No.3)에서 지적된 위반은 GDE-01·02 행으로 적는다. CQ-구조 정합성 검사(4.1 No.4)에서 찾은 미사용 개념·속성은 CQS-05 행으로 적는다. 설계 리포트 11절에서 어느 쪽을 따를지 정해지지 않은 항목은 INP-01 행으로 적는다. CQ별 판정과 매핑 대조에서 나오는 지적은 판정 스크립트가 5·6절과 2절에서 정하므로 4.2절에 적지 않는다([`검사-규칙.md`](검사-규칙.md) 1절).

- 스크립트 행이 이미 짚은 결함은 스킬 행으로 다시 적지 않는다([`검사-규칙.md`](검사-규칙.md) 4절)
- 외부 코드의 종류는 [`검사-규칙.md`](검사-규칙.md) 2절에, 가이드 항목 번호를 적는 꼴은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 5장에 있다
- 참고 자료에는 규칙 원문이나 근거가 있는 곳을 적는다. GDE는 가이드의 해당 절, CQS-05는 개념이면 설계 리포트 5.1절이고 속성이면 설계 리포트 4절과 5.3절, INP-01은 설계 리포트 11절의 해당 No.다

스킬 행은 아래처럼 적는다. 앞의 네 행은 스크립트 행이다.

```markdown
| No. | 규칙 | 외부 코드 | 위치 | 문제 설명 | 발생 경로 | 조치 방안 | 조치 주체 | 참고 자료 |
|---|---|---|---|---|---|---|---|---|
| 5 | CQS-05 | 해당 없음 | 개념 '자격증'(정의 문서 88줄) | 어느 CQ도 쓰지 않는 개념임. CQ가 요구하지 않은 구조가 확정 뒤에도 남음 | 개념 '자격증' → 쓰는 CQ 없음(설계 리포트 5.1절 근거 CQ 빈칸) | 정의 문서에서 개념 삭제 | 설계 담당 | 설계 리포트 5.1절(개념 목록) |
| 6 | INP-01 | 해당 없음 | 개념 '교육'(정의 문서 40줄) | 두 입력 문서가 이 개념의 범위를 다르게 적어 어느 쪽을 따를지 정해지지 않음. 범위에 따라 질의의 답이 달라짐 | 용어 자료 '표제어' 표: 사내 교육만 교육으로 적음 ↔ 업무 이해서 '교육 운영' 절: 외부 위탁 교육도 교육으로 적음 | 용어 자료 작성자가 정한 뒤 개념 설명과 별칭 유지 또는 변경 | 용어 자료 작성자 | 설계 리포트 11절 No.1 |
```

**`※ 수집 조건:` 줄은 고치지 않는다.** 수집할 때의 정의 문서 해시, 경고 기호, 규격 검사 수행 여부와 converter 판본 해시, 원천 구조 문서, 빌더 판본 해시를 적은 한 줄이다. 원천 구조 문서는 경로와 해시로 적힌다. 받지 않았으면 「없음」, 텍스트로 읽을 수 없으면 「대조 불가(형식)」로 적힌다. 판정 스크립트가 판정할 때의 조건으로 이 줄을 다시 만들어 맞대 보고 다르면 원인별로 멈춘다. 원인 여섯 가지와 할 일은 [`구조-판정-서식.md`](구조-판정-서식.md) '판정하지 않고 멈추는 경우'에 있다.

**정의 문서를 고쳐 다시 수행하면 수집 스크립트 출력을 통째로 바꿔 붙인다.** 4.1 No.1·No.2 행, `※ No.2 자동 채움:` 주석, 4.2절 스크립트 행, `※ 수집 조건:` 줄이 모두 바뀐다. 고친 내용에 맞춰 5·6절과 스킬 행도 다시 본다.

### 5. CQ별 판정 — 구조가 답하는가

**CQ 하나가 한 줄이다.** 구조에서 시작하지 않고 CQ에서 시작하는 것이 중요하다. 그래야 답하지 못하는 CQ가 눈에 띈다.

CQ가 어느 값을 쓰고 **어느 경로로 답에 이르는지는 설계 리포트 4절**에 있다. 여기에는 판정과 그 까닭, 끊긴 곳과 조치 방안만 적는다. 같은 표를 두 번 싣지 않는다.

**CQ 칸에는 번호와 짧은 내용을 함께 적는다** — 「CQ-01 교육별 참석 사원」. 판정 스크립트가 이 칸에서 앞의 CQ 번호를 뺀 글을 구조 판정 문서의 문제 설명에 옮긴다(「'교육별 참석 사원' 응답 불가. 필수 CQ라 확정을 막음」). CQ 번호는 위치 칸에 적힌다.

**판정은 그 경로를 짚어 내린다.** 설계 리포트 4절의 경로 칸이 「경로 없음」 이면 `응답 불가` 다. CQ가 그 CQ에 건 **경로 조건**을 지키지 못하면 `부분 응답` 이다 — 홉 수를 넘거나, 관계를 거쳐야 한다고 했는데 거치지 않는 경우가 그렇다. 경로가 아닌 요구는, CQ 옆 칸에 있든 CQ 문서가 따로 적어 둔 통과 조건 절에 있든 아래 「CQ 옆 칸이 요구한 것도 이 칸에 넣는다」 가 정한다. 경로가 있고 조건을 지키면 그다음으로 데이터를 본다 — 아래 두 경우가 그것이다. 경로를 보지 않고 판정하면 무엇을 근거로 `응답 가능` 이라 했는지 남지 않는다.

`판정` 칸이 이 표의 목적이다. 값은 1.3 의 셋뿐이다.

**`응답 불가` 이거나 `부분 응답` 인 필수 CQ가 있으면 설계가 끝나지 않은 것이다.** 리포트에 적고 넘기지 말고, 구조를 고칠지 CQ를 필수에서 내릴지 사용자에게 알린다.

**CQ 옆 칸이 요구한 것도 이 칸에 넣는다.** 본문이 요구하는 답이 모두 나와도, CQ 옆 칸이 요구한 것을 만들지 못했으면 `응답 가능` 이 아니라 `부분 응답` 이다. 두 개념을 맞대 보라는 칸이 그런 예다([`개념을-더-둘-때.md`](개념을-더-둘-때.md) 4장). 무엇이 빠졌는지와 근거를 적은 절을 함께 적고, 필수 CQ면 7.3절에도 올린다. 본문만 보고 `응답 가능` 으로 적으면 채우지 못한 요구가 표에서 사라진다.

**구조는 답하는데 데이터가 아직 없는 경우는 `응답 가능` 으로 적는다.** 그 대신 설계 리포트 7.1절의 어느 항목이 채워져야 하는지를 근거 칸에 적는다. 구조와 데이터는 따로 본다 — 개념이 먼저 완성되고 데이터가 뒤따라오는 것이 정상이다.

**CQ가 쓰는 값의 컬럼이 원천에 없거나 있는지 몰라 매핑을 비운 경우도 `응답 가능` 이다.** 설계 리포트 7.2절에 그 컬럼이 올라 있는지 보고, 올라 있으면 근거 칸에 그 항목을 가리킨다. 올라 있지 않으면 `부분 응답` 이다.

거꾸로도 본다. **어느 CQ도 쓰지 않는 개념이나 속성이 있으면** 그것은 만들지 말았어야 할 것이다. 개념은 설계 리포트 5.1절에서 `근거 CQ` 칸이 빈 행이다. 속성은 설계 리포트 4절 `사용 속성` 칸에도 5.3절(CQ 외 추가 속성)에도 없는 속성이다. 찾으면 요소마다 4.2절에 CQS-05 행으로 적고 4.1 No.4 결과에 센다.

| 칸 | 기재 내용 |
|---|---|
| 출처·등급 | 설계 리포트 4절의 같은 CQ 행과 같게 적는다. 출처는 그 CQ가 적힌 CQ 문서, 등급은 CQ 문서가 매긴 말이고 없으면 「-」다. 판정 스크립트가 등급 칸을 `--required-grade`와 맞대 본다 |
| 누락 항목 | 부분 응답·응답 불가일 때 빠진 조건이나 답. 응답 가능이면 「해당 없음」 |
| 위치 | 부분 응답·응답 불가일 때 끊긴 곳. [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장의 CQ 지적 위치 꼴로 적는다. 응답 가능이면 「해당 없음」 |
| 근거 | 그렇게 판정한 까닭. **모든 줄을 채운다** — 응답 가능인 줄에는 짚은 경로와 홉 수를 적고 설계 리포트의 절을 가리켜도 된다. 아닌 줄에는 끊긴 곳까지의 경로를 [`검사-규칙.md`](검사-규칙.md) 3절 CQS-01~04의 발생 경로 표기대로 적는다. 이 칸은 구조 판정의 발생 경로가 된다([`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장 발생 경로 표기) |

**부분 응답·응답 불가 행의 위치와 조치 방안을 비우지 않는다.** 비었으면 판정 스크립트가 판정하지 않고 멈춘다. 위치를 해석하는 규칙은 [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 7장에 있다. 응답 가능 행에 「해당 없음」 밖의 값이 있어도 멈춘다. 규칙 번호는 적지 않는다([`검사-규칙.md`](검사-규칙.md) 1절).

### 6. 매핑 컬럼 대조 결과

②가 모은 값마다(답과 조건 모두) 그 값을 담은 속성이 **매핑한 컬럼**과 뜻이 같은지 보고, **본 결과를 한 줄씩 남긴다.** 짚기만 하고 표를 쓰지 않으면 짚었는지 건너뛰었는지 아무도 알 수 없다. 대체 매핑은 매핑이 채워져 있어 겉으로는 멀쩡해 보이므로, 이 표가 없으면 읽는 사람이 되짚을 곳조차 모른다.

**이 절은 「해당 없음」으로 남기지 않는다.** 매핑이 하나라도 있으면 맞댈 값이 있다. 비는 경우는 ⑦을 통째로 건너뛴 때뿐이고, 그때는 「매핑 단계 미수행. 원천 구조 문서 미제공」 이라고 사유까지 적는다. 그냥 「해당 없음」은 맞대 보지 않았다는 뜻으로 읽는다.

**뜻이 같은지는 속성 이름이 아니라 매핑한 컬럼으로 가린다.** 속성 이름을 값과 똑같이 지어도, 매핑한 컬럼이 다른 뜻이면 대체 매핑이다. 값이 관계를 거쳐 나오면 그 관계의 조인 속성이 매핑한 컬럼도 본다. 값 이름을 슬쩍 바꿔 적어도, 컬럼을 슬쩍 바꿔 이어도 읽는 사람은 원천에 그 값이 있는 줄 안다.

가르는 차례는 넷이다(1.3 의 판별 순서). 위에서부터 짚어 **처음으로 답이 나온 것 하나**를 쓴다.

**1) 스타일 가이드·입력 문서의 결정 사항** — 두 말을 같은 대상으로 정해 두었으면 그것을 따르고 여기서 끝난다. 사전이 `용량` 을 `부품용량` 밑에 두었어도, 가이드가 `용량` 을 `설비정격출력` 으로 부르게 정했으면 잇는다. 결정 사항을 알아보는 법은 [`입력-문서-읽기.md`](입력-문서-읽기.md) 1장에 있다. 사전과 갈렸다는 사실은 설계 리포트 11절에 적는다. **정해 둔 것이 없으면 2) 로 간다.** 결정 사항이 가장 앞에 오는 까닭은, 문서를 쓴 사람이 두 말의 관계를 이미 정했는데 사전의 분류로 뒤집으면 그 결정이 사라지기 때문이다.

**2) 용어 사전** — 값과 컬럼 이름이 모두 사전에 글자 그대로 있어야 이것으로 가른다. 표제어나 실무 표현에 띄어쓰기만 다르고 같은 글자로 있을 때만 본다. 둘이 서로 다른 표제어 밑에 있으면 뜻이 다르다. 말을 쪼개거나 끝말을 떼어 찾지 않는다 — 찾는 법이 실행마다 달라지면 멀쩡한 매핑이 끊긴다.

**3) 원천 문서의 컬럼 설명** — 한쪽이라도 사전에 없으면 컬럼 설명으로 뜻을 본다.

**4) 컬럼 이름이 가리키는 업무 절차** — 설명이 값의 갈래(시점·금액 같은 것)만 적어 뜻을 가르지 못할 때 본다. `입고일시` 는 입고의 시점이지 출고의 시점이 아니다.

원천 문서가 그 CQ에 답할 값이 있다고 적었어도 이 판단은 바꾸지 않는다. 이것은 두 문서 가운데 하나를 고르는 일이 아니라 매핑 판단이라서 「고르지 않는다」 규칙에 들지 않는다. 설계 리포트 11절에는 기록만 남긴다.

**가린 결과를 표로 남긴다.**

| 칸 | 기재 내용 |
|---|---|
| 값 | ②가 모은 값. 답과 조건을 가리지 않는다 |
| 사용 CQ | 그 값을 쓰는 CQ 번호를 모두 적는다 |
| 대상 속성 | 그 값을 담은 `개념 · 속성`. 설계 리포트 7.2절의 `사용 개념·속성` 과 같은 이름으로 적는다. 미매핑 행도 정의 문서에 있는 속성을 적는다. 판정 스크립트가 모든 행의 대상 속성을 정의 문서에서 찾고 없으면 멈춘다 |
| 매핑 컬럼 | 이은 컬럼을 '데이터 구조.컬럼' 꼴로 적는다(「hr.TB_휴가신청내역.신청자번호」). 판정 스크립트가 정의 문서의 매핑과 맞대 보고 다르면 멈춘다. 잇지 않았으면 **설계 리포트 7.2절에 올린 컬럼 이름**을 같은 '데이터 구조.컬럼' 꼴로 적는다 — 그래야 7.2절과 맞댈 열쇠가 생긴다 |
| 판정 | `일치` · `의미 불일치 미매핑` · `원천 부재 미매핑` · `원천 확인 필요 미매핑` 넷 중 하나. `대체 매핑` 은 고치지 않고 넘기기로 정했을 때만 남는다 |
| 판정 근거 | 위 차례의 번호와 무엇을 보았는지. 1) 은 가이드의 항 번호나 결정 사항 번호와 그 내용, 2) 는 표제어, 3) 은 컬럼 설명, 4) 는 그 컬럼이 가리키는 업무 절차를 적는다. `의미 불일치 미매핑` 이면 **대체 후보였던 컬럼 이름**도 적는다. 대체 후보가 있었으면 `의미 불일치 미매핑`, 없었으면 `원천 부재 미매핑` 이다 |
| 조치 방안 | 대체 매핑 행에만 적는다. [`검사-규칙.md`](검사-규칙.md) 3절 MAP-01의 조치 지침을 따른다. 비우면 판정 스크립트가 멈춘다. 나머지 행은 「해당 없음」이고 미매핑의 후속 조치는 7.2절이 갖는다 |

**설계 리포트 4절 응답 경로에 나온 관계마다 조인 속성 쌍을 대조한다.** 한 행에는 관계 하나만 둔다. 값 칸에는 「부서와 사원을 잇는 값」 처럼 두 개념을 잇는 값이라고 적고, 대상 속성·매핑 컬럼 칸에는 출발·도착 양쪽을 같은 차례로 쉼표로 이어 적는다. 판정 스크립트가 쉼표 차례대로 짝지어 정의 문서와 맞대 본다. 조인 속성이 다른 뜻의 컬럼에 이어져 있으면 관계가 엉뚱한 개체를 잇는데, 값 행만 보면 드러나지 않는다.

- 조인 속성이 곧 CQ가 묻는 값이면 그 값 행이 쌍 행을 겸한다. 대상 속성·매핑 컬럼 칸에 양쪽을 적는다
- 응답 경로의 관계가 정의 문서에 없으면(5절 위치에 `관계(없음)`으로 적은 끊긴 곳) 맞댈 조인 속성이 없으므로 조인 쌍 행을 두지 않는다
- 양쪽 판정이 같고 `대체 매핑`이 아니면 한 행에 적는다. 양쪽 판정이 다르거나 한쪽이라도 `대체 매핑`이면 쪽마다 한 행으로 나눈다. 대체 매핑인 쪽이 따로 한 행이 되어야 판정 스크립트가 그 매핑의 위치를 찾고 다른 쪽의 판정에 묻히지 않는다

**6절에는 위치 칸을 두지 않는다.** 대체 매핑 행은 판정 스크립트가 대상 속성과 매핑 컬럼으로 정의 문서의 매핑 행을 찾아 위치를 채운다. 미매핑 행의 대상 속성에 정의 문서의 매핑이 있어도 판정 스크립트가 멈춘다. 규칙 번호는 적지 않는다([`검사-규칙.md`](검사-규칙.md) 1절).

`일치` 가 아닌 줄이 이 표의 목적이다. 그 줄이 하나도 없으면 정말 없는 것인지 짚지 않은 것인지 다시 본다.

**`대체 매핑` 은 구조를 확정하지 못하게 막는다.** 구조 판정 문서가 이 줄을 Error로 센다. 뜻이 다른 것을 알았으면 매핑을 비우고 설계 리포트 7.2절에 필요한 컬럼으로 올리는 것이 맞고, 그러면 판정이 `의미 불일치 미매핑` 으로 바뀐다.

**판정 근거는 차례 번호로 적는다.** 「비슷해서」·「이름이 같아 보여서」처럼 번호 없이 적힌 줄은 가리지 않은 것이다. 글자가 아주 같은 값은 아래 묶는 줄로 보낸다 — 거기서만 이름이 같다는 것이 근거가 된다.

**설계 리포트 4절 `사용 속성` 칸에 나온 속성은 빠짐없이 이 표에 한 번 이상 나온다.** 한 속성이 여러 값에 쓰이면 값마다 나온다. 맞댈 원본이 있어야 빠뜨린 값이 보인다. ②의 표는 어디에도 남지 않으므로 설계 리포트 4절이 그 자리를 대신한다.

**값 이름과 컬럼 이름이 띄어쓰기만 빼고 글자 그대로 같은 값들은 한 줄에 모아도 된다.** 그때도 값 이름과 컬럼 이름을 **모두 적는다.** 대상 속성은 `개념 · 속성`을, 매핑 컬럼은 '데이터 구조.컬럼'을 같은 차례로 쉼표로 이어 적는다(조인 쌍 행과 같은 꼴). 판정 스크립트가 두 칸을 쉼표로 나눠 차례대로 짝지어 정의 문서에서 찾기 때문이다. 「나머지 값」으로 뭉뚱그리거나 글자가 다른 값을 「이름이 같다」며 끌어들이면, 표가 있어도 어느 값을 짚었는지 사라진다.

**미매핑인 줄은 설계 리포트 7.2절에 그 컬럼이 올라 있어야 한다.** 표와 7.2절이 어긋나면 둘 중 하나는 틀린 것이다.

### 7. 후속 조치

사람이 이어서 할 일을 네 갈래로 나눠 표로 옮긴다. 설계 리포트 7절의 추가 필요 메타타입, 8절의 확인 필요 사항, 원천 확보와 수집 시험, 대상 환경에서 확인할 데이터 구조 이름 같은 것들이다. **4.2절의 규격 검사 보류(SPC-03)와 대상 환경 미생성 데이터 구조(DOC-09)도 올린다.** 보류를 빠뜨리면 인수 측은 반입이 왜 막히는지 모른다.

| 소절 | 기재 대상 |
|---|---|
| 7.1 대상 환경 조치 | 데이터 구조 만들기, 스키마 이름 확인, 규격 검사의 보류 |
| 7.2 원천 조치 | 컬럼 더하기, 사내 원천 확보, 수집 시험 |
| 7.3 의사결정 필요 사항 | CQ 등급 확정, 어느 문서를 무엇으로 볼지 정하기, 가이드와 부딪히는 항목 정리 |
| 7.4 데이터 확인 후 기재 사항 | `확인 필요` 로 남긴 값 |

**고쳐야 할 항목은 이 표에 넣지 않는다.** 답하지 못하는 필수 CQ, 대체 매핑, 규격 오류가 그렇다. **구조를 고쳐야 풀리는 것**은 구조 판정 문서 3절의 몫이다. 성격이 다른 둘을 한 목록에 담으면 받는 사람이 무엇을 꼭 해야 하는지 가려내지 못한다. 이 절이 길어지는 것은 정상이다 — 길다는 것이 구조가 덜 됐다는 뜻은 아니다.

**소절 네 개를 모두 남긴다.** 해당 없는 소절은 소제목을 남기고 「해당 없음」 이라 적는다. 갈래에 들지 않는 일이 생기면 넷 가운데 가장 가까운 곳에 넣고, 소절을 늘리지 않는다.

**조치 주체 칸을 비우지 않는다.** 정해지지 않았으면 `지정 필요` 로 적는다. 근거 칸에는 이 조치가 나온 곳(「설계 리포트 7.1절 No.2」, 「4.2절 No.3」)을 적는다.

## 검증에서 보이는 신호

검사하다 보면 설계가 빗나간 것이 드러나는 곳이 있다. **검증 리포트를 고치지 말고 설계를 고친다.**

| 신호 | 의미 |
|---|---|
| 1.3 의 판정값 정의나 절 첫머리 설명이 빠졌다 | 받는 사람은 「대체 매핑」·「정의 문서 검사」 가 무슨 뜻인지 모른다 |
| 칸에 「②의 값 표」·「⑦의 매핑」 처럼 스킬 단계 번호가 있다 | 받는 사람에게 뜻이 없는 번호다. 문서 이름과 절로 가리킨다 |
| 4.1절에 결과가 빈 줄이 있다 | 그 검사를 하지 않았다. 「미수행」 과 사유를 적는다 |
| 규격 검사에 보류가 있는데 7.1절에 없다 | 인수 측이 할 일을 놓친다. 반입이 왜 막히는지 모른다 |
| 4.1절 No.3 에 확인한 항목 수가 없다 | 가이드를 펴지 않고 통과로 적었다 |
| 5절에 `응답 불가` 인 필수 CQ가 있다 | 구조가 덜 만들어졌다 |
| 6절이 비어 있거나 「해당 없음」 이다 | 값과 컬럼을 맞대 보지 않았다. ⑦ 을 통째로 건너뛴 때만 비는 것이 맞다 |
| 6절에 `일치` 가 아닌 줄이 하나도 없다 | 정말 없는 것인지 짚지 않은 것인지 다시 본다 |
| 3절의 「대표 표시 속성이 1건이 아닌 개념」 이 0이 아니다 | 반입이 막힌다 |
| 3절의 「확인 필요 표기」 가 크다 | 참고 문서가 모자라거나, 알 수 없는 것을 억지로 만들었다. 고칠 것은 CQ가 요구하지 않는데 만든 것뿐이다. 그 밖의 항목은 7.4절로 옮긴다. 값을 채워 이 수를 줄이지 않는다 |
| 칸에 적은 낱말이 입력 문서에 없고, 산출물 어디에도 그 낱말이 무엇을 가리키는지 적은 곳이 없다 | 스킬 참고 문서나 가이드의 예시에서 온 말이다. 받는 사람은 그 문서를 볼 수 없다. 입력 문서의 말로 바꾸거나 지운다. 1.3 이나 절 첫머리 설명, 표의 정의 칸, 정의 문서의 설명 줄이 그 낱말을 풀어 두었으면 해당하지 않는다 |
| 6절에 `대체 매핑` 인 줄이 있다 | 뜻이 다른 컬럼이 그대로 이어져 있다. 구조 판정이 「확정 불가」 가 된다. 매핑을 비우고 설계 리포트 7.2절에 올려 `의미 불일치 미매핑` 으로 바꾸거나, 그대로 두기로 정했으면 판정 문서에 Error로 남는다 |
| 2절 「구조 판정」 칸이 비어 있다 | 판정 스크립트를 수행하지 않았다. 이 리포트만으로는 구조를 확정해도 되는지 알 수 없다 |
| 7절에 구조를 고치는 일이 있다 | 갈래를 잘못 잡았다. 답하지 못하는 CQ·규격 오류·대체 매핑은 구조 판정 문서 3.1절로 간다 |
| 6절 한 행에 글자가 다른 값 여럿을 합쳤다 | 대조 건수가 실행마다 달라진다. 띄어쓰기만 다른 값이 아니면 값마다 한 행으로 나눈다 |
| 6절에 응답 경로의 관계가 조인 쌍 행으로 다 나오지 않는다 | 관계가 엉뚱한 개체를 잇는지 맞대 보지 않았다 |
| 7절에 소절이 없고 줄만 늘어서 있다 | 갈래를 나누지 않았다. 받는 사람이 무엇부터 할지 정하지 못한다 |
| 인용 블록·줄표·조사 띄어쓰기가 보인다 | 옛 서식이다. [`리포트-작성-규칙.md`](리포트-작성-규칙.md) 6장으로 점검한다 |

설계안 확인에서 사용자가 그대로 두기로 한 항목은 신호로 보지 않는다. 설계 리포트 2절 「설계안 확인」 에 적힌 답을 따른다.
